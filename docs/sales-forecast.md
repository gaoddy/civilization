# 文明战旗 销量预测

> 日期：2026-11-25
> 性质：跨版本文档；商业预测
> 结论置信度：中低（±50%），随执行质量大幅波动
> 数据与获取方式：[销量预测外部数据](sales-forecast-sources.md)

---

## 0. 结论

**按当前产品路线（L2a + L2b 顺序做完）的中位预测：约 42 万份，首年净收入约 $2.5M–3.0M。**

| 方案 | 中位销量 | 主力区间（P25–P75） | 首年净收入 | 5 年累计倍数 |
| --- | --- | --- | --- | --- |
| 现状计划（L1：全平台 + 多语言 + 好美术 + 机器人补位） | 17.5 万 | 7–26 万 | $1.0M–1.5M | 1.5–2× |
| L2a（+ 难度分级、单人模式入口、局外解锁、难度递进） | 26 万 | 12–40 万 | $1.6M–2.2M | 2–3× |
| **L2a + L2b（+ 连续 run、继承、挑战目标）** | **42 万** | **22–70 万** | **$2.5M–3.0M** | **3–4×** |
| 上者 + 一次传播事件 | 60–120 万 | — | $4M–9M | 4–5× |

净收入口径：`$12.99 × 70%（Steam 分成）× 94%（退款）× 85%（区域定价加权）≈ $7.26/份`。

**本预测的核心判断**：

1. 决定销量的第一变量不是游戏质量，是**「一个人能不能玩」**。在这个品类里，单人可玩与纯联机的销量差 10 倍以上（见 §3.3）。
2. 第二变量是**曝光**，而曝光是纯日历时间——AI 无法压缩。
3. 开发速度（AI 辅助）已经把瓶颈完全转移到了验证与分发，不在写代码上。
4. 炉石传说（酒馆战棋）只证明品类需求，不提供销量基准：它免费、无 Steam 版、靠 IP 与平台分发（见 §3.4）。

## 1. 预测方法

采用四层模型，自外向内收窄。前三层是通用方法，第四层是本作独有。

```
第 1 层  可触达人群（TAM）        —— 平台与语言覆盖率
第 2 层  同品类基准率              —— 实际销量分布，而非直觉
第 3 层  转化漏斗                  —— 曝光 → 商店页 → 购买
第 4 层  联机临界质量 + 收入换算    —— 本作独有约束
```

每一层都给出**依据**，而不是给一个数字。任何一层被证伪，结论都会大幅变动（见 §8）。

所有引用的外部数据、原始值与复跑命令见 [销量预测外部数据](sales-forecast-sources.md)。

## 2. 第 1 层：可触达人群

### 2.1 平台与语言的实际覆盖

Steam 硬件与软件调查（2026-10）：

| 维度 | 占比 |
| --- | --- |
| Windows | 93.70% |
| macOS | 2.35% |
| Linux | 3.95% |
| 简体中文 | 21.98% |
| 英文 | 39.04% |

Steam 月活约 1.3 亿。

> 口径提醒：简体中文占比单月波动极大（本月较上月 -9.41 个百分点），且 macOS 与简体中文负相关——中文 Steam 用户绝大多数在 Windows，Mac 玩家以英文环境为主。因此不能用两个比例独立相乘估交集，那样会高估。

### 2.2 不同配置下的天花板

| 配置 | 有效人群（量级） | 相对基准 |
| --- | --- | --- |
| macOS 独占 + 纯中文 | 约 20–40 万 | 1× |
| + Windows | 约 1,200 万 | 约 30–60× |
| + 全语言 | 约 3,000 万–6,000 万（按品类兴趣 5–10% 折算） | 约 100–150× |

### 2.3 本层的用途与局限

这一层只说明"天花板在哪"，**不预测销量**。天花板一旦高于某个阈值（本作在 L2 方案下远高于），它就不再是约束——约束转移到下三层。

## 3. 第 2 层：同品类基准率

### 3.1 Steam 整体分布

- 中位游戏首年收入约 **$1,000–2,000**
- **58–70%** 的游戏首年不到 $1,000
- 分布极度头部化，少数作品占据大部分收入

> 来源为 Gamalytic / GameDiscoverCo / VG Insights 的公开统计，属**二级来源，未经原文逐项核对**，见[外部数据](sales-forecast-sources.md#5-二级来源未经原文核对)。趋势方向可信，精确数值需核对原文。

### 3.2 Auto Battler 标签的实际分布

按 SteamSpy 的 Auto Battler 标签抓取（2026-11-25，共 47 条）：

- 拥有量 ≥2 万的 **13 款（28%）**
- 其余 **34 款全在 0–2 万档**，且大量只有几百到几千

| 作品 | 拥有量 | 定价 | 好评率 | 备注 |
| --- | --- | --- | --- | --- |
| Dota Underlords | 1000–2000 万 | 免费 | 82% | Valve 出品，已停止更新 |
| Minion Masters | 500–1000 万 | 免费 | 89% | |
| **Backpack Battles** | **50–100 万** | $11.99 | 91% | **异步 PvP，单人可完成** |
| **弈仙牌 Yi Xian** | **50–100 万** | 免费 | 74% | **单机 roguelike 为主** |
| Legion TD 2 | 100–200 万 | $24.99 | 87% | 联机为主，积累 6 年以上 |
| 9 Kings | 100–200 万 | $9.99 | 92% | 单人 |
| Thronefall | 100–200 万 | $6.49 | 96% | 单人 |

> 口径提醒：SteamSpy 标签接口按拥有量排序返回，**底部被截断**，真实"2 万以下"的占比只会更高。标签本身也有噪声（Vampire Survivors、MS Flight Simulator、Bad North、Thronefall 并非严格意义的自走棋）。

### 3.3 从基准率读出的关键断层

**这个品类的销量分布，几乎完全被"单人能不能玩"切开：**

- 单人可玩 / 异步 / 免费：50 万–2000 万
- 纯联机付费：除 Legion TD 2（6 年积累）外，**几乎全在 2 万以下**

这条断层的解释力强于美术、语言、价格中的任何一个。

**但必须区分**：上述成功作品是**设计上就单人优先**，不是"8 人局加机器人"。本作拿到的是这个人群，不必然是那个天花板。

> 口径限定：炉石传说（酒馆战棋）不在同一比较池——它免费、无 Steam 版、靠 IP 与平台分发（见 §3.4），因此既不构成"纯联机付费全在 2 万以下"的反例，也不能反过来抬高本作的销量预期。

### 3.4 主要对标：炉石传说（酒馆战棋）

本作的 8 人酒馆战棋骨架来自炉石传说 2019-11 上线的《酒馆战棋》（Battlegrounds）：8 人、每回合招募、战斗自动结算、前四名算胜。它是这个品类的定义者，也是唯一长期运营的头部产品。

| 指标 | 数值 | 时间 | 来源与可信度 |
| --- | --- | --- | --- |
| 累计注册 | 1 亿 | 2018-11 | Blizzard 官方 |
| 活跃玩家 | 2,000 万+ | 2020 | Blizzard 年度回顾（经 Wikipedia 转述） |
| 月收入 | 约 $2,000 万 | 2015-06 | SuperData 估计（二手） |
| 年收入 | 约 $6 亿 | 2019 | KeyBanc 估计（二手） |
| 当前月活 | 约 340 万 | 2026-11 近 30 天 | ActivePlayer.io 第三方模型（低可信） |

> 口径提醒：酒馆战棋的独立玩家数 Blizzard 从未披露；2023-10 微软完成收购后，不再按 IP 披露用户与收入。第三方月活（340 万）与官方 2020 年口径（2,000 万+）差近一个数量级，只能取趋势方向，不能取绝对值。

**它证明什么**：8 人自走棋有千万级活跃用户的需求盘子，且能长期运营 7 年以上。玩法本身不是小众。

**它不证明什么**：

1. 它是**免费 + 内购**，不是 $12.99 买断，用户数不能换算成本作销量或收入。
2. 它**没有 Steam 版**（Steam 商店搜索 `Hearthstone` 返回 0 条），没有可比拥有量口径。
3. 它的分发依赖 Blizzard 账号体系、IP 粘性与手机端，本作都没有。
4. 因此 §3.2、§3.3 的 Steam 基准率才是本作的销量参照；炉石只用于判断**品类天花板**与**玩法已验证**，不进入销量基线。

**可借用的唯一推论**：如果本作把单人循环做成 L2b，它面对的需求盘子不是"2 万份"，而是千万级活跃；差距在获客与分发，不在需求是否存在。

## 4. 第 3 层：转化漏斗

### 4.1 无宣发新游的典型漏斗

| 环节 | 量级 |
| --- | --- |
| 首月商店页曝光 | 几千 – 几万 |
| 进店率 | 5–10% |
| 购买转化 | 10–15% |
| 首月销量 | 约 190 份（2 万曝光口径） |
| 首年系数 | 2–3× |

### 4.2 美术的作用位置

美术**不影响曝光**，只影响第二段（进店与购买）：

| 素材 | 影响 |
| --- | --- |
| 主胶囊图 | 决定点击率，权重最高 |
| 页头图 + 小胶囊 | 次之 |
| 前 4 张截图 | Steam 用户平均只看 2.6 张 |
| 预告片前 5 秒 | 决定是否继续看 |

综合量级：**×1.3–2**，且主要抬右尾（被主播/算法撞上的概率），不抬中位。

**本作已具备的条件**：`client/assets/cards/faces` 已有 432 张卡面，63 张英雄立绘、44 个头像；[卡片封面美术生成](current/technical/card-cover-art.md) 定义了统一风格（「深墨描金扁平插画 + 科学史纹样」）。**统一风格是最难的部分，已解决。**

**缺口**：未发现 Steam 胶囊四件套与预告片。

### 4.3 AI 生成宣发素材的边界

AI 把**素材生产**成本压到接近零，但宣发是分发问题：

| 环节 | AI 可覆盖 | 决定成败的因素 |
| --- | --- | --- |
| 视频 / 图 / 文案生产 | 是 | — |
| 多语言版本 | 是 | 母语审校 |
| 素材 A/B | 是 | 有流量才测得出来 |
| 把素材送出去 | 极少 | 账号权重、平台算法、人的转发 |
| 让人相信 | 不能 | 信任转移 |

素材供给趋近无限时，注意力成为唯一稀缺品；且新账号初始推荐权重接近零，冷启动仍以月计。

## 5. 第 4 层：联机临界质量（本作独有）

### 5.1 机制

- 单局约 25 分钟，8 座
- 公开匹配要让等待稳定在 5 分钟以内，经验上需要 **100–200 CCU**
- CCU ≈ DAU 的 2–5%；DAU ≈ 拥有量的 10–20%
- 反推：**100 CCU ≈ 1–5 万份拥有量**

### 5.2 后果

**1–5 万份是公开匹配能否转起来的分水岭。** 低于此：

```
排不到人 → 退款/差评 "dead game" → Steam 算法降权 → 销量进一步下跌
```

这是一个负反馈，不是线性下降。

### 5.3 本作的实际状态（仓库核对）

**已实现**：`botFill` 协议字段（"开始时空位是否用机器人补满"），`room.rs` 默认 `bot_fill: true`，`prepare_start` 在补位开启时允许真人不满 8 人开局，客户端有 `BotFillButton` 与对应 UI。

**含义**：一个玩家开房 + 7 个机器人即可开局。这**已拆除**"必须 8 个付费玩家"的获客闸门，但**尚未**把"单人"变成购买动机。

**差距**：
1. `server/crates/sim/src/bot/brain.rs` 只有一套启发式策略，**无难度分级**
2. 它是"空位补满"的开关，不是主菜单里的「单人模式」
3. 机器人局的成就/进度归属未定义

## 6. 产品档位定义

预测按档位给出，因为档位决定数量级。

| 档位 | 内容 | 本质 | 新规则面 |
| --- | --- | --- | --- |
| **L1** | 3 档难度 + 主菜单「单人模式」入口 + 成就规则 | 从"联机游戏的补位"变成"可以一个人买的游戏" | 无 |
| **L2a** | L1 + 局外解锁 + 难度递进（10 档）+ 每日种子局/排行榜 | 从"能打完一局"变成"想再来一局" | 无（复用现有 432 张卡） |
| **L2b** | L2a + 连续 run（多场 8 座对局串联 + 继承） | 从"单局"变成"一次 run" | **无**（若原子单位仍是 8 座对局） |
| **L2c**（不建议） | 独立 PvE 关卡/波次/首领 | 第二个游戏 | **有**，且与 PvP 不通用 |

### 6.1 为什么 L2b 不一定引入第二套规则面

取决于单机模式的**原子单位**：

| 形态 | 原子单位 | 新规则面 |
| --- | --- | --- |
| A. 单机 = 一局 8 座对局 | 一场对局 | 无 |
| B. 单机 run = 连续多场 8 座对局 | 多场对局的编排 | **无** |
| C. 单机 = PvE 关卡 | 一场 PvE 战斗 | 有 |

**推荐 B**：结算仍走 `rule-engine`，单机 run 只是外层编排（胜出 → 继承 → 机器人变强 → 终点）。与 L2a 方向一致，是延伸而非另起产品。

### 6.2 B 仍然带来的三个新面（非规则面）

1. **状态面**：run 存档、进度、解锁、继承值。现有重连一致性不变量只覆盖对局状态，跨会话的 run 状态是新的不变量面。
2. **配置面**：难度、回合上限、继承幅度。可用确定性模拟器机器验证，成本远低于 C。
3. **验证面**：测试矩阵多一个模式维度。

### 6.3 不建议 C 的理由

C 需要在 `rule-engine` 内引入 PvE 专属分支，会污染"纯库、确定性、所有结算只在这里"的架构；且带来独立平衡面、独立内容、独立验证基线，等于做两个游戏。

## 7. 要达到预测目标需要做什么

按"是否阻塞销售"排序，不按工作量排序。

### 7.1 P0 —— 不做就卖不了

| 项 | 现状 | 目标 |
| --- | --- | --- |
| Windows 构建 | `client/export_presets.cfg` 只有 macOS / iOS / Steam(macOS) / macOS Local Debug / Android / Android AAB，**无 Windows** | Windows 预设 + Steam depot + 成就/云存档路径 |
| 卡牌内容多语言 | UI 已 `tr()`（115 个 `.gd` 文件），但只有 `client/text/zh_CN.zh_CN.translation`；卡面文本全中文 | 432 卡 + 262 技能 + 32 英雄 + 全部 UI 字符串；内容 schema 先定，分批翻译 |
| Steam 商店页 | 未建（App ID、depot、成就 API 名均在 v0.2 待确认） | 主胶囊、页头、小胶囊、前 4 张截图、5 秒预告 |
| 账号跨端 | Steam 登录与手机号绑定契约已实现；短信通道未接 | 三端同账号；短信服务商选型与接入 |
| 服务器容量 | 单实例、房间制 | 多区部署、扩容方案、限流 |

### 7.2 P1 —— 决定曝光（纯日历时间）

| 项 | 目标 | 备注 |
| --- | --- | --- |
| Demo | 支持加入付费玩家房间，或开放 1–2 个完整时代 | 与新品节绑定 |
| Steam 新品节 | 至少两次（预热 + 首发前） | 需提前 3–4 个月报名 |
| 愿望单 | **上线前 ≥30,000** | 首周销量 ≈ 愿望单 × 10–20% |
| 宣发账号 | 立即启动，冷启动需 3–6 个月 | 新账号初始权重接近 0 |
| 叙事方向 | "一个人 + AI + 11 天 + 432 张卡的科学史自走棋" | 最可信、最独有、成本最低的素材 |
| 定价 | $12.99–$14.99 + 区域定价 | 不宜 $9.99 |

### 7.3 P2 —— 决定留存

| 顺序 | 项 | 说明 |
| --- | --- | --- |
| 1 | 难度递进（3→10 档） | 复用全部现有卡，零新内容，L2 中 ROI 最高 |
| 2 | 单人模式入口与命名 | 不改代码，只改入口与商店页文案 |
| 3 | 局外解锁 | 可复用已实现的成就系统骨架 |
| 4 | 每日种子局 + 排行榜 | 成本低，回访拉力强 |
| 5 | 新手引导 | 用简单难度机器人局承接，与单人模式合并做 |
| 6 | L2b 连续 run | **前置条件：L2a 的 D7 回访达标**（见 §8） |

**L2 阶段不新增卡牌或新模式。** 432 张卡是资产，用难度与解锁重新组织，比再造 100 张新卡值钱。

### 7.4 关键路径（AI 无法压缩）

| 事项 | 所需日历时间 |
| --- | --- |
| 宣发账号冷启动 | 3–6 个月 |
| 愿望单积累至 3 万 | 6–12 个月 |
| Steamworks / Apple / Google 审核 | 4–8 周 |
| 新品节报名与档期 | 提前 3–4 个月 |
| 多语言母语审校 | 2–4 周排期 |
| 家长/教育渠道关系 | 6–12 个月（最慢） |

**这些加起来长于 L2a + L2b 的开发时间。** 开发速度越快，越应尽早启动这些排队项。

## 8. 验证指标与证伪条件

### 8.1 上线前后可验证的中间指标

| 指标 | 时间点 | 达标线 | 未达标的含义 |
| --- | --- | --- | --- |
| 愿望单 | 上线前 1 个月 | ≥30,000 | <1 万不建议发布 |
| Demo 试玩转化 | 新品节期间 | ≥8% | 商店页或首小时体验有问题 |
| 首周销量 | 上线 7 天 | 3,000–6,000 | 对应愿望单 10–20% |
| 首月 CCU 峰值 | 上线 30 天 | 800–1,500 | 低于 300 说明联机体验未成立 |
| 好评率 | 上线 30 天 | ≥85% | <80% 说明留存或联机有硬伤 |
| **单人模式 D7 回访** | 上线 30 天 | **≥30% 可做 L2b；<15% 不做** | 决定 L2b 是否值得投入 |

### 8.2 证伪条件

- **"单人模式很无聊"** 成为评价高频词 → 预测直接掉回 5 万以下。吸引来的是单机玩家，他们会用单机游戏的标准评价。
- **L2a 的 D7 回访 < 15%** → L2a 未成立，L2b 会白费（L2b 只是把同样的循环做长）。
- **愿望单 < 1 万仍强行发布** → 落入 P10 区间，且损失 Steam 算法唯一一次新游曝光机会。

## 9. 不确定项

### 9.1 关于"家长会买"的判断

该假设在本作现有形态下不成立，原因：

1. **买家 ≠ 玩家**，需要家长渠道（教育公众号、学习机预装、老师推荐），本作无此渠道。
2. **机制与家长诉求相反**：家长要的是单人、无陌生人、可离线、短局；本作是 8 人在线、25 分钟、有淘汰。
3. **监管三重**：版号、未成年人防沉迷实名与时段限制、教育类应用备案。
4. **人群在中国**，而中国区短期不发行。

**L1 的单人模式拆掉了第 2 条中的"陌生人"堵点**，但单局 25 分钟、无教学目标、无渠道三项仍在。结论：从"不可行"变为"可行但需单独设计"，未计入主预测。

### 9.2 关于手机端

- iOS 与 Android 已在导出预设中；Android 属 v0.2 范围。
- 自走棋的节奏（每回合 60–120 秒决策、战斗自动播放）**适合手机**，形态上成立。
- 真正的限制不是形态，是**发现与付费**：付费 PvP 手游依赖商店推荐位。
- 跨端同池对填充率有实质帮助（移动端玩家填补 PC 端错峰）。
- 贡献估计：主预测基础上 **+25–40%**（在单人模式成立的前提下）。

### 9.3 值得单独评估的移动端渠道：Apple Arcade

一次性解决发现、付费、家庭共享三个问题，且契合"无内购、不做付费变强"的设计原则。代价通常是排他性。概率估计 10–20%，一旦达成是 upfront 付款。**未计入主预测。**

## 10. 一页摘要

1. **中位预测 42 万份，区间 22–70 万，首年净收入 $2.5M–3.0M。**
2. 决定量级的是"单人能不能玩"——这个品类里单人可玩与纯联机差 10 倍以上。
3. 本作已经具备两个关键资产：统一的 432 张卡面风格、默认开启的机器人补位。
4. 缺口不在开发，在**验证和分发**：难度分级、模式入口、局外解锁、商店页、愿望单、宣发账号。
5. AI 压缩了写代码的时间，没压缩试玩、审核、账号冷启动、愿望单积累的时间——这些才是真正的关键路径。
6. 唯一需要立刻动手且不可等待的事：**建 Steam 商店页 + 建宣发账号**。
