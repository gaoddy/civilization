# v0.1 M1a（协议 + 房间服务）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 8 个开发机器人通过真实 WebSocket 按协议打完一整局，服务端权威结算，逐座位过滤视图，支持去重与重连。

**Architecture:** 先在 `rule-engine` 补三处纯函数能力（重复英雄放开、意图预检 `check_*`、逐座位视图与战斗报告），再把协议 schema 的四处缺口补齐并用 `typify` 生成 `crates/protocol`，最后建 `crates/room-service`（axum + 每房间单 task 串行）与 `sim bot --connect`。引擎不新增状态字段，排行榜/哈希口径不变，M0 基线不受影响。

**Tech Stack:** Rust 1.94 edition 2024；rule-engine（纯库）、sim（CLI）、protocol（typify 生成）、room-service（axum 0.8、tokio 1、tokio-tungstenite 0.28）；Python 3 生成/校验脚本；`make` 统一入口。

**Spec:** [v0.1 M1 单房间联调实现设计](../specs/2026-11-15-v0.1-m1-room-service-design.md)

## Global Constraints

- 全部回复与文档使用简体中文；代码、路径、标识符、日志原文不翻译。
- 规则结算只在 `rule-engine`；`room-service` 不复制规则，只做会话、时序与视图映射。
- 依赖方向固定：`room-service → protocol`、`room-service → rule-engine`；`rule-engine` 不依赖 `protocol`、tokio、sqlx 或任何 I/O 库。
- 协议契约唯一来源 `protocol/schema/v1/`；不手写与 schema 不一致的 Rust 类型；生成物随源提交。
- `rule-engine` 保持 `#![forbid(unsafe_code)]`，纯库：不读时钟、环境变量、文件、网络。
- 确定性：只用整数与 `BTreeMap`/有序 `Vec`；不得引入浮点参与判定；不得新增 `GameState` 字段（否则 M0 哈希与基线漂移）。
- 引擎内每个意图先校验后修改，拒绝时 `GameState` 逐字节不变。
- 构建、测试、生成统一走 `make`；新增 `protocol-rs`、`protocol-rs-check`、`m1-check`。
- 错误码只增不改，取值与 `protocol/schema/v1/errors.schema.json` 一致。

## Review Focus

1. 8 个座位选到同一张英雄卡 → 必须能正常开局（当前引擎会拒绝，与卡牌规范 §2.1 冲突）。
2. 玩家有待选未消费时提交 `EndRecruit` → 服务端不得卡死，超时仍能推进到 `Combat`。
3. 重连时 `lastSeq` 落后于服务端 → 必须收到完整 `Snapshot`，不得只补增量。
4. 同一个 `clientIntentId` 重复提交 → 只执行一次，不重复扣金币、不重复产生事件。
5. 对手手牌、金币、商店、刷新次数、种子 → 视图里一律不出现。
