# v0.1 M1b（Godot 五场景客户端）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 Godot 4 最小可读客户端，用 1 个客户端 + 7 个机器人经真实 WebSocket 打完一局，五场景可读，客户端不做任何本地规则结算。

**Architecture:** 客户端是一个独立 Godot 工程 `client/`：`GameStore` 保存服务端最新 `PlayerView`，`Net` 持有 `WebSocketPeer` 并负责认证、重连与消息分发，`CardDB` 只加载产品文档生成的展示表；五个场景（登录/大厅/房间/对局/结算）只读 store 与 `affordances`，状态变化整包替换，操作只发协议意图。协议常量与卡牌展示表由现有 Python 生成器输出到 `client/generated/`，漂移检测进 `make`。

**Tech Stack:** Godot 4.7 GDScript、WebSocketPeer、JSON；Python 3 生成器与 unittest；Rust `room-service` / `sim bot` 作为真实服务端与机器人。

**Spec:** [v0.1 M1 单房间联调实现设计](../specs/2026-11-15-v0.1-m1-room-service-design.md) §5.6、§5.7

## Global Constraints

- 全部回复与文档使用简体中文；代码、路径、标识符、日志原文不翻译。
- 客户端不加载、不执行规则引擎，不做本地结算；状态只来自服务端 `PlayerView`，可操作提示只读 `affordances`、待选只读 `pendingChoices`。
- 客户端不得出现 `rule-engine`、`rule_engine`、`resolve_combat`、`start_game`、`server/data` 等对规则实现的引用（由 `tests/test_client_boundary.py` 断言）。
- 协议唯一来源是 `protocol/schema/v1/`；`client/generated/protocol.gd` 与卡牌表由脚本生成，随源提交，不手改。
- 对局界面只提供协议十种意图对应的操作；不展示对手手牌、金币、商店、刷新次数或种子。
- 构建、生成、校验统一走 `make`；Godot 可执行文件通过 `GODOT` 变量覆盖，默认自动探测 `godot` 或 `/Applications/Godot.app/Contents/MacOS/Godot`。
- 机器人使用开发验证码 `123456`；服务端默认监听 `127.0.0.1:8080`，客户端默认 `ws://127.0.0.1:8080/ws`。
- 代码风格：GDScript 用 4 空格缩进、`snake_case` 函数/变量、`PascalCase` 节点名；Python 沿用现有脚本风格。

## Review Focus

1. 服务端拒绝意图（如金币不足、目标缺失）→ 客户端只展示 `Error` 的 code/message，不改本地视图、不自行扣金币。
2. 对局中断线 → `Net` 自动重连，先 `AuthRequest(token)` 再 `Reconnect{roomId,lastSeq}`，重连后整包 `Snapshot` 覆盖视图。
3. 招募倒计时到 0 → 客户端显示 0 且不再允许操作，阶段推进完全由服务端 `StateUpdate` 驱动。
4. 发现/进化待选未消费 → 弹层按 `pendingChoices` 顺序渲染，选择只发 `ChooseDiscover`。
5. 房间未满 8 人或有人未准备 → 房主界面提示等待，不出现本地“开始游戏”按钮。
