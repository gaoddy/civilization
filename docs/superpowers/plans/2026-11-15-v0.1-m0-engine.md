# v0.1 M0 规则引擎 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可运行的 v0.1 规则引擎与 CLI 模拟器，通过路线图 M0 的全部退出标准。

**Architecture:** `server/` Cargo workspace，`rule-engine` 是纯库（无 I/O、无时钟、无全局随机），`sim` 是确定性 AI 与批量模拟器。卡牌数据由 Python 从实体文档生成 JSON 并提交，引擎通过 `Catalog::from_json` 加载。效果用 `effects` DSL 的类型化 AST 解释，单卡不写特判。

**Tech Stack:** Rust 1.94.1 / edition 2024、serde + serde_json、proptest、Python 3 标准库、GNU Make。

**Spec:** `docs/superpowers/specs/2026-11-15-v0.1-implementation-design.md`

## Global Constraints

- `rule-engine` 顶部 `#![forbid(unsafe_code)]`；不依赖 tokio、sqlx、协议 crate，不做文件 I/O、不读时钟、不读环境变量。
- 结算路径只用整数；禁止浮点参与判定与比较；概率用整数权重。
- 禁止使用 `HashMap` / `HashSet` 的迭代结果；映射用 `BTreeMap`，集合用有序 `Vec`。
- 随机数只用自实现 xoshiro256++；五个标签流 `shop` / `combat` / `discover` / `matchmaking` / `effects`；引擎只接受注入的种子。
- 卡牌数据唯一来源是 `docs/versions/v0.1/product/content/`；生成物提交，`make data-check` 必须零差异。
- 不新增产品规则；文档未定义处按 Spec §11 裁决，影响核规则的歧义先登记 `docs/versions/v0.1/open-questions.md`。
- Python 脚本与测试只用标准库；现有测试命令保持 `python3 -m unittest discover -s tests -v` 可用。
- 构建、测试、静态检查、生成统一走 `make`；每个任务结束时工作区只含本任务改动。
- 提交按任务拆分，消息写明范围与目的。

## Review Focus

- **确定性**：同种子 + 同意图序列重放 100 次，状态哈希必须全同；随机调用点必须带标签，战斗随机不得消耗商店流。Task 5、15 的测试固定这一点。
- **牌池耗尽**：7 星池每张 5 份，抽空后商店必须重抽星级而不是死槽或 panic；三连、召唤、复制各有不同的扣池规则。Task 6、7、13 覆盖。
- **战斗终止**：双方都有复生/亡语/召唤时可能不收敛；200 次行动必须强制结束并按 §5.3 判定。Task 8 覆盖。
- **结算顺序**：同一时点死亡、同时清场、第 20 回合强制结束、镜像幽灵，顺序错一次就会得到不同名次。Task 9、13 覆盖。
- **DSL 未知语义**：任何未知触发、动作、选择器、参数必须在加载期失败，不能运行到才失败；无卡牌使用的组合只进覆盖报告。Task 1、4 覆盖。

```python
# tests/test_audit_effects.py
import pathlib, sys, tempfile, unittest
ROOT = pathlib.Path(__file__).resolve().parents[1]
sys.path.insert(0, str(ROOT / "scripts"))
import audit_effects
SKILLS = ROOT / "docs/versions/v0.1/product/content/skills"

class AuditEffectsTest(unittest.TestCase):
    def test_all_committed_skills_are_clean(self):
        report = audit_effects.audit(SKILLS)
        self.assertEqual(report.violations, [])
        self.assertEqual(report.skill_count, 118)
        self.assertEqual(sum(report.matrix.values()), 109)  # 108 个技能的 109 段效果
    def test_times_if_without_times_is_reported(self):
        with tempfile.TemporaryDirectory() as tmp:
            p = pathlib.Path(tmp) / "bad.md"
            p.write_text("---\nid: bad\ntext: 战吼：成长\neffects: OnPlay|Growth|friendly:single|timesIf=人类:2\n---\n")
            self.assertTrue(any("timesIf" in v for v in audit_effects.audit(pathlib.Path(tmp)).violations))
    def test_when_on_play_is_reported(self):
        with tempfile.TemporaryDirectory() as tmp:
            p = pathlib.Path(tmp) / "bad.md"
            p.write_text("---\nid: bad\ntext: 战吼：成长\neffects: OnPlay|Growth|self|times=1,when=tribe=人类\n---\n")
            self.assertTrue(any("when" in v for v in audit_effects.audit(pathlib.Path(tmp)).violations))
```

审计规则固定为：`timesIf` 只能与 `Growth` 的 `times` 同时出现；`when` 只能用于事件类触发（`OnDeath`、`OnFriendlyDeath`、`OnEnemyDeath`、`OnAllySummon`、`OnAllyGrowth`、`OnAllyEvolve`、`OnDealDamage`、`OnCombatEnd`、`OnUse`），不能用于 `OnPlay`、`OnActivate`、`Aura`、`ConditionalAura`；`GrantKeyword` 的 `keyword` 基名为 `繁衍` / `装配` / `传染` 时必须带 `value`，其余关键词禁止 `value`；`Summon` 必须且只能有 `token` 或 `card` 之一；`Discover` 必须同时有 `pool` 与 `choose`，且 `choose` 为 1；`GainMinion` 必须同时有 `level` 与 `to`。

## 已知规格缺口

以下问题不影响 M0 开工，但 M1 前必须处理；实现时先按默认值继续，并在 `docs/versions/v0.1/open-questions.md` 登记：

1. **单目标选择缺少意图参数**：`BuyMinion`、`PlayCard` 的战吼/效果可能要求 `friendly:single` 由玩家指定目标，但核心规则 §3 与 schema 都没有目标字段。M0 的引擎意图带 `target: Option<InstanceId>`，AI 自动选择；M1 在协议里给这两种意图加可选 `targetMinionId`，并同步 schema、样例、生成物与 `core-rules.md`。
2. **发现的选择消息缺失**：核心规则 §3 的九种意图没有"选择发现结果"，但 §6.4 要求玩家三选一。M0 用引擎内部 `Intent::ChooseDiscover`，M1 在协议中新增同义意图/消息并同步 schema、样例、生成物与 `core-rules.md`。
3. **`PlayerView` 字段不足**：当前 schema 不能表达对手阵容、淘汰名次、当前对手与托管状态。M1 按"先改 schema + 样例，再改两端"补齐。
4. **协议 `protocol` crate 生成物位置**：设计写 `protocol` crate 用 `typify` 生成，`server-stack.md` 写仓库根 `protocol/generated/protocol.rs`。M1 统一为仓库根生成、crate 依赖生成文件，并回写 `server-stack.md`。
5. **数值基线**：M0 报告只产出数据，不自动调数值；越界项登记 `open-questions.md`，调整属于后续任务。
