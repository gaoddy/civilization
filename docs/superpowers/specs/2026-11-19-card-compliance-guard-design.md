# 卡牌合规护栏与说明回写 · 设计

> 状态：待确认
> 关联需求：[卡牌规范与数据](../../current/product/content/card-system.md)

## 1. 背景与目标

卡牌参数重排完成后，评审留下三项缺口：

1. `## 设计说明` 的平衡边界仍写着重排前的身材数字；另有 14 张用裸数字写身材，合计 57 张需要回写。
2. 缺少从商店 / 招募入口出发的 `card_in_pool` 集成测试，现有测试只覆盖随从或直接调用 `card_in_pool`。
3. `balance_report.py` 没有自动校验「4 费效果牌只能 6–7 星」与「多技能机制词汇归属」。

目标：补齐上述三项，让 `make balance-check` 覆盖产品 §5.1 / §5.2 与 [数值与经济 §6](../../current/product/systems/economy-and-numbers.md) 的护栏；当前数据违规的卡在同一任务内修正。

非目标：不改玩法数量、卡牌 id / 卡名 / 时代 / 星级 / 科学分类、牌池份数、金币曲线、效果原语、引擎规则与客户端协议；不追求把 1000 局夺冠率收敛进 4%–12%（该问题已记录在 [open-questions](../../versions/v0.1/open-questions.md)）。

## 2. 设计说明回写

### 2.1 范围

- 57 张卡的 `## 设计说明`，包含 43 张显式「N 星 X/Y」与 14 张裸数字（如「2/4 处于 2 星中位」）。
- 只改 `## 设计说明`，不改 `## 出处`、卡牌字段、技能文本。

### 2.2 改写方式（方案 A，已选定）

保留「定位」「使用建议」两句，重写「平衡边界」为按当前数据计算的统一句式：

```
平衡边界：<星级> 星 <攻击>/<生命>；攻击力取该星级<位置>，生命值取该星级<位置>；关键词折算 <N> 点，合计 <总强度>，<等于|低于> <上限> 上限<差额>。
```

- 位置按 [数值与经济 §5](../../current/product/systems/economy-and-numbers.md) 的星级区间分档：下限 / 偏下 / 中位 / 偏上 / 上限。
- 关键词折算复用 `scripts/validate_docs.py::keyword_cost`，上限复用 `CAP`，避免另立口径。
- 无关键词折算时句子改为「无关键词折算，合计 …」。
- 原句包含「最小星级」「时代」等关键词解锁说明时，保留该说明附在原句之后。

另外修正 4 张「定位」与现值矛盾的卡（argonaut、blue-ringed-octopus、coelacanth、komodo-dragon），以及本任务改技能后定位失效的 5 张（beetle、butterfly、pufferfish、orchid、termite-king）。

被否方案：B 只替换数字，保留「中位/偏上」等旧判断（会留下自相矛盾）；C 重写整个设计说明（超出本轮范围，定位/使用建议大多仍成立）。

## 3. 多技能机制词汇归属校验

按产品 §5.1 / §5.2 实现，规则分星级：

| 星级 | 规则 |
| --- | --- |
| 1–2 | 技能数量由 `validate_docs.py` 限制为 1；本校验不重复 |
| 3–4 | 第二个技能必须命中本玩法机制词汇 |
| 5–7 | 至少 1 个技能命中本玩法词汇（签名机制），且最多 1 个技能不命中（通用工具） |

- 只校验 `card_type=minion`、非学者、非英雄、玩法非 `neutral` 的卡；中立工具卡没有词汇表，学者与英雄技能不走 §5.2。
- 词汇识别基于 `skills.json` 的结构化字段（`keyword`、`effects[].trigger/op/selector/params`），不按技能 id 或英文关键词名硬匹配；技能文本只用于人工复核。
- 机制词汇表直接取产品 §5.2 的 13 个玩法。

## 4. 商店入口集成测试

在 `server/crates/rule-engine/tests/pool.rs` 增加一条使用真实卡表的测试：

- 卡表用 `common::test_catalog()`；定向牌用真实鱼纲效果牌 `yangliu`（1 星、1 费、`play:fish`），通用牌用一张真实 1 星通用效果牌。
- 商店权重临时改为只出 1 星；清空共享池（效果牌不占池，随从因此被排除），使候选只剩 1 星效果牌。
- 未启用鱼纲：多次 `Engine::roll_shop` 后 `yangliu` 永不出现，通用牌可出现。
- 启用鱼纲：多次刷新后 `yangliu` 出现，通用牌仍出现。

覆盖点：`roll_shop → draw_shop_card → is_eligible → card_in_pool` 的完整链路，而不是只测数据层函数。

## 5. balance_report.py 改动

- 新增 `--skills` 参数，默认 `server/data/v0.1/skills.json`。
- 新增两项 `violations`：
  - 效果牌 `cost == 4` 时 `level` 必须为 6 或 7。
  - 上文 §3 的多技能词汇归属。
- `--playstyle` 模式仍只检查指定玩法的攻血比，跳过全局检查。
- `tests/test_balance_report.py` 增加对应用例：4 费星级边界；3–4 星第二技能；5–7 星签名与通用数量；中立 / 学者 / 英雄跳过；词汇识别覆盖关键词与触发式技能。

## 8. 风险

- **12 张卡改技能影响模拟胜率**：夺冠率验收本就未达成，本轮以「不新增超模、不破坏关键词解锁」为护栏，记录新结果而非强行收敛。
- **设计说明模板化**：统一句式会弱化单卡机制说明；定位与使用建议保留，必要时人工补一句。
- **词汇识别误判**：以结构化字段为准，落地后在 `make balance-check` 全表跑一遍并人工抽查边界技能。

## 9. 后续调整（2026-11-19）

§3.1 表把三张卡的「进化」换成本玩法词汇后，`keyword-evolve` 从 6 张降到 3 张，低于 `card-system.md` §3.1 的「进化 ≥6」。经确认改为补回进化密度：`revived-mammoth`、`synthetic-cell`、`jiyin-gaizaoren` 把第一个技能「复生」换回「进化」（第二个技能仍是本玩法签名机制，5–7 星规则允许 1 个表外技能）；关键词折算同为 3 点，身材与模拟结果不变。`dolly` 4 星保持不变——它是唯一 4 星复生卡，`validate_docs` 要求复生的最小星级为 4。调整后 `keyword-evolve` 6 张、`keyword-reborn` 4 张。
