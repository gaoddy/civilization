# 卡牌与英雄改为单实体文档 — 短设计

日期：2026-11-14
范围：`docs/`（文档结构重构，不涉及代码）

## 意图

CSV 里 120 张卡、10 位英雄挤在两张宽表里，单张卡的说明无处安放，评审时只能数行。拆成一人一文档后，每张卡有自己的链接、历史和扩展空间，同时保留机器可校验的数据。

## 目标 / 非目标

- 目标：120 张卡、10 位英雄各一个 Markdown 文档；字段放进 YAML front matter，正文写效果与设计说明；校验改为扫描实体文档；删除两个 CSV。
- 非目标：不改任何数值、关键词、技能效果与 id；不改写 30 张战术牌（它们不在 CSV 中，继续留在 06）；不改写 `docs/superpowers/plans/` 历史记录。

## 目录结构

```
docs/data/
├── cards/
│   ├── baiyi.md
│   ├── qishi.md
│   └── …（120 份，文件名 = id）
├── heroes/
│   ├── luxun.md
│   └── …（10 份）
└── validate.py          # 唯一校验入口，仅用标准库
```

## 单文档格式

卡牌（`docs/data/cards/baiyi.md`）：

```markdown
---
id: baiyi
name: 白蚁
tribe: 生物
subtype: 昆虫
level: 1
era: 史前
attack: 1
health: 2
keywords: [繁衍 1]
is_scholar: false
source: 素材
---

# 白蚁

## 效果

繁衍 1：回合开始时获得 +1 生命
```

英雄（`docs/data/heroes/luxun.md`）：front matter 承载 `id`、`name`、`discipline`、`skill_name`、`skill_cost`、`skill_type`、`skill_text`、`series`；正文承载从 06 §3 迁出的设计说明（定位、平衡边界、使用建议等）。

**解析约定**：front matter 只使用本项目生成器产出的子集——`key: scalar` 与 `keywords: [a, b]` 两种形式；`validate.py` 用标准库按行解析，不引入 PyYAML。

## 校验

- 卡牌：120 份；id/名称唯一；`^[a-z][a-z0-9_]*$`；文件名 = id；学者攻击 0；流派与 `is_scholar` 一致；时代 24/24/24/30/18；流派 24/22/24/12/10/28；星级 18/24/26/22/18/12；关键词白名单、流派专属词越界、星级数值区间与超模上限。

- 文档内所有卡牌/英雄链接可解析到实际文件。
