# 对局页酒馆战棋结构改版 设计

> 状态：已确认
> 需求归属：v0.1
> 产品规则：[对局页](../../current/product/ui/pages/game.md)
> 参考：炉石传说酒馆战棋官方对局界面（招募阶段与战斗阶段截图）

## 1. 意图与原因

对局页当前是「左排名栏 + 中区 + 右操作栏」的三栏结构：商店与棋盘在中区上下排列，售货员、商店操作、回合、倒计时、英雄与工具入口集中在右栏。它承载了全部功能，但视觉重心被右栏分走，棋盘与手牌不是页面的主体。

本次按用户选定的酒馆战棋方向重排：**商店与售货员回到顶部中央，商店操作改为售货员两侧的图标；棋盘居中，商店或对手棋盘与我方棋盘之间加入一条河道行；自己英雄改为 64×84 英雄卡，放在我方棋盘下方、手牌上方；手牌贴到页面最底；回合数在河道中央、倒计时在右端；左栏保留排行榜**。右栏整体移除。

## 2. 目标

- 页面结构对齐酒馆战棋：顶部中央商店与图标操作、中央棋盘、底部 64×84 英雄卡与贴底手牌、左缘排行榜。
- 在商店或对手棋盘与我方棋盘之间加入河道行，回合数在中央、倒计时在右端，战斗结果横幅与回合数共用中央位置。
- 移除右侧操作栏，棋盘成为页面主体。
- 战斗阶段顶部中央恢复对手英雄，让「对手」与「我」在同一视线轴上。
- 去掉手牌、棋盘、商店的外框与标题，减少面板层级。
- 为后续美术版本固定槽位与尺寸，本轮不引入图片资源；操作图标用矢量绘制。

## 3. 非目标

- 不改服务端、协议、规则、伤害公式、配对与卡牌数据。
- 不做招募阶段的下一位对手预告：配对在 `finish_recruit` 才生成，战斗结算后清空，招募阶段 `opponentPlayerId` 为 `null`。
- 不做移动端、浅色主题、图片与字体资源。
- 不改图鉴、首局引导、选择浮层、详情层、战报的内容与规则。
- 不调整左排名栏的宽度与信息密度。

## 4. 反目标

- 把商店搬到右栏、把右栏改窄后继续保留三栏，却称其为酒馆战棋结构。
- 为了塞下结构而缩小卡面到文字不可读。
- 手牌或英雄被裁切、被压在其他区块下面而无法完整查看。
- 用背景图撑出层次，而结构本身没有分区。

## 6. 方向比较

| 方向 | 做法 | 代价 | 结论 |
| --- | --- | --- | --- |
| A 商店进右栏 | 保留三栏，右栏改为商店 + 英雄 + 回合控制 | 右栏高度放不下商店 3 行 + 英雄块；加宽右栏会挤压 7 张棋盘卡与 10 张手牌；与酒馆战棋真实结构不符 | 否 |
| B 经典对局骨架 | 取消左排名栏，8 人改顶部横排，对手英雄置顶、自己英雄置底 | 名次与战报是本作核心信息，横排后战报浮层、名次重排、座位详情都要重做 | 否 |
| **C 酒馆战棋官方结构** | 保留左排名栏，移除右栏；商店与售货员在顶部中央，棋盘居中，中间加河道行，自己英雄在手牌上方、手牌贴底 | 需要重排右栏全部内容；战斗阶段要恢复顶部对手英雄；手牌与英雄的垂直空间需要压缩 | **选定** |

方向 A 在上一轮口头方案中出现过，核对官方截图后确认商店实际位于顶部中央，右栏不存在，因此改为方向 C。

## 7. 结构决定

### 7.1 三个区域

```text
┌──────────────────────────────────────────────────────────────┐
│ 状态文本                                    图鉴 提示 退出     │
├──────┬───────────────────────────────────────────────────────┤
│ 排名 │  [升时代] [售货员] [刷新] [冻结]                      │
│ 栏   │        商店 6 槽（单行）                               │
│ 8 行 │  ────────── 第 N 回合 ─────────── [倒计时/结束招募]   │
│      │        我方棋盘（7 槽）                                │
│      │        [英雄卡 64×84] [金币] [技能]                   │
│      │        手牌（贴底居中，无面板）                         │
└──────┴───────────────────────────────────────────────────────┘
```

战斗阶段把顶部商店区替换为对手英雄 + 对手随从行，结果横幅占用河道中部，其余区域不变：

```text
┌──────┬───────────────────────────────────────────────────────┐
│ 排名 │        对手英雄（头像 + 名字 + 生命 + 名次）            │
│ 栏   │        对手随从行                                     │
│ 8 行 │  ────────── 第 N 回合 · 结果横幅 ────── [战斗中]      │
│      │        我方随从行                                     │
│      │        [英雄卡 64×84] [金币]                           │
│      │        手牌（只读，贴底）                              │
└──────┴───────────────────────────────────────────────────────┘
```

### 7.2 几何预算

- 页面 1280×720；左右外边距 16，上下 12；顶部工具区 28，工具区与舞台间距 8。
- 左排名栏 88，栏与舞台间距 12，舞台宽 1148。
- 河道行高 32，宽度与舞台一致；中央回合数、右端倒计时、战斗时中部的回合数与结果横幅都在这条行内，不新增行。
- 卡面保持 112×146：商店 6 槽单行 712、棋盘 7 槽单行 832、手牌 10 张按 80 步进 832，均小于舞台宽。
- 招募阶段纵向：商店操作行 64 + 间距 6 + 商店 146 + 间距 18 + 河道 32 + 间距 6 + 棋盘 146 = 418；再接间距 8 + 英雄行 84 + 间距 8 + 手牌 146，合计 664。
- 战斗阶段纵向：对手英雄 64 + 间距 6 + 对手行 146 + 间距 18 + 河道 32 + 间距 6 + 我方行 146 = 418；再接间距 8 + 英雄行 84 + 间距 8 + 手牌 146，合计 664。
- 18 间距位于商店/对手行与河道之间；河道下方另留 6 与棋盘/我方行相接。两种组合的河道都在组合顶部下方 234–266，下方行从 272 开始。
- 结论：保持 112×146 卡面，不缩小卡牌；英雄卡 64×84（112×146 的等比缩小），英雄行 84，手牌贴页面最底，卡底边 712。

### 7.3 手牌

- 手牌行位于页面最底部、英雄行下方，居中，无面板与标题。
- 保留 80 步进重叠与悬停 1.12；不改成扇形（Godot 内实现成本高，且 10 张在 1148 宽内可完整单行）。
- 悬停放大以底边中点为轴，向上增长；底部留出约 8 的边距，避免缩放后被窗口裁切。
- 战斗阶段只读；空手牌显示一行「手牌为空」。

### 7.4 英雄

- 自己英雄位于我方棋盘下方、手牌上方：英雄卡 64×84，与普通卡 112×146 同比例缩小；卡内自上而下为封面、名字行、底部数值行。
- 名字单独一行；底部左侧攻击、右侧生命、时代在两者中间；攻击取英雄卡攻击，生命显示「当前/上限」。
- 英雄卡右侧为金币与英雄技能图标；技能图标 40×40，费用角标右上、剩余次数角标左上；默认 1 次不显示数字，0 次整枚置灰并禁用，2 次及以上显示数字；战斗阶段技能图标隐藏，英雄卡保留。
- 对手英雄：战斗阶段顶部居中，头像 64×64 + 名字 + 生命 + 名次；幽灵战加「幽灵」角标且不显示血量条。
- 自己已淘汰时，英雄行显示「已淘汰 · 观战中」。

### 7.5 河道行

- 河道行位于商店或对手随从行与我方棋盘之间，高 32，宽与舞台一致。
- 中央显示「第 N 回合」；右端显示倒计时胶囊。
- 招募阶段：中央只显示回合数；倒计时胶囊悬停翻成「结束招募」，点击发出 `EndRecruit`；移出恢复剩余秒数，沿用现有交互。
- 战斗阶段：中央始终显示回合数，播完后在同一位置追加结果（胜负与伤害）；右端显示「战斗中」并禁用。
- 倒计时归零：右端显示「等待结算」并禁用招募操作。
- 河道不接收拖拽落点，指针经过时不改变拖拽状态。

### 7.6 工具与状态

- 图鉴、提示、退出对局移到顶部工具区右侧。
- 连接、错误与等待视图文本移到顶部工具区左侧；页面底部状态行删除。

## 10. 风险

- 垂直空间紧：招募/战斗组合固定 418，英雄行 84，手牌底边 712；没有弹性留白，任何新增行高或间距都会挤压手牌。实现前需在 Godot 内量一次实际文本高度。
- 图标替代文字：图标按钮失去可见文本，必须保留中文 tooltip 与禁用原因；测试改按节点名与 tooltip 断言，不能按按钮文本查找。
- 英雄卡比例：64×84 是 112×146 的等比缩小，卡内名字与数值只有 7–8px；Godot 内需确认最小字号可读，必要时把名字行与数值行各加 1px，但不改变 64×84 槽位。
- 手牌在英雄行下方：悬停放大 1.12 会向上覆盖英雄行，属于临时悬浮；需要关闭手牌行裁剪并让手牌位于英雄行之上，移出后立即恢复。
- 对手英雄恢复：与 2026-11-17 HUD 改版「删除战斗英雄条」的结论相反，需要在产品文档中明确为本次增量，不能当作缺陷。
- 战报浮层：左栏点击展开的浮层覆盖舞台，商店与手牌在其下方仍可操作；需要确认浮层不拦截鼠标。
- 首局引导：节点名与锚点变化会导致引导高亮错位，需同步改四步锚点。
- 河道行：位于两个可拖拽区域之间，必须忽略鼠标命中，不能成为拖拽落点或拦截指针。

## 11. 开放问题

- 无。招募阶段对手预告已明确排除；美术资源明确在后续版本单独处理。
