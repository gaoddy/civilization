# 选英雄界面改版与英雄候选分配

> 状态：待确认
> 分支：`feature/hero-pick-redesign`
> 任务范围：客户端选英雄页改版 + 服务端英雄候选分配 + 英雄卡扩到 32 张

## 1. 意图与原因

当前房间页把「房间码 / 成员列表 / 英雄下拉框 / 离开房间」放在同一屏，英雄从全部 13 张里任选，选完还要单独点「准备」。目标是把开局前的选英雄做成一个独立、聚焦的页面：顶部只看到别人的名字与确认状态，底部是自己那几张英雄卡，点卡选中、点确认即准备。

同时确认了一条产品规则：每名玩家只从一组互不重复的英雄里选（现在是 4 张）。13 张英雄不够 8 人 × 4 张，因此英雄卡扩到 32 张。

## 2. 目标与非目标

**目标**

- 选英雄页不显示房间码、不显示离开房间入口。
- 顶部显示其他玩家的名字与确认状态，不显示他们选了哪个英雄。
- 底部列出本人候选英雄卡（卡面 = 铺满的部落色封面 + 底部居中名字），点击为选中态。
- 选中一张卡后弹出该英雄的技能浮层。
- 「确认」一次发出选英雄与准备，确认后不可改选。
- 每人一组互不重复的候选，重进房间（含断线重连）不重抽。
- 英雄卡从 13 张扩到 32 张，新卡进牌池，与既有规则一致。

**非目标**

- 不做邀请 / 分享房间码入口（后续版本另做）。
- 不改对局内选英雄相关展示（`game.gd` 的英雄小卡保持原样）。
- 不改自动匹配、天梯等 v0.2 能力。
- 不新增效果 DSL 原语；19 张新英雄只用现有原语。

## 3. 备选方向与取舍

**候选分配**

| 方向 | 做法 | 代价 | 结论 |
| --- | --- | --- | --- |
| A 座位切片 | 房间种子洗 32 张，按座位号切 4 张，不存状态 | 座位一变候选就变；大厅断线即释放座位 → 重连重抽 | 否 |
| B 玩家分配表 | 房间保存「玩家 id → 4 张候选」，首次进房分配，座位释放时回收 | 房间多一份状态与回收路径 | **采用** |
| C 共享牌堆 | 32 张洗成牌堆，进房抽走 4 张 | 断线重连必重抽，与要求冲突 | 否 |

**重进保留范围**：大厅断线后座位保留宽限期（与对局内 `RECONNECT_GRACE_MS` 同为 30 秒），宽限内重连回到原座位与原候选；主动离开立即释放。这样「重进不重抽」在网络抖动下也成立。

**新增英雄卡与牌池**：沿用「英雄就是带 `is_hero` 的普通随从卡」，32 张全部进牌池，可被任何玩家购买。

## 4. 产品规则（相对 v0.1 基线的增量）

### 4.1 英雄卡与候选

- 英雄卡共 32 张，仍为 `is_hero: true` 的普通随从卡，进牌池、可被购买。
- 开局前每名玩家获得一组候选英雄，当前固定 4 张；同一房间内各玩家的候选互不重复。
- 候选在玩家首次进入房间时确定；该玩家在宽限期内断线重连、或未释放座位前重进，都取回同一组候选。
- 玩家只能从自己的候选中选择；选择列表外的卡被拒绝。
- 候选对本人可见，对其他玩家不可见；其他玩家只看到「已确认 / 未确认」。

### 4.2 确认

- 底部一张卡被点击即为选中态（同时只允许一张）。
- 选中后弹出该英雄技能浮层；点浮层外或再点该卡关闭。
- 点「确认」一次完成「选择英雄 + 准备」。确认后：该卡保持高亮并标「已确认」，其余卡与确认按钮禁用，不可改选。
- 未选中任何卡时「确认」禁用。
- 房间码不在本页展示；本页没有离开房间入口。

### 4.3 页面状态

| 状态 | 表现 |
| --- | --- |
| 加载中 | 候选为空且未确认时，底部显示「正在分配英雄…」，确认禁用 |
| 未连接 | 状态行「未连接服务器」，确认禁用 |
| 已选未确认 | 选中卡描边高亮，技能浮层可见，确认可用 |
| 已确认 | 选中卡高亮 + 「已确认」，其余卡与确认禁用 |
| 错误 | 状态行显示固定中文文案，`message` 进 tooltip；`NOT_IN_ROOM` / `ROOM_NOT_FOUND` 回大厅 |

## 5. 技术方案

### 5.1 内容（19 张新英雄卡）

- 每张含卡牌实体文档（卡面属性、`## 效果`、`## 设计说明`、`## 出处`）与所需技能文档。
- 只使用现有原语：`Growth` / `ModifyStats` / `GrantKeyword` / `DealDamage` / `Copy` / `Discover` / `RefreshShop` / `GainShopSlot` / `Aura`。
- 数值遵守校验脚本约束：学者攻击 0 且生命 = 同星级上限 ×1.3 ±1；非学者落在星级区间内且不超过超模上限。
- 同步更新：总卡数、时代/流派/星级分布常量、英雄卡数量断言、卡牌与技能索引、「13 张」相关表述。

### 5.2 服务端

- `PlayerSlot` 增加 `hero_candidates: Vec<String>` 与 `disconnected_at: Option<Instant>`。
- 房间保存候选分配；首次进房按房间种子洗出的 32 张英雄序列切出下一段未使用的 4 张。
- `RoomUpdatePlayersItem` 增加可选 `heroCandidates`，只在发给本人的那份里填充；广播改为按玩家分别序列化。
- 选英雄校验：卡必须在本人的候选中。已确认（`ready`）后再次选英雄返回 `INVALID_STAGE`。
- 大厅断线改为标记 `disconnected_at` 并启动宽限；tick 中超时按现规则释放座位并回收候选；`Leave` 立即释放。

### 5.3 客户端

- `client/scenes/room.gd` 重写布局：顶部其他玩家（名字 + 确认标记）、底部候选卡行、确认按钮、状态行；删除房间码与离开房间。
- 候选卡为页面私有结构：`ColorRect` 封面（`UITheme.tribe_cover`）、居中首字水印、底部居中名字；选中态加 `color-accent` 描边。
- 技能浮层复用对局页详情面板的视觉（`UITheme.panel_style("raised")`），只在本页实现。
- `GameStore` 增加本人候选字段的读取。

## 6. 验收

- 32 张英雄卡文档通过 `python3 scripts/validate_docs.py`，输出数量与新分布一致。
- 协议 schema、生成物与样例同步，`make protocol-check` / `make protocol-rs-check` 无差异。
- 服务端测试覆盖：候选互不重复、重连取回同组、候选外选择被拒、确认后不可改选、宽限超时释放。
- 客户端冒烟覆盖：候选卡渲染、选中态、确认后锁定、无房间码与离开按钮。
- 目标设备手动验证深浅色与 1280 宽布局。
