# 移除英雄独立实体，英雄并入卡池

> 状态：设计已确认，待实施
> 日期：2026-11-14
> 影响版本：v0.1

## 1. 意图

当前 v0.1 把「英雄」做成与卡牌并列的独立实体：单独的 `heroes/` 目录、独立的 `id` 命名空间、独立的 `hero-system.md` 与校验分支。这会带来两套数据契约、两套索引、两套校验，以及同名人物在英雄池与随从池各存一份的重复。

本设计把英雄还原为卡：**英雄是卡池中的一张随从卡**，只是额外带 `is_hero` 标记与一组英雄技能字段。开局选英雄就是从卡池里选一张 `is_hero` 为真的卡，不再有独立的英雄实体、目录或命名空间。

## 2. 目标与非目标

### 目标

- 删除独立英雄实体：`heroes/` 目录、`hero-system.md`、`HERO_FIELDS` 校验分支、英雄 `id` 命名空间。
- 13 位人物全部成为 `cards/` 下的 `card_type: 随从` 卡，其中 5 位与现有同名随从卡合并为一张。
- 保留「开局选一张英雄卡」与「每回合使用英雄技能」的玩法，行为与现在一致。
- 卡牌、技能、校验脚本、索引与文档只保留一套数据模型。

### 非目标

- 不调整 13 个英雄技能的费用、次数、触发时机与效果文本。
- 不改变开局选英雄的流程、`UseHeroPower` 意图与返回码。
- 不删除扩展层的「英雄坐镇」模式，只把候选口径改为 13 张英雄卡。
- 不为 8 张新并入的卡新增随从技能；它们作为无技能随从进入卡池。

## 3. 现状与影响面

- `heroes/`：13 份英雄文档 + 索引；`hero-system.md` 定义英雄字段与校验。
- 13 个英雄技能 `hero-*`，只被英雄引用。
- 5 位人物已有同名随从卡：`einstein`、`darwin`、`mendel`、`marie-curie`、`faraday`。英雄文档与随从卡目前分属两个命名空间，可以同名。
- 8 位人物只在英雄池存在：`adam-smith`、`davinci`、`edison`、`galileo`、`knuth`、`luxun`、`pasteur`、`tesla`。
- 规则与文档引用英雄的位置：`core-rules.md`（Lobby、`UseHeroPower`、战斗开始被动）、`keywords-and-mechanics.md`、`skill-system.md`、`card-system.md`、`modes-and-achievements.md`、`design-overview.md`、`game-intro.md`、`balance-analysis.md`、各 README 与索引、`network-architecture.md`、`content-backlog.md`、`version-roadmap.md`。
- `scripts/validate_docs.py` 的 `check_heroes`、`check_hero_intros`、`check_skill_context` 与固定数量期望。

## 4. 方案

### 4.1 已选方案 A：英雄就是普通随从卡

13 位人物在 `cards/` 各一张 `card_type: 随从` 卡，新增 `is_hero` 与英雄技能字段。

- 5 位有同名卡的：保留现有随从卡的 `name`、`tribe`、`subtype`、`level`、`era`、`attack`、`health`、`skills`、`is_scholar`；补上英雄字段与 `## 英雄技能`。现有卡名是短名（达尔文、法拉第、爱因斯坦、玛丽·居里、孟德尔），不改全名。
- 8 位没有同名卡的：补齐随从数值、时代、流派、子类与「## 出处」；不新增随从技能，`## 效果` 写「无」。卡名沿用卡池的短名风格（达·芬奇、爱迪生、伽利略、特斯拉、巴斯德、高德纳、鲁迅、亚当·斯密），不使用英雄文档的全名。
- 英雄文档的 `discipline` 只作为新卡的 `subtype` 来源；5 张合并卡保留现有 `subtype`（玛丽·居里仍为「物理」，不改「化学」）。不新增 `discipline` 字段。
- 英雄文档的 `summary` 与 `## 简介` 不搬到卡上；定位信息保留在 `## 设计说明` 的第一条「定位」。
- 13 张英雄卡同时是普通随从：进入共享牌池，可在商店购买，参与三连与牌池份数计算。
- 开局在 `Lobby` 从 13 张 `is_hero` 卡中选 1 张；选择只授予该卡的英雄技能，不把卡放入手牌或战场，也不从牌池扣除。多人可以选择同一张。
- `UseHeroPower` 执行所选英雄卡的 `hero_skill`。

### 4.2 未采用的方案 B：卡池中的第三类「英雄卡」

`card_type: 英雄`，只在开局选，不站场、不进商店。改动更小，但英雄仍是特殊卡类，只统一了目录与命名空间，不符合「所有英雄本质上也是一张卡」的目标，因此不采用。

## 5. 数据模型

### 5.1 卡牌新增字段

只允许 `card_type: 随从` 使用；`is_hero` 为真时以下英雄字段必填。

| 字段 | 类型 | 取值域 | 说明 |
| --- | --- | --- | --- |
| `is_hero` | 布尔 | `true` / `false` | 是否为英雄卡；全卡池恰好 13 张为 `true` |
| `hero_skill` | 字符串 | 技能 id | 开局选中后由 `UseHeroPower` 执行的技能 |
| `hero_skill_cost` | 整数 | 0–2 | 主动 0–2；被动固定 0 |
| `hero_skill_type` | 枚举 | 主动 / 被动 | 主动需消耗金币发起 |
| `hero_skill_uses_per_turn` | 整数 | 1–2 | 每回合可用次数，默认 1；鲁迅为 2 |
| `hero_skill_trigger` | 枚举 | 主动使用 / 首次刷新时 / 战斗开始时 | 主动技能固定为「主动使用」 |

非英雄卡省略以上字段。`hero_skill` 引用的技能仍使用现有技能实体，技能 `id` 保持 `hero-*` 不变，不迁移技能数据。

### 5.1.1 英雄技能的使用边界

- `hero_skill` 只在 `Lobby` 选中该卡后可用；购买同名卡得到的是普通随从，只获得卡上的 `skills`，不获得 `hero_skill`。
- 英雄卡不在场上：不参与站位、攻击、死亡与三连；英雄技能以玩家为宿主结算，被动技能（`OnCombatStart` / `OnFirstRefresh`）在该玩家侧触发，而不是在场上某张随从上触发。
- 选择英雄卡不消耗牌池份数；同一张卡可被多人选中，也可被任何玩家在商店买到。

### 5.2 卡牌文档格式

英雄卡在现有 `## 属性`、`## 效果`、`## 出处` 之间新增两个可选小节：

```
## 属性
（新增行：英雄资格 / 英雄技能 / 英雄技能费用 / 英雄技能类型 / 每回合次数 / 触发时机）

## 效果
（随从技能渲染，无技能写「无」）

## 英雄技能
（英雄技能名：技能 text）

## 设计说明
（原英雄文档的平衡说明，原样保留，便于回查）

## 出处
（现有出处要求）
```

非英雄卡不出现「英雄资格」之后的行，也不出现 `## 英雄技能`。

### 5.3 命名空间

- 卡牌 `id` 全池唯一（含英雄卡），文件名等于 `id`。
- 随从与效果卡名分别唯一；英雄卡是随从，与随从卡共用名称唯一性。5 位同名人物合并后不再有重名。
- 技能 `id` 与卡牌 `id` 分属两个命名空间，允许同名。
- 删除英雄独立命名空间。

## 9. 边界与兼容

- 开局选英雄不消耗卡池份数；同一张英雄卡可被多人选择，也可被任何玩家在商店买到。
- 购买同名卡只得到普通随从与卡上的 `skills`，不获得 `hero_skill`；`hero_skill` 只在 `Lobby` 选中时生效。
- 英雄卡被购买后是普通随从，其三连、出售、金色规则与其它随从一致。
- 英雄技能的费用与每回合次数仍属于「宿主」（当前是所选卡），不进入技能实体；同一技能若未来被随从引用，触发方式由宿主决定。
- 比赛模式的英雄技能替换表不变。
- 「英雄坐镇」扩展模式仍引用 13 张英雄卡，不新增实体。
- `docs/superpowers/plans/` 与 `docs/superpowers/specs/` 中的历史文档保留原样，视为历史记录，不回写。
