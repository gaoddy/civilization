# sim dev：本地联调一键起 7 个机器人

> 状态：待实施
> 日期：2026-11-15

## 意图

开发者本地手测 Godot 客户端时，需要 7 个对端才能凑满 8 人开局。现在要手工敲 7 条 `sim bot` 命令，每条带不同的 `--name` 与 `--hero`，还要先把房间码从客户端抄出来填进 7 条命令。

目标：一条命令拉起服务端与 7 个机器人，机器人自己建房并把房间码打出来；开发者在桌面客户端大厅输入房间码，选英雄、准备，8 人齐自动开局。按 Ctrl-C 一次全部退出。

## 目标与非目标

- 目标：单条 `make dev-bots`；房间码可见可复制；Ctrl-C 干净退出；不改协议、不改客户端、不改服务端。
- 目标：房间码由机器人进程拿到后直接打印，不落临时文件、不轮询日志。
- 非目标：不替代 `make m1b-e2e`。e2e 是无头客户端的自动验收，`dev-bots` 是人工联调的工具，两者职责不同、互不覆盖。
- 非目标：不自动拉起 Godot 客户端，不预填房间码。开发者自己开客户端、自己填码。

## 方案

拆成两层，各做自己擅长的事。

### Rust 侧：`sim dev` 子命令

```
sim dev --connect ws://HOST:PORT/ws [--intent-seed N]
```

- 固定 7 个机器人，不提供 `--bots`。服务端只在座位满 8 且全部准备时开局（`room.rs:105-121`），机器人 + 开发者正好 8；少于 7 个永远开不了局，参数没有可用的取值空间。
- 第 0 个机器人带 `create: true` 建房，用已有的 `BotConfig::room_code_sink`（`oneshot`）拿到房间码——这条通路本来就是为进程内取码预留的，不新增机制。
- 拿到房间码后立刻打印两行：机器可读的 `ROOM_CODE=<code>`，和给人看的提示「在客户端大厅输入房间码 <code>」。
- 再拉起剩余 6 个机器人用 `--room <code>` 加入。
- 英雄卡从 `sim::embedded_catalog()` 里按 id 升序取前 7 张 `is_hero` 卡，确定性分配，开发者不需要传任何英雄参数。
- 每个机器人 `intent_seed = intent_seed + index`，与 `room-service/tests/e2e.rs:83,103` 一致，避免 7 个机器人决策轨迹同步。
- 所有机器人并发跑完一局，结束打印一行汇总（名次与回合数），退出码 0。

实施约束：必须给出明确的超时，否则错误路径会永久挂起。

| 阶段 | 超时 | 超时行为 |
| --- | --- | --- |
| 取房间码 | 10s | 打印原因，非零退出 |
| 等 `GameStarted` | 900s | 打印「开发者未在 900 秒内进房并准备」，非零退出 |
| 整局 | 300s | 打印已有结果，非零退出 |

- 超时或任一机器人提前失败时：取消所有已启动的 bot 任务，打印哪些 bot 失败，以非零退出。不留下「只能靠 Ctrl-C 收场」的路径。
- 开局等待给到 900s，是因为这 900 秒里开发者要手动登录、输入房间码、选英雄、点准备。

不改 `sim bot` 子命令，`scripts/m1b_e2e.sh` 与 `room-service/tests/e2e.rs` 保持原样。

### 脚本侧：`scripts/dev_bots.sh`

职责只有进程生命周期，不含机器人编排。

1. 探测 `DEV_PORT`（默认 8080）是否已被占用。**占用即失败退出**，提示 `端口 8080 已被占用，用 make dev-bots DEV_PORT=8081 换端口`。不做自动复用：`/dev/tcp` 探测只能证明有进程在听，证明不了对端是 room-service，误连会变成难懂的 WebSocket/认证错误。
2. 端口空闲则起 `room-service`，轮询 `/dev/tcp` 等就绪，记下 pid。
3. 就绪后立刻 `kill -0 "$SERVER_PID"` 确认进程还活着——沿用 `scripts/m1b_e2e.sh:51-55` 的守卫。旧服务未完全退出时新进程会绑定失败并立即退出，而端口探测仍然成功，只查端口会误判。
4. 前台运行 `sim dev`，把房间码原样透到终端。
5. `trap` 在正常退出、失败与 Ctrl-C 时都杀掉第 2 步起的服务端进程。
6. 透传 `sim dev` 的退出码。

### Makefile

```make
DEV_PORT ?= 8080

dev-bots: m1b-build
	DEV_PORT=$(DEV_PORT) bash scripts/dev_bots.sh
```

`DEV_PORT` 可覆盖，默认 8080 —— 与客户端登录页预填的 `ws://127.0.0.1:8080/ws` 一致，开发者一个字段都不用改。

## 考虑过的替代方案

- **纯 Bash 起 7 个 `sim bot`**：与 `m1b_e2e.sh` 同构，不碰 Rust。但房间码要从日志里轮询，7 个进程各自管理，Ctrl-C 要逐个关。放弃：把一个「一条命令、按一下就走」的工具，最脏的部分放在进程管理上。
- **机器人自动发现房间**：新增 RoomList 协议消息，机器人不用码就能找到房间。改动跨协议、服务端、客户端三处，收益只是省去复制一次 6 位码。放弃：代价与收益不成比例，且会让协议多出一条只为开发服务的消息。

## 取舍与遗留

- 房间码固定打在 stdout 首部。若日后要同时起多个房间，需要另加参数，当前不做。
- 机器人选英雄是确定性分配（按卡 id 升序取前 7 张英雄），不追求搭配强度；`--intent-seed` 只影响意图选择，不影响英雄分配。
- 没有「只观察大厅、不开局」的模式：7 个机器人固定满员，开发者必须进房才能开局。这是刻意的——这个命令唯一的用途就是凑人开局。
- `make m1b-e2e` 仍占 18080，`dev-bots` 默认 8080，互不冲突。

## 验收

- `make dev-bots` 后终端出现 `ROOM_CODE=<6 位>` 与提示行。
- 客户端登录、在大厅输入该码，选英雄并准备，8 人齐自动开局并正常打完。
- 命令在整局结束后自行退出，退出码 0，端口释放。
- Ctrl-C 退出后端口释放，无残留 `room-service` 或 `sim` 进程。
- 端口已被占用时，命令立即失败并给出可执行的换端口提示，不会连到错误服务。
- 开发者不按任何操作时，900 秒后命令自行报错退出，不永久挂起。
- `make lint`、`make test`、`make m1b-e2e` 仍通过。
