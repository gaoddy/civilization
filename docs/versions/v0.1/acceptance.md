# v0.1 验收记录

> 状态：待记录
> 关联：M2 联机内测、M3 桌面端内测

本文记录 v0.1 的验收口径与内测观察数据，不描述产品规则或实现方案。规则见[核心规则](product/rules/core-rules.md)，实现见[当前实现状态](../../current/README.md)。

## 1. 验收口径

- M2 不设真人完成率验收。断线重连后状态一致由自动化用例保证（见 §4）。
- 桌面端完整对局：至少 1 局由真人从建房走到结算页，结果记入 §2。
- 崩溃率、意图拒绝率、单局时长只记录观察值，不设通过阈值，记入 §3。

## 2. 桌面端完整对局记录

「对局是否完整」指从开局打到 `GameOver` 并收到结算页，而非中途关闭客户端或退出房间。

## 3. 观察项记录

| 日期 | 对局数 | 客户端崩溃次数 | 意图总数 | 拒绝数 | 拒绝率 | 单局时长 | 数据来源 |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |  |

- 崩溃率 = 客户端崩溃次数 ÷ 对局数。
- 拒绝率 = 拒绝数 ÷ 意图总数；按单局 `rejectionRatePermille` 汇总时同样以总数相除，不对千分比再取平均。
- 单局时长取 `durationMs`，可记均值与范围；数据来自服务端每局结束打印的观察日志（见 §5）。

## 4. 断线重连一致性

自动化用例覆盖「重连快照与当前视图逐字段一致」与「战斗阶段重连补发本场 `CombatResult`」，不依赖真人操作：

```bash
cd server && cargo test -p room-service --test reconnect
```

| 日期 | 用例数 | 结果 | 备注 |
| --- | --- | --- | --- |
| 2026-11-20 | 11 | 全部通过 | `cargo test -p room-service --test reconnect`；同时由 `make m1-check` 的 `cargo test --workspace` 覆盖 |

## 5. 记录方法

- 服务端进入 `GameOver` 时向 stderr 打印一行 JSON，字段与计数口径见[房间服务与联网](../../current/technical/room-service/README.md) §15。
- 按天汇总：把当天各局的 `intentsTotal`、`rejectionsTotal`、`durationMs` 逐局抄入 §3，再按行合计计算拒绝率。
- 崩溃次数取客户端进程异常退出次数；同一进程在一次对局内多次异常只计 1 次。
