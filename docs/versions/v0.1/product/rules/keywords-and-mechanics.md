# 关键词与机制

> 依赖：[设计总纲](../overview/design-overview.md)（§6.6、§6.8）、[核心规则](core-rules.md)（§5）
> 状态：方案未实施
> 说明：本文是卡牌文本的唯一词表。[卡牌规范与数据](../content/card-system.md)（含「英雄卡」小节）与实现中的效果解析器只能使用这里的词与模板；出现新词必须先进本表并回写 00-设计总纲。

本文描述关键词判定、结算顺序、临时增益与效果文本模板；不描述具体卡牌与数值曲线。归属版本产品基线的规则。

## 1. 关键词判定表

| 关键词 | 英文名 | 触发时机 | 作用对象 | 叠加规则 | 金色时变化 | 学者是否生效 | 文本模板 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 成长 | Growth | 效果结算时立即 | 一个友方随从 | 可叠加，永久保留 | 单次成长量不变；若效果本身触发两次则执行两次 | 生效，但只取 +生命值部分（实际 +0/+1） | 「成长：获得 +1/+1」 |
| 繁衍 N | Breed N | 回合开始时 | 自身 | N 累加；写入卡面即为固定值 | 触发两次，等价于 N×2 | 生效 | 「繁衍 N：回合开始时获得 +N 生命」 |
| 战吼 | Battlecry | 随从进入战场时 | 自身或指定目标 | 每次入场触发一次 | 触发两次 | 生效 | 「战吼：…」 |
| 亡语 | Deathrattle | 随从死亡时 | 自身或指定目标 | 每次死亡触发一次；复生后再次死亡可再次触发 | 触发两次 | 生效 | 「亡语：…」 |
| 复生 | Reborn | 首次死亡时 | 自身 | 每场战斗最多 1 次 | 仍为 1 次 | 生效 | 「复生：以 1 点生命复活一次」 |
| 嘲讽 | Taunt | 战斗选目标时 | 自身 | 不叠加 | 无变化 | 生效（学者可以嘲讽） | 「嘲讽」 |
| 护盾 | Divine Shield | 自身受到伤害时 | 自身 | 不叠加，最多 1 层 | 无变化 | 生效 | 「护盾：抵消一次伤害」 |
| 连击 | Windfury | 战斗行动时 | 自身 | 不叠加，固定每回合 2 次 | 无变化 | 不生效（攻击力为 0，无意义） | 「连击：每回合可攻击两次」 |
| 传染 | Contagion | 造成伤害后 | 受击目标 | 层数叠加；每层使目标每回合开始 −1 生命 | 触发两次，叠 2 层 | 不生效（反击伤害为 0） | 「传染：造成伤害后，目标每回合 −1 生命」 |
| 最优攻击 | Optimal Attack | 战斗选目标时 | 自身 | 不叠加 | 无变化 | 不生效（攻击力为 0） | 「最优攻击：无视嘲讽，优先攻击可被击杀的目标」 |
| 装配 N | Assemble N | 进入战场时 | 你的其他机械随从 | N 可叠加，每次触发独立结算 | 触发两次，等价于 N×2 | 不适用（学者不是机械） | 「装配 N：进入战场时，使你的其他机械随从各获得 N 次成长」 |
| 播种 | Sow | 死亡时 | 自身 | 不叠加，每次死亡触发一次 | 召唤两个幼苗 | 不适用（学者不是植物） | 「播种：死亡时召唤一个 1/1 的幼苗」 |
| 进化 | Evolve | 战吼时（进入战场） | 自身 | 每次入场触发一次 | 选两次，可重复选同一项 | 不适用（学者不是生物） | 「进化：从 +2/+2、护盾、复生中选择一个」 |

**字段口径**：卡牌不再有 `keywords` 字段；关键词由所引用技能的 `keyword` 字段派生，共 12 个常驻词。「成长」是效果原语，只出现在效果文本与 `Growth` 结算中，不登记为技能 `keyword`。

**英文名转数据 id**：数据与协议里一律使用英文 id，由本节「英文名」列按固定规则转写——去掉末尾的层数标记 `N`（含具体数字），转小写，空格转下划线。例如 `Optimal Attack` → `optimal_attack`、`Divine Shield` → `divine_shield`、`Breed N` → `breed`、`Assemble N` → `assemble`。层数不写进 id：技能 `keyword` 写作 `breed 2` 这样「id + 空格 + 层数」，效果 DSL 用 `keyword=breed,value=2` 表达；文本表按 `enum.keyword.<id>` 提供展示名。

**传染的口径**：传染对召唤物同样生效——召唤物也是随从，获得传染层数并照常结算。首版没有击杀类效果，传染造成的死亡不定义击杀归属；后续若引入击杀效果，再按"造成致命伤害的随从"归属。

### 1.1 流派专属关键词

装配、播种、进化是**流派专属词**，规则与通用 10 词不同：

1. 装配只出现在机械卡，播种只出现在植物卡，进化只出现在生物卡；
2. 它们**不参与时代解锁**——卡牌一出现就可用。通用 10 词仍按 §7 的时代表开放；
3. 卡牌数据里出现跨流派的专属词，视为数据错误；
4. 三者都不改变学者的规则：学者不能装配、不能播种、不能进化。

**进化携带的护盾/复生**是一次性效果，不是卡牌的常驻关键词；一张卡可以"进化选护盾"，但它派生出的关键词仍然遵守时代解锁。

**「光环」不是关键词。** 卡面上的持续效果（如"你的机械随从获得最优攻击"）只在 `text` 中描述，技能 `keyword` 留空；它不参与 [数值与经济](../systems/economy-and-numbers.md)的关键词折算，强度由星级区间约束。数据表里出现 `光环` 视为数据错误。

## 2. 结算顺序

同一时机的多个效果，必须按固定顺序结算，否则服务端与客户端会算出不同结果。

### 2.1 回合开始（`Recruit` 进入前）

1. 繁衍：每个随从按 N 获得生命值；
2. 传染：每个带层数的随从每层 −1 生命；生命降至 0 的随从在本回合开始即死亡（触发亡语）；
3. 其他回合开始效果：按站位从左到右结算（如风车的「回合开始时获得 +0/+1」）；
4. 临时增益的计时器不在此阶段递减。

### 2.2 随从进入战场

1. 随从落到指定位置；
2. 触发战吼；若该战吼是**进化**，先由玩家从三项中选择，再结算；
3. 触发**装配**，按 N 结算；
4. 执行三连判定（见 [核心规则](core-rules.md) §6）。

### 2.3 单次攻击

严格按 [核心规则](core-rules.md) §5.2 的第 1–8 步执行，顺序不可调换。

### 2.4 死亡结算

1. 触发亡语；
2. 触发**播种**（召唤幼苗）；
3. 检查复生：未触发过则以 1 点生命复活。

### 2.5 战斗结束（进入 `Settle` 前）

1. 双方所有随从的**临时增益**清除（只保留成长、繁衍、传染等永久记录）；
2. 死亡随从的亡语已在上一步结算完毕；
3. 计算伤害与胜负。

### 2.6 同一时机的排序规则

- 多个随从同时触发：按**站位从左到右**；
- 单个随从有多个效果：按**卡面文本从上到下**；
- 金色随从的"触发两次"是连续触发两次，中间不插入其他随从的效果；召唤类效果同样额外触发一次（见 [核心规则](core-rules.md) §6）。

### 2.7 战斗开始时（`CombatStart`）

排在 [核心规则](core-rules.md) §5.1 的前置之后、§5.2 的行动循环之前。

1. 英雄卡的被动技能先结算，按先手方 → 后手方；
2. 随从效果按先手方 → 后手方，各自按站位从左到右，单卡文本从上到下；
3. 每条效果结算后立即执行死亡判定与死亡结算（§2.4）；
4. 招募阶段触发、但因目标在敌方而延迟的战吼，在本阶段结算；该随从若已离场，效果取消。

## 3. 时长与永久成长

### 3.1 时长口径

| 时长 | 卡面写法 | 清除时点 |
| --- | --- | --- |
| `permanent` | 获得 N 次成长 / 获得 +X 攻击力 / 获得 +Y 生命值 | 随从离开战场 |
| `combat` | 直到本回合结束 | `Settle` 前（§2.5） |
| `instant` | 无后缀 | 结算完即止 |

- 卡面文本统一写「直到本回合结束」；「直到回合结束」「本回合」不再作为独立说法。
- **成长**是永久记录，写进随从的 `growth` 计数，出售或合成时保留在卡上。
- 成长 1 次默认 +1/+1；`healthOnly` 的成长与学者的成长只加生命值，即 +0/+1。
- 素材里的"加成"按保留方式分三类：成长写「获得 N 次成长」；单边数值的永久修改写「获得 +X 攻击力」或「获得 +Y 生命值」；只管这一场的写「直到本回合结束」。

### 3.2 光环

- 光环是静态效果，在任何区域变化后全量重算，不做增量。
- 不同来源的光环加法叠加；同一关键词的多个来源幂等，只生效一次；同一张卡不叠加自身。
- 「你的」包含自身，写「其他」才排除。
- 光环来源离场导致生命值下降时，生命值下限为 1，不因此死亡。

**书写格式**：光环只能写在 `## 效果` 文本中，固定句式 `你的[其他]<流派>随从获得 <值>`：

| 位置 | 取值 | 示例 |
| --- | --- | --- |
| 是否排除自身 | 省略（含自身）/ `其他` | 你的其他生物随从获得 +1 攻击力 |
| 流派筛选 | 省略（全体）/ 人类 / 机械 / 生物 / 植物 / 病毒 / 学者 | 你的植物随从获得 +1/+1 |
| 值 | `+X/+Y`、`+X 攻击力`、`+X 生命值`，或 `最优攻击` / `嘲讽` / `护盾` / `复生` / `连击` | 你的学者随从获得 +0/+2 |

- 一次光环只写一个筛选条件，「机械与生物」这类并列写法不允许，拆成两条光环。
- 一句文本里有多个效果时用「；」分隔，光环必须是其中一个完整分句，不能嵌在战吼、亡语或装配后面。
- 光环不写入技能 `keyword`；技能 `keyword` 出现「光环」视为数据错误。
- 校验脚本按上述句式检查所有随从的光环分句。

## 4. 学者规则

学者是唯一一个由关键词体系强制约束的流派，规则如下（与 [设计总纲](../overview/design-overview.md) §6.6 一致）：

1. 学者的 `attack` 恒为 0，卡牌数据中不允许出现非 0 值；
2. 任何攻击力加成对学者无效，包括：成长、临时增益、光环、效果牌、主动技能；
3. 学者的成长只产生 +生命值（成长 1 次 = +0/+1）；
4. 学者可以被攻击、被击杀、被嘲讽、被护盾、被复生；
5. 学者的反击伤害为 0，因此不触发传染，也不触发任何"造成伤害后"的效果；
6. 学者的生命值普遍高于同星级其他流派（见 [数值与经济](../systems/economy-and-numbers.md)的星级区间表）。

## 5. 效果文本模板

卡牌文本一律写成「触发词：动作（数值）」，禁止口语化描述。模板如下：

| 场景 | 模板 | 示例 |
| --- | --- | --- |
| 入场效果 | 「战吼：<动作>」 | 「战吼：使一个友方随从获得一次成长」 |
| 死亡效果 | 「亡语：<动作>」 | 「亡语：召唤一个 1/2 的白蚁」 |
| 持续效果 | 「<条件>时，<动作>」 | 「回合开始时，获得 +1 生命」 |
| 光环效果（不是关键词） | 「你的<对象>随从获得 <关键词或属性>」 | 「你的机械随从获得最优攻击」「你的随从获得 +0/+1」 |
| 触发式成长 | 「每当<事件>，获得一次成长」 | 「每当一个友方随从死亡，获得一次成长」 |
| 选择目标 | 「使一个<对象>…」 | 「使随机一个敌方随从失去所有成长」 |

**目标选择器必须显式写出**：随机、最左侧、最左侧及相邻、攻击力最高、全体。招募阶段的战吼不能指定敌方目标；写成「对随机一个敌方随从…」的战吼延迟到 `CombatStart` 结算（§2.7 第 4 条）。

**条件变体**写作「若其为<流派>，改为<效果>」，不拆成两条独立效果。

## 6. 常见错误写法对照

素材中的表述必须按下表改写，否则无法被规则引擎解析：

| 错误写法（素材原文） | 正确写法 | 原因 |
| --- | --- | --- |
| 「属性会随着回合呈现斐波那契数式增长」 | 「回合开始时，获得第 N 个斐波那契数点生命（N 为本局回合数）」 | 特殊数列效果，需写明取值规则，不能只写"增长" |
| 「让己方随从获得一次成长」 | 「战吼：使你的随从各获得一次成长」 | 缺少触发时机 |
| 「加生命值」 | 「成长：获得 +0/+1」 | 未说明是否永久 |
| 「让敌方随从停止一次攻击，失去所有加成」 | 「战吼：使一个敌方随从的攻击力变为 0 直到回合结束，并移除其全部成长」 | 需拆成两个可结算动作，并限定持续时间 |
| 「每回合为自己添加一次繁衍，繁衍会添加自己的生命」 | 「繁衍 1」 | 关键词已覆盖，禁止重复解释 |
| 「本回合金币数翻倍」 | 「战吼：本回合剩余金币翻倍」 | 经济类效果必须写明触发时机与结算边界 |
| 「消灭人类随从所有加成」 | 「战吼：移除所有人类随从的全部成长」 | "加成"含义不明，拆为可判定的成长移除 |
| 「使机械类随从拥有最优攻击方式」 | 「你的机械随从获得最优攻击」 | 光环效果使用固定句式 |

## 7. 关键词与时代的解锁关系

抽取只看星级；下表是"该关键词首次可被抽到的时代"，由卡池中出现它的最小星级反推，不反向约束卡牌（详见 [时代与场景](eras-and-scenarios.md)七时代总表）：

| 时代 | 首次可用关键词 |
| --- | --- |
| 史前 | 繁衍 |
| 原始 | 成长、嘲讽 |
| 古典 | 连击、最优攻击、传染 |
| 封建 | 复生 |
| 工业 | 护盾 |
| 现代 | — |
| 未来 | — |

现代与未来不引入新关键词，终局身份来自 6/7 星池与关键词组合。新增卡牌不得让任何关键词的最小星级前移。

装配、播种、进化不在此表内：它们随流派出现，不按时代解锁（见 §1.1）。

战吼与亡语从史前起即可用。

**解锁表的约束范围**：本表约束的是**随从携带的常驻关键词**与**随从经由效果获得的关键词**；**效果牌文本赋予的临时关键词不受本表约束**。例如 1 星的「阿Q精神」可以让随从获得嘲讽直到回合结束——效果牌是一次性消耗品，赋予的关键词不进入卡池，因此不构成"史前卡池出现嘲讽"。校验脚本据此只对随从统计最小星级。

## 8. 触发时机

一条卡牌（含英雄卡）效果只能使用下表中的时机，不允许自由描述。

| 时机 | 标识符 | 阶段 |
| --- | --- | --- |
| 战吼 | `OnPlay` | 招募 · 入场 |
| 装配 | `OnPlay`（专有关键词） | 招募 · 入场 |
| 进化 | `OnPlay`（专有关键词，先选后结算） | 招募 · 入场 |
| 回合开始 | `OnTurnStart` | 招募 · 回合开始 |
| 使用效果牌 | `OnPlayEffect` | 招募 · 任意时刻 |
| 主动使用 | `OnActivate` | 招募 · 玩家发起 |
| 响应使用效果牌 | `OnUse` | 招募 · 打出时 |
| 每回合首次刷新 | `OnFirstRefresh` | 招募 · 刷新时 |
| 战斗开始时 | `OnCombatStart` | 战斗 · 快照后 |
| 造成伤害后 | `OnDealDamage` | 战斗 · 每次伤害 |
| 死亡时 | `OnDeath` | 战斗 · 死亡结算 |
| 友方随从死亡 | `OnFriendlyDeath` | 战斗 · 死亡队列后 |
| 敌方随从死亡 | `OnEnemyDeath` | 战斗 · 死亡队列后 |
| 友方随从入场 | `OnAllySummon` | 招募 / 战斗 |
| 友方获得成长 | `OnAllyGrowth` | 招募 / 战斗 |
| 友方进化 | `OnAllyEvolve` | 招募 |
| 战斗结束 | `OnCombatEnd` | 战斗 · 结算前 |
| 静态光环 | `Aura` | 持续求值 |
| 条件静态 | `ConditionalAura` | 持续求值 |

**触发队列**：效果产生的新触发进入队列尾部，先进先出；单场战斗的触发总数上限为 200，达到上限后不再触发新效果（与 [核心规则](core-rules.md) §5.2 的行动上限同源，防止递归）。

**`OnPlayEffect` 与 `OnUse` 的分工**：`OnPlayEffect` 是效果牌自身技能的触发，描述「这张牌打出时做什么」；`OnUse` 是其他技能对"有玩家打出效果牌"这一事件的响应，描述「每当有人打出效果牌时做什么」，不改变被打出牌的效果。

## 9. 效果表达模型

### 9.1 结构

技能是效果文本的实体，卡牌（含英雄卡）一律通过 `skills` 引用技能获得效果。一条技能效果由四段组成：`Trigger × Selector × Op × Duration`；主动技能在技能实体上带 `cost` 与 `uses_per_turn`，触发式技能按文本前缀确定时机（见[技能规范与数据](../content/skill-system.md)）。静态光环以 `Aura` / `ConditionalAura` 作为触发登记（§8），动作仍复用 §9.3 的常规原语，不单设光环原语。

### 9.2 选择器

| 维度 | 取值 |
| --- | --- |
| 区域 | 战场 / 手牌 |
| 阵营 | 己方 / 敌方 / 双方 / 自身 / 事件目标 |
| 筛选 | 流派、子类、卡牌 id、类型、是否学者、是否带某关键词、「其他」 |
| 选取 | 玩家指定 / 随机（走种子）/ 最左侧 / 最左侧及相邻 / 攻击力最高 / 全部 / 随机 N 个 |

### 9.3 动作原语

| 原语 | 结构 | 说明 |
| --- | --- | --- |
| 成长 | `Growth {selector, times, healthOnly, timesIf}` | 永久；`healthOnly` 只加生命值；`timesIf` 按流派改次数 |
| 属性修改 | `ModifyStats {selector, attack, health, duration, canKill}` | 永久、临时与负向修改 |
| 赋予关键词 | `GrantKeyword {selector, keyword, value, duration}` | 含赋予繁衍 N、传染层数 |
| 移除成长 | `RemoveGrowth {selector}` | 移除全部成长 |
| 禁止攻击 | `CannotAttack {selector, duration}` | 本场无法攻击 |
| 伤害 | `DealDamage {selector, amount, source}` | 经过护盾与复生 |
| 召唤 | `Summon {selector, token 或 card, count}` | 召唤位置由 `selector` 决定；`token` 取注册表 id，`card` 取牌池卡 id |
| 复制 | `Copy {selector, to}` | `to` 为手牌或战场 |
| 发现 | `Discover {pool, choose}` | 三选一 |
| 刷新商店 | `RefreshShop {free, extra}` | 主动技能专用 |
| 增加商店槽位 | `AddShopSlot {era, count}` | 主动技能专用；商店额外出现 `count` 张 `era=current` 的随从 |
| 获得随从 | `GainMinion {from, level, to}` | 主动技能专用 |

光环不单设原语：静态光环在 §8 登记为 `Aura` / `ConditionalAura` 触发，其动作写 `ModifyStats` 或 `GrantKeyword`，并显式带 `duration=permanent`。

### 9.4 数据语法

技能实体用 `effects` 字段记录结构化效果（见[技能规范与数据](../content/skill-system.md) §2），单行 DSL：

```
<effect>[ ; <effect>...]
<effect> = <trigger>|<op>|<selector>[|<params>]
```

- 段之间用 `|`；效果之间用 `;`；参数之间用 `,`，参数写作 `key=value`，同一效果内键不重复；没有参数时省略第 4 段；
- 技能没有可结构化行为、只有关键词时写 `[]`。

**选择器**：

| 写法 | 含义 |
| --- | --- |
| `self` | 技能携带者自身 |
| `target` | 触发事件的目标（如「它」指获得成长的那个随从） |
| `<阵营>:<选取>[:<筛选>...]` | 按阵营与选取方式取一组随从 |

- 阵营：`friendly` / `enemy` / `both`；
- 选取：`single`（玩家指定）/ `all` / `random` / `leftmost` / `leftmost+adjacent` / `topAttack`；
- 筛选：`tribe=<human|machine|biology|plant|virus|scholar>`、`subtype=<subtype slug>`、`id=<卡牌 id>`、`type=<minion|effect>`、`other=<true|false>`；多个筛选并列即同时满足。

**参数**：

| 参数 | 取值 | 用于 |
| --- | --- | --- |
| `times` / `count` / `amount` / `attack` / `health` / `value` / `extra` | 整数（可为负） | 次数、数量、伤害与数值改动 |
| `duration` | `permanent` / `combat` | 见 §3.1；省略按 `instant` |
| `canKill` | `true` / `false` | 负向修改是否可致死 |
| `healthOnly` | `true` / `false` | 成长只加生命值 |
| `timesIf` | `<英文流派 id>:<次数>` | 目标属于该流派时改次数，如 `timesIf=human:2` |
| `condition` | `count:<阵营>:<筛选>:<比较符><数值>` | 控制数量条件，如 `count:friendly:tribe=human:>=3` |
| `when` | `<筛选>` | 限定触发事件的对象，如 `when=tribe=biology` |
| `keyword` | §1 的英文 id（如 `taunt`、`optimal_attack`） | 赋予的关键词；`breed` / `assemble` 另带 `value` 层数 |
| `token` / `card` | Token 注册表 id / 卡牌 id | 召唤目标；`Summon` 二者取一 |
| `to` | `hand` / `board` | 复制或获得的目标区域 |
| `from` | `hand` / `board` / `shop` | 复制或获得的来源 |
| `type` | `minion` / `effect` | 从手牌复制时限定卡牌类型 |
| `pool` / `choose` | 发现池、可选数量 | `Discover` |
| `free` | `true` / `false` | 免费刷新 |
| `era` / `level` | `current` 或具体值 | 商店槽位时代、获得随从的星级 |

示例：

- `OnPlay|Growth|friendly:single|times=2`
- `OnCombatStart|DealDamage|enemy:leftmost|amount=3`
- `Aura|ModifyStats|friendly:all:tribe=machine|attack=2,health=2,duration=permanent`
- `OnActivate|Copy|self|from=hand,type=minion,to=hand`

`effects` 是机器字段，不进入 `## 属性` 表；`## 效果` 仍由技能 `text` 渲染，与 `effects` 语义一致。卡牌不重复记录 `effects`——它们通过 `skills` 引用技能，效果由技能实体统一维护。

## 10. 属性求值顺序

每个随从持有：`base`（卡面数值）、`growth`（成长次数）、`keywords`（由所引用技能派生出的常驻关键词）、`auras`（生效中的光环）、`modifiers`（临时修改）、`breed`（繁衍层数）、`contagion`（传染层数）与战斗标记（护盾、复生、攻击次数、禁攻）。

```
attack = base.attack + growth（学者与 healthOnly 为 0）+ Σ aura.attack + Σ modifier.attack
       → 学者强制 0 → 下限 0

health = base.health + growth（每次 +1）+ Σ aura.health + Σ modifier.health
       → 下限 0，为 0 触发死亡
```

1. 学者过滤只在 `attack` 的最后一步执行，一次过滤全部来源；
2. 光环在任何区域变化后重算（§3.2）；
3. 负向修改默认 `duration: combat`、`canKill: true`；
4. 光环失效不致死，生命值下限为 1。
