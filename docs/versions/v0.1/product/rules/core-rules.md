# 核心规则

> 依赖：[设计总纲](../overview/design-overview.md)（§6.1–§6.5、§6.11、§6.12）
> 状态：方案未实施
> 说明：本文定义的状态名、意图名、返回码是全项目的唯一命名，[联网与技术架构](../../technical/architecture/network-architecture.md)与后续实现必须复用。

本文描述对局房间、阶段状态机、玩家意图、招募与战斗结算、淘汰与异常处理规则；不描述卡牌数值、关键词判定与实现。归属版本产品基线的规则。

## 1. 对局与房间

- 一局 8 名玩家，每人初始 40 点生命，按固定座位号 0–7 入座（座位号由服务端分配，贯穿全局，用于平局判定）。
- 房间创建时确定三件事并写入对局种子：本局启用的 5 个流派、8 人座位顺序、首回合先手方。
- 玩家生命降至 0 或以下即出局；出局后不再参与招募与配对，但可继续观战。
- 对局在第 20 回合结束后强制收束（见 §7）。
- 房间必须有 8 名真人就绪才进入对局，**不设 AI 补位**；人数不足时房间保持 `Lobby` 继续等待。
- 断线与 AFK 由 AI 托管（§8.1），托管只接管已有座位，不改变对局人数。
- 开局时，每位玩家从卡池的 13 张 `is_hero` 卡中选 1 张作为英雄；选择不消耗牌池份数、不进入手牌或战场，多人可以选择同一张。买到的同名英雄卡按普通随从结算，并获得该卡的全部 `skills`（含其中的主动与被动技能）。

## 2. 阶段状态机

```
Lobby ──(8 人就绪)──→ Recruit ──(全员 EndRecruit 或超时)──→ Combat
  ↑                     ↑                                     │
  └──(重开)── GameOver ←┴────────── Settle ←──────────────────┘
```

| 状态 | 进入条件 | 允许的意图 | 退出条件 |
|---|---|---|---|
| `Lobby` | 房间创建 | 准备/换英雄卡 | 8 人准备完毕 |
| `Recruit` | 回合开始、结算完毕 | 全部招募类意图 | 全员 `EndRecruit` 或 90 秒超时 |
| `Combat` | 招募结束 | 无 | 战斗演示播完 |
| `Settle` | 战斗结算完成 | 无 | 伤害与淘汰处理完成 |
| `GameOver` | 仅剩 1 人或第 20 回合结束 | 无 | — |

**阶段是服务端权威的**：客户端不得自行推进状态，只能发送意图并等待 `StateUpdate`。

- `Combat` 为战斗演示阶段，不可跳过、没有加速；播完才进入结算。招募与演示共用固定的 150 秒回合预算，见 §5.5。

## 3. 玩家意图

| 意图 | 前置条件 | 资源变化 | 副作用 | 失败返回码 |
|---|---|---|---|---|
| `BuyMinion` | 处于 `Recruit`；槽位有卡；金币足够；手牌有空位 | −卡牌费用 | 卡牌进入手牌；随从仍做三连判定（不触发战吼、不入场） | `NOT_ENOUGH_GOLD` / `SHOP_SLOT_EMPTY` / `NO_SPACE` / `INVALID_STAGE` |
| `SellMinion` | 处于 `Recruit`；目标存在 | +1 金币（金色 +3） | 从场上/手牌移除；归还牌池 | `NO_SUCH_MINION` |
| `RerollShop` | 处于 `Recruit` | 首次免费，其后 −1 金币 | 重抽 6 个槽位 | `NOT_ENOUGH_GOLD` |
| `UpgradeEra` | 处于 `Recruit`；时代 < 7；金币 ≥ 当前升级费用 | −当前升级费用 | 时代 +1；刷新商店为新时代概率 | `NOT_ENOUGH_GOLD` / `ALREADY_MAX_ERA` |
| `PlayCard` | 处于 `Recruit`；卡在手中；随从需棋盘有空位 | 无（费用在获得该牌时已支付） | 从手牌打出到指定站位（缺省追加到最右）；效果牌即时结算；随从入场，需要目标的战吼转为待选目标 | `CARD_NOT_IN_HAND` / `NO_SPACE` / `INVALID_CHOICE` |
| `RearrangeBoard` | 处于 `Recruit` | 无 | 把随从移动到指定站位，原位及其右侧依次移位 | `NO_SUCH_MINION` |
| `FreezeShop` | 处于 `Recruit` | 无 | 冻结当前槽位到下回合开始 | — |
| `UseHeroPower` | 处于 `Recruit`；费用足够；本回合次数未用尽 | −技能的 `cost` | 使用所选英雄卡上的一个主动技能，次数受该技能 `uses_per_turn` 限制 | `NOT_ENOUGH_GOLD` / `HERO_POWER_LIMIT` |
| `EndRecruit` | 处于 `Recruit` | 无 | 本玩家结束招募 | — |
| `ChooseDiscover` | 存在本座位的发现或进化待选 | 无 | 消费最靠前的待选 | `INVALID_CHOICE` |
| `ChooseTarget` | 存在本座位的目标待选 | 无 | 以指定随从结算该待选的战吼 | `NO_VALID_TARGET` |

**通用规则**：同一回合内，`BuyMinion` / `RerollShop` / `UpgradeEra` / `PlayCard` / `UseHeroPower` 共用同一个金币池，顺序不限；金币不跨回合累积，多余部分清零。

**补充返回码**：`NO_VALID_TARGET`（效果需要指定单一目标、存在合法目标但未指定或指定不合法；没有合法目标时主动技能不可用并返回该错误，随从战吼与效果牌则效果落空、意图仍可提交；`ChooseTarget` 指定的随从不在合法池时同样返回该码；见 [卡牌规范与数据](../content/card-system.md) §2.1「英雄卡」）；`TARGET_NOT_ALLOWED`（招募阶段试图指定敌方目标）；`INVALID_CHOICE`（`ChooseDiscover` 的候选索引不合法）。

## 4. 招募阶段细则

### 4.1 商店

- 6 个槽位。回合开始时自动刷新，首次手动刷新免费，之后每次 1 金币。
- 冻结的槽位在下回合开始时保留，不自动刷新；手动刷新会取消冻结。
- 冻结只保留下回合开始；若本回合升时代，商店按新时代概率免费重抽，冻结同时取消。
- 槽位内容按"当前商店等级（= 玩家时代）× 星级"的概率表抽取（见 [数值与经济](../systems/economy-and-numbers.md)），并从共享牌池中实际扣除该卡。
- 牌池中某张卡被抽完时，该卡不再出现在任何人的商店。

### 4.2 棋盘与手牌

- 战场 7 个随从位。手牌上限 10 张，存放效果牌与未上场的随从。
- 商店购买的牌**一律先进入手牌**，不直接入场；随从需玩家再提交 `PlayCard` 才进入战场。效果牌同样先入手牌，由 `PlayCard` 使用。
- 随从在**进入战场时**触发战吼；买入不触发战吼、不登记进化。
- 战斗棋盘与招募棋盘同为 7 位，按**存活随从**计数：战斗中阵亡的随从不占位，召唤、播种、复制与复生都要求存活数 < 7，满场时一律作废。

### 4.3 升时代

- 一次只能升一级，费用见总纲 §6.2；未支付时，每回合开始时费用 −1，最低 2。
- 升时代后，商店立即按新时代概率重抽（免费，不消耗金币）。
- 时代不会下降。

### 4.4 目标选择规则

- 招募阶段的任何意图**只能指定己方目标**。对手的阵容在本阶段不可见（见 [联网与技术架构](../../technical/architecture/network-architecture.md)隐藏信息清单），因此不存在"对一个敌方随从"的主动操作。
- 所有"对一个敌方随从…"的效果由服务端按卡面写明的选择器选目标，可选：随机（走种子）、最左侧、最左侧及相邻、攻击力最高、全体。卡面必须写明是哪一种，未写明视为数据错误。
- 招募阶段的战吼若声明了敌方目标（如「战吼：对随机一个敌方随从造成 1 点伤害」），不在招募期结算，而是延迟到战斗开始（见 [关键词与机制](keywords-and-mechanics.md) §2.7）；该随从在战斗开始前离场则效果取消。
- 亡语等战斗内触发的敌方效果，在触发时按同一套选择器立即选目标。
- 需要指定单一目标的效果（`target` 选择器，以及「使一个友方随从…」这类写成 `friendly:single` 的战吼、英雄技能与效果牌）在存在合法目标时必须指定；未指定或目标不在合法池内返回 `NO_VALID_TARGET`。合法池为空时，主动技能不可用并返回该错误；随从战吼与效果牌落空，意图仍可提交。
- 合法池只含打出或入场前已存在的随从；效果牌在释放瞬间按当时的棋盘判定，随从战吼则在随从**入场后**判定，因此池内包含该随从自身。
- 需要指定单一目标的随从战吼不阻塞出牌：随从先入场，随即转入目标待选，玩家提交 `ChooseTarget` 后才结算；待选期间该座位不能提交其它招募意图。
- 客户端提交敌方目标即返回 `TARGET_NOT_ALLOWED`。

## 5. 战斗结算算法

### 5.1 前置

1. 锁定双方阵容快照，**招募阶段的任何操作在战斗阶段不可见、不可改**。
2. 每个随从获得 `attackTokens`：普通 1，连击 2。护盾记 1 层，护盾被消耗后不再恢复。
3. 先手方：上一场战斗的胜者先手；首回合由对局种子决定。
4. **战斗开始时**：按 [关键词与机制](keywords-and-mechanics.md) §2.7 结算所选英雄卡上的被动技能、延迟战吼与所有 `OnCombatStart` 效果，之后才进入 §5.2 行动循环。

### 5.2 行动循环

按以下顺序执行，直至一方场上无存活随从或行动数达到 200 次（防死循环）：

1. **选攻击者**：双方各有指针，从各自最左侧开始交替取随从；指针所指随从已死亡则右移。攻击者 `attackTokens` 为 0 则右移。
2. **选目标**：
   - 若攻击者有「最优攻击」：在敌方存活随从中筛出"可被击杀"者（攻击力 ≥ 目标当前生命且目标无护盾），在其中随机；无可击杀目标时退回普通规则；
   - 否则若敌方存在「嘲讽」：只在嘲讽随从中随机；
   - 否则在敌方全部存活随从中随机。
3. **结算主伤害**：目标若有护盾，抵消本次伤害并移除护盾；否则目标生命 −= 攻击力。
4. **触发传染**：若攻击者带「传染」且本次实际造成的伤害 > 0，目标获得 1 层传染（学者反击伤害为 0，故不触发）。
5. **结算反击**：目标仍存活则对攻击者造成等量于目标攻击力的伤害（护盾规则同上）；目标攻击力为 0 时不造成伤害。
6. **死亡判定**：生命 ≤ 0 的随从进入死亡队列，同一时点死亡的随从按站位从左到右处理。
7. **死亡结算**：按队列顺序触发亡语 → 若该随从带「复生」且本场尚未触发，则以 1 点生命复活并清除该次死亡；已触发过复生的不再复活。
   同一时点的进场顺序固定为**死亡 → 召唤 → 复生**：死亡先把位置空出来，亡语与播种召唤只用空出的位置（满 7 个存活随从时召唤作废）；复生最后判定，位置已被召唤占光时不再复生，但该次复生机会照常消耗，本场不再尝试。
8. **推进指针**：攻击者 `attackTokens` −1；为 0 时指针右移，否则留在原地（下一次仍由它攻击）。
9. **重复**。

### 5.3 结束与胜负

- 一方场上无存活随从时战斗结束。另一方为胜者。
- 双方同回合清场：判**平局**，双方都不受伤害、都不计为本场胜者；战报显示无胜者、伤害为 0。
- 胜者不受伤害；败者受到伤害（§5.4）。
- 平局不改变下一次战斗的先手，先手沿用上一场胜者。
- 行动数到上限而双方仍有存活者时不属于同回合清场，仍按生命 → 累计伤害 → 座位的判据分胜负。

### 5.4 伤害公式

```
受到伤害 = 败者当前已升到的时代等级（1–7）
         + 向上取整（胜方所有存活随从的星级之和 ÷ 2）
```

- 用"已升到的时代"，不是"回合数对应的时代"。
- 学者计入星级之和。
- 单次伤害上限 15，下限 1（即使胜方无存活随从也至少造成 1 点）。
- **为什么除以 2**：随从星级是 1–7，若直接求和，第 12 回合的单次伤害会达到 30–40，40 点生命只够两次失败，20 回合的对局会在第 10 回合前结束。

### 5.5 战斗演示与回合时长

- 每个回合固定 150 秒：招募 90 秒、战斗演示预算 60 秒。
- 演示按服务端结算出的动作序列播放，双方画面一致；演示不可跳过、没有加速，播完才进入结算。
- 演示实际耗时 T 从下回合招募里抵扣：下回合招募时长 = 150 − T，不设下限。
- 演示只影响下回合招募时长，不影响金币、商店与结算结果。

## 6. 三连与发现

1. **判定时机**：每次获得随从后（购买入手牌、发现、效果牌召唤）立即判定。
2. **判定范围**：只看该玩家自己的战场 + 手牌，不查询牌池余量。
3. **合成**：3 张同名同星级随从合并为 1 张金色随从，占 1 个格子，攻击力与生命值各 ×2；战吼/亡语额外触发一次。
4. **发现**：合成后立即触发一次发现，从"该卡星级 +1"的随从中三选一（6 星卡从 6 星中三选一），候选受本局启用的流派限制。
5. **金色随从**：出售返还 3 金币；不可再参与三连。
6. **Token**：播种幼苗、合成细胞等衍生随从单独注册（见 [Token 注册表](../content/tokens/README.md)），不进牌池、不可购买、不参与三连，死亡即消失。
7. **召唤已有卡**：从牌池扣除份数；池空时创建副本但不扣池。
8. **复制品**：进入手牌，占手牌位，不扣牌池；参与三连。

## 7. 淘汰、排名与平局

- 结算阶段依次处理：扣血 → 生命 ≤ 0 的玩家出局 → 记录出局顺序 → 检查是否仅剩 1 人。
- 正常结束的排名 = 出局顺序倒序（最后出局者为第 2 名，最后存活者为第 1 名）。
- 第 20 回合结束仍有多人存活时，立即结束并按下述优先级排名，逐级比较：
  1. 生命值高者优先；
  2. 上一场战斗胜者优先；
  3. 本局累计造成伤害高者优先；
  4. 座位号小者优先。
- **确定性要求**：同一事件日志重放必须得到完全相同的名次，不允许使用未播种的随机。

## 8. 异常与托管

### 8.1 超时与 AFK

- 招募阶段 90 秒；剩余 10 秒时服务端广播 `TimerWarning`。演示阶段抵扣后的招募时长按实际值计算，警告口径不变。
- 超时自动执行 `EndRecruit`；若玩家在超时前 10 秒内无任何意图，且连续两个回合如此，第三回合起进入 AI 托管。
- AI 托管使用简单策略：先把手牌随从打上棋盘 → 买得起的最贵卡 → 升时代 → 刷新；不改变玩家已有阵容结构。

### 8.2 断线重连

- 断线 30 秒后进入 AI 托管；重连时服务端下发全量 `Snapshot`，客户端丢弃本地状态后整片载入，不补发历史事件。
- 重连不消耗回合时间；若重连发生在 `Combat` 阶段，客户端从当前演示进度继续播放，不重算、不从头重播。

### 8.3 边界情况

| 情况 | 处理 |
|---|---|
| 手牌已满 | 禁止购买，返回 `NO_SPACE` |
| 牌池中目标卡已抽完 | 商店不出现该卡；三连仍可基于玩家自有卡成立 |
| 对阵人数为奇数 | 落单座位**必有对战**：对战一名**随机出局者**的最终阵容（幽灵），取其棋盘原样（保留成长、永久增益与自身光环），不结算英雄被动、不产生手牌、不写回牌池；失败按伤害公式正常扣血（败者时代 + 幽灵存活随从星级），获胜计入本回合胜者；双方同回合清场判平局（与真实战同一口径）；幽灵每回合从全部出局者中随机抽一次，可能连续抽到同一人；没有出局者时幽灵为空阵容 |
| 同一对手连续匹配 | 配对时优先排除上一场对手；仅剩 2 人时无法排除 |
| 战斗超过 200 次行动 | 双方仍有存活者时不属于同回合清场，按生命 → 累计伤害 → 座位分胜负（判据同 §5.3） |
| 玩家在第 20 回合前全员存活 | 第 20 回合结算后强制结束 |
