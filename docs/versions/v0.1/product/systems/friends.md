# 好友

> 依赖：[房间与邀请](rooms-and-invites.md)（§3）、[核心规则](../rules/core-rules.md)
> 状态：方案未实施

本文描述 v0.1 好友关系的添加、申请、列表、删除与房间邀请；不描述技术实现、页面视觉、私聊与好友榜（v0.2）。归属版本产品基线的系统规则。

## 1. 定位与范围

- 好友是账号之间的单向申请、双向确认关系；好友关系跨端同步，跟随手机号账号。
- 好友功能用于好友列表、最近对局添加与邀请加入房间。
- 首版不做好友榜、私聊、拉黑、举报、赠送、战队与关注。
- 页面与视觉见 UI 设计文档，本文只定义规则与状态。

## 2. 添加好友

支持两种添加入口：

| 入口 | 规则 |
| --- | --- |
| 最近对局 | 展示最近 20 局内同局过的玩家，按最近对局时间排序；可对其中任意玩家发送好友申请 |
| 玩家 ID 搜索 | 输入完整的 6 位玩家 ID 精确查找，不支持昵称模糊搜索 |

- 不能向自己发送申请。
- 已是好友时，入口显示「已是好友」，不显示申请按钮。
- 已有待处理申请时，不能重复发送；入口显示「已申请」。
- 对方好友数量达到 100 时，申请无法发送，提示对方好友已满。
- 发送申请不需要对方在线；对方离线时申请保留。
- 首版不展示「谁看过我」与推荐好友。

## 3. 好友申请

- 申请列表展示申请人昵称、玩家 ID 与发送时间。
- 待处理申请上限 20 条；达到上限后新申请不再进入列表，申请方看到「对方申请已满」。
- 申请 7 天内未处理自动失效；失效后申请方可以重新发送。
- 同意后双方立即成为好友，双方好友列表同时出现对方。
- 拒绝后申请失效，申请方不收到拒绝通知；申请方可以再次发送，但 24 小时内最多发送 3 次。
- 对方在申请待处理期间将申请方加入黑名单的能力首版不做。

## 4. 好友列表

- 好友上限 100 人；达到上限后需要先删除好友才能通过新申请。
- 列表按状态排序：在线优先，其次对局中，最后离线；同一状态内按昵称首字排序。
- 每条展示昵称与状态；首版不展示段位与积分。
- 列表支持删除好友：单方删除立即解除双方好友关系，不需要对方同意，也不通知对方。
- 好友状态只对好友可见；非好友看不到在线状态。

## 5. 邀请加入房间

- 从好友列表可以邀请好友加入自己所在的房间；对方接受后进入该房间。
- 对方在房间已满、对局已开始或不在线时接受失败，邀请方看到失败原因。
- 邀请在 60 秒内未响应自动失效。
- 好友接受邀请后按[房间与邀请](rooms-and-invites.md) §4 的规则准备与开局。
- 首版不做好友小队与组队排队；自动匹配在 v0.2 引入。

## 6. 状态与边界

| 场景 | 表现 |
| --- | --- |
| 未登录 | 好友入口不可用，提示先登录 |
| 搜索不存在的玩家 ID | 显示「未找到该玩家」 |
| 对方已是好友 | 显示「已是好友」 |
| 对方好友已满 | 申请发送失败，提示对方好友已满 |
| 自己的申请列表已满 | 新申请不进入列表，申请方看到「对方申请已满」 |
| 对方 7 天未处理 | 申请自动失效，可重新发送 |
| 邀请 60 秒未响应 | 邀请自动失效 |
| 邀请时对方不在线 | 邀请发送失败，提示对方不在线 |
| 删除好友 | 双方关系立即解除，双方列表同时移除 |

## 7. 首版不做

- 不做私聊、语音、表情与动态。
- 不做拉黑、举报、屏蔽与投诉。
- 不做好友赠送、借用卡牌与组队奖励。
- 不做关注、粉丝、战队与社区。
- 不做昵称模糊搜索与推荐好友。
- 不做好友榜与好友小队；好友榜与小队匹配在 v0.2 引入。

## 8. 验收标准

1. 最近 20 局内的同局玩家出现在添加列表，可以发送好友申请。
2. 输入完整 6 位玩家 ID 可以精确找到玩家；输入不完整或不存在的 ID 显示未找到。
3. 对方同意后，双方好友列表同时出现对方；拒绝后申请方可以重新发送。
4. 待处理申请超过 20 条时，新申请不进入列表。
5. 申请 7 天未处理后自动失效。
6. 好友上限为 100，达到上限后无法通过新申请。
7. 删除好友后双方关系立即解除。
8. 好友邀请可以把自己所在房间的加入入口发给好友；对方接受后进入房间。
9. 邀请 60 秒未响应后自动失效。
