# 技能规范与数据

> 依赖：[卡牌规范与数据](card-system.md)、[英雄与技能](hero-system.md)、[关键词与机制](../rules/keywords-and-mechanics.md)
> 状态：方案未实施
> 数据：`docs/versions/v0.1/product/content/skills/`（118 份，文件名 = id）

本文描述技能实体的定义、字段规范、引用与渲染规则、共享规则、数据总览与校验方式；不描述具体实现与后续版本技能。归属版本产品基线的内容。

## 1. 定义与关系

- **技能**：一段可独立结算的效果。技能有独立 `id` 与规范文本，可被任意卡牌或英雄引用，也可被多张同时引用。
- **效果牌**：本质上是一定携带技能的卡牌，必须携带至少 1 个技能，技能数量不设上限。
- **随从牌**：可携带 0–N 个技能；省略 `skills` 等于不带技能。
- **英雄**：恰好携带 1 个技能，由 `skill` 引用。
- **关键词**：不再是卡牌字段，而是技能上的属性 `keyword`；卡牌的关键词由所引用技能派生。

技能 `id` 与卡牌 `id`、英雄 `id` 分属三个命名空间，各自查重，允许同名。

**共享引用**：同一技能被多张卡牌或英雄引用时，它们看到同一份规范文本，技能改动同步生效；但每处引用各自结算，互不影响。

## 2. 字段规范

每个技能一个文档：`docs/versions/v0.1/product/content/skills/<id>.md`，文件名等于 `id`。文档由 YAML front matter 与正文组成。

| 字段 | 必填 | 取值域 | 说明 |
| --- | --- | --- | --- |
| `id` | 是 | `^[a-z][a-z0-9-]*$` | 技能命名空间内唯一；必须等于文件名 |
| `name` | 条件必填 | 自由 | 显示名；被英雄引用的技能必填，卡牌技能可省略 |
| `keyword` | 否 | 12 个常驻关键词的取值（含 `繁衍 N`、`装配 N`） | 该技能使携带者登记的关键词；赋予他人关键词的效果不填 |
| `text` | 是 | 自由 | 技能的规范效果文本，也是卡面显示的唯一真值 |
| `match_text` | 条件必填 | 自由 | 比赛模式下的确定性替换；被效果牌或英雄引用的技能必填，无随机写「同左」 |

**正文约定**：一级标题在 `name` 存在时为显示名，否则为 `id`；`## 属性` 用表格复述 `id`、关键词与比赛模式替换；`## 效果` 写 `text` 原文。属性表与 front matter 必须一致，由 §6 的校验脚本交叉核对。

**`text` 的形态**：沿用卡面现有写法。战吼、亡语、繁衍、装配、播种、进化、传染等带触发关键词的效果保留前缀（如「战吼：使一个友方随从获得一次成长」）；英雄主动技能不带前缀，触发方式由英雄字段表达。

**技能边界**：一段技能是一个可独立结算的效果单元，不等于按「；」机械切分。「若其为<流派>，改为<效果>」是前一段效果的条件变体，必须与前一段留在同一个技能内（如炼金术士、巫医），因此技能 `text` 内部可以出现「；」。其余并列效果各成一个技能。

**`keyword` 的口径**：只登记「携带者自身拥有的常驻关键词」。例如白蚁的「繁衍 1」登记在技能 `keyword` 上，再由白蚁这张卡派生；而效果牌「光合作用」的文本是「使一个友方植物随从获得繁衍 2」，关键词是赋予目标的，技能的 `keyword` 留空，卡牌也不因此获得关键词。每段技能最多登记 1 个关键词；一张卡有多个关键词时，拆成多个技能。

**不做的参数化**：`繁衍 1`、`繁衍 2`、`繁衍 3` 是三个技能，不合并为带参数的模板。参数化留待后续版本。

## 3. 引用与渲染

### 3.1 卡牌

卡牌用 `skills: [<技能 id>, ...]` 引用技能，有序列表，顺序即结算顺序，等价于原「卡面文本从上到下」。效果牌的 `skills` 必填且非空；随从牌可省略，省略等于不带技能。

- **`## 效果`**：按 `skills` 顺序取技能 `text`，用「；」连接；不带技能时写「无」。
- **属性表**：新增「技能」行，列出技能 `id`，多个用「；」分隔；无技能写「无」。
- **关键词**：随从牌的「关键词」行保留，值由所引用技能的 `keyword` 按 `skills` 顺序派生；没有关键词写「无」。卡牌不再有 `keywords` 字段。

### 3.2 英雄

英雄用 `skill: <技能 id>` 引用单个技能。`skill_cost`、`skill_type`、`skill_uses_per_turn`、`skill_trigger` 保留在英雄上；触发时机、费用与每回合次数属于宿主，不进入技能实体。同一个技能可以被一个战吼随从和一个战斗开始时结算的英雄共用，触发方式由宿主决定。

### 3.3 关键词派生

卡牌派生出的关键词只来自技能 `keyword`，不来自卡面文本的任意词。效果文本中「使目标获得某关键词」不使携带者登记该关键词（见 §2「`keyword` 的口径」）。数值折算使用派生后的关键词。

## 4. 共享规则

- 只有 `text` 完全相同、且 `keyword` 上下文一致（同一段落在各卡上登记的关键词相同）时才共享同一个技能；否则各自建立独立技能。
- 措辞不同但语义相近的保持独立，不修改既有卡面文本。
- 唯一需要拆分的共享文本是「战吼：使你的所有机械随从获得一次成长」：克劳德·香农把它登记为 `战吼`，无线电报在迁移前只登记 `装配 2`，两者不能共用同一个 `keyword` 值，因此拆成两个技能。
- 技能文本变化时，所有引用它的卡牌与英雄同步变化；这是共享引用的预期行为。
- 同一技能被多张卡引用时，各自结算，互不影响。

## 6. 校验

每次修改技能、卡牌或英雄文档后必须运行：

```bash
python3 scripts/validate_docs.py
```

技能相关校验覆盖：

1. 技能文档 118 份，`id` 等于文件名且在技能命名空间内唯一；
2. 技能属性表与 front matter 一致；
3. 被英雄引用的技能必须有 `name` 与 `match_text`；被效果牌引用的技能必须有 `match_text`；
4. 每张效果牌至少引用 1 个技能；7 张无效果随从的 `skills` 为空且 `## 效果` 为「无」；
5. 卡牌 `## 效果` 与所引用技能 `text` 按顺序拼接的结果一致；
6. 卡牌属性表的「技能」「关键词」行与 front matter、技能 `keyword` 一致；
7. 英雄的 `skill` 指向存在的技能。

期望：末行输出 `随从 176 张、效果牌 36 张、技能 118 个、英雄 13 位、成就 6 个，校验通过`，退出码 0；否则逐条打印违规并以退出码 1 结束。
