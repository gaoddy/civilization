# 卡牌规范与数据

> 依赖：[关键词与机制](../rules/keywords-and-mechanics.md)、[时代与场景](../rules/eras-and-scenarios.md)、[数值与经济](../systems/economy-and-numbers.md)
> 状态：方案未实施
> 数据：`docs/versions/v0.1/product/content/cards/`（212 份，文件名 = id）

本文描述卡牌字段规范、数值与关键词约束、数据总览与校验方式；不描述具体实现与后续版本卡池。归属版本产品基线的内容。

## 1. 字段规范

每张卡一个文档：`docs/versions/v0.1/product/content/cards/<id>.md`，文件名等于 `id`。文档由 YAML front matter 与正文组成；front matter 只使用 `key: 标量` 与 `skills: [技能 id, ...]` 两种形式。

卡牌分两类：**随从牌**（`card_type: 随从`）能站场，必须有初始攻击力与生命值；**效果牌**（`card_type: 效果`）不站场，不得有攻击力与生命值。

| 字段 | 类型 | 取值域 | 说明 |
| --- | --- | --- | --- |
| `id` | 字符串 | 语义 slug | **同一实体类型内唯一**：卡牌池（随从与效果共享）、英雄池、成就池各自独立查重，池之间允许同名；匹配 `^[a-z][a-z0-9-]*$`；必须等于文件名；中文名用拼音，外国人名与国际通用术语用英文；不含时代前缀，时代由 `era` 字段表达 |
| `card_type` | 枚举 | 随从 / 效果 | 随从站场，效果不站场 |
| `name` | 字符串 | 同一类型内唯一 | 卡名；优先使用素材原名。首版只做中文，多语言字段在实现期预留，不进入实体文档 |
| `tribe` | 枚举 | 人类 / 机械 / 生物 / 植物 / 病毒 / 学者；效果牌另可用「通用」 | 随从必须为 6 流派之一；效果牌可用「通用」表示不绑定流派，任何局都可出现 |
| `subtype` | 字符串 | 自由 | **仅随从**；学科或类别，供英雄技能引用 |
| `level` | 整数 | 1–7 | 星级，不是时代；7 星的数值区间与份数见[数值与经济](../systems/economy-and-numbers.md) |
| `era` | 枚举 | 史前 / 原始 / 古典 / 封建 / 工业 / 现代 / 未来 | **仅随从**；题材归属 |
| `attack` | 整数 | ≥0 | **仅随从，必填**；学者必须为 0 |
| `health` | 整数 | ≥1 | **仅随从，必填**；学者取同星级区间上浮 30% |
| `skills` | 列表 | 技能 id 列表 | **随从可省略**，省略等于不带技能；**效果牌必填且非空**；顺序即结算顺序；技能本体见[技能规范与数据](skill-system.md) |
| `is_scholar` | 布尔 | `true` / `false` | **仅随从**；与 `tribe=学者` 必须一致 |
| `source` | 枚举 | `素材` / `新增` | **仅随从**；标明是否沿用原始笔记的卡名 |
| `cost` | 整数 | 0–4 | **仅效果，必填**；购买费用，独立于星级 |
| `match_text` | 字符串 | 自由 | **仅效果，必填**；比赛模式下的确定性替换，与原效果相同写「同左」 |

**正文约定**：一级标题为卡名；`## 属性` 用表格复述 front matter 的字段，供直接阅读，并新增「技能」行列出所引用的技能 id；`## 效果` 由所引用技能按 `skills` 顺序渲染，无技能写「无」。属性表与 front matter 必须一致，由 §5 的校验脚本交叉核对。

**出处约定**：`source` 为 `新增` 的随从，正文必须附一句科学史或文明史来源说明，写清这张卡对应的人物、发现或事件；`source` 为 `素材` 的卡不强制，但同样不得杜撰史实。

**编码约定**：front matter 一行一个字段，列表元素用英文逗号分隔；正文只使用中文标点（，、；：）。

## 2. 数值与关键词约束

以下约束作用于随从牌；效果牌只校验星级与费用。

1. 攻击力与生命值必须落在 [数值与经济](../systems/economy-and-numbers.md)的星级区间内；
2. 学者的 `attack` 必须为 0，生命值取区间上浮 30%；
3. 关键词由所引用技能的 `keyword` 字段派生，只能来自 13 词表；其中**成长只出现在效果文本、不作为技能 `keyword` 登记**，技能 `keyword` 实际可登记 12 个常驻词；**通用 10 词**必须符合 [关键词与机制](../rules/keywords-and-mechanics.md) §7 的时代解锁关系（史前只有繁衍/战吼/亡语，原始才有成长/嘲讽，古典才出现连击/最优攻击/传染，封建才有复生，工业才有护盾，现代与未来不再新增），**流派专属 3 词不参与时代解锁**（03 §1.1）；`光环` 不是关键词，持续效果写在正文 `## 效果` 中；
   - 流派专属词必须与流派一致：`装配` 只能在机械卡、`播种` 只能在植物卡、`进化` 只能在生物卡；
4. 关键词折算后，`攻击力 + 生命值 + 折算` 不得超过同星级白板总和 + 4；
5. 同名卡只允许出现一次（三连靠份数，不靠重名）；该唯一性约束**按卡牌类型分别作用于随从池与效果牌池**，英雄技能使用独立命名空间；
6. 涉及敌方目标的文本必须显式写出选择器：随机、最左侧、最左侧及相邻、攻击力最高、全体；战吼中的敌方效果延迟到战斗开始时结算，见 [核心规则](../rules/core-rules.md) §4.4。

**统计口径**：成长按全部卡牌（随从与效果牌）的效果文本统计，不作为技能 `keyword` 登记；其余 12 词按所引用技能的 `keyword` 统计。

**分布约束**：三个流派专属词必须各有足够密度，否则玩家在同一局里抽不到自己的机制。首版下限为装配 ≥8、播种 ≥5、进化 ≥6；当前实际为 15 / 16 / 6。

**为什么"新增"占多数**：素材共 140+ 条，但可用于随从的名字在时代上极不均衡——现代之后极其密集（科学家、发明、病毒），史前/原始几乎没有人物名，未来社会完全空缺。为保证每个时代、每个星级都有足够卡量，史前 14 张、原始 19 张、未来 18 张，共 **51 张必须新增**；封建与现代则尽量沿用素材。在此之上，植物、病毒与人类在 4 星以后存在密度断层，又新增 16 张原创卡（植物 6、病毒 6、人类 4），合计 **67 张新增**。七时代扩展再补 **40 张新增**（古典 14、工业 14、7 星 12），最终为 **123 张新增**。这是**有意的取舍**，不是遗漏。

## 5. 校验规则与命令

每次修改卡牌或英雄文档后必须运行：

```bash
python3 scripts/validate_docs.py
```

校验覆盖：文档数量、`card_type` 合法、文件名与 `id` 一致、`id` 在卡牌池内唯一、`id` 格式、枚举字段合法、随从必有 `attack`/`health` 且效果牌不得有、学者攻击为 0 且与流派一致、随从时代/流派/星级分布、关键词白名单与流派专属词越界、光环分句句式、星级数值区间与超模上限、效果牌星级与费用、单体敌方目标是否写明选择器、英雄数量与费用、英雄技能次数与触发时机、**技能引用完整性与渲染一致性**（每张效果牌至少 1 个技能、技能 `id` 存在、`## 效果` 与所引用技能 `text` 按序拼接一致、派生关键词与技能 `keyword` 一致）、**每份文档的属性表与其 front matter 一致**。

期望：末行输出 `随从 176 张、效果牌 36 张、技能 118 个、英雄 13 位、成就 6 个，校验通过`，退出码 0；否则逐条打印违规并以退出码 1 结束。
