# 卡牌规范与数据

> 依赖：[关键词与机制](../rules/keywords-and-mechanics.md)、[时代与场景](../rules/eras-and-scenarios.md)、[数值与经济](../systems/economy-and-numbers.md)
> 状态：方案未实施
> 数据：`docs/versions/v0.1/product/content/cards/`（409 份，文件名 = id）

本文描述卡牌字段规范、数值与关键词约束、数据总览与校验方式；不描述具体实现与后续版本卡池。归属版本产品基线的内容。

## 1. 字段规范

每张卡一个文档：`docs/versions/v0.1/product/content/cards/<id>.md`，文件名等于 `id`。文档由 YAML front matter 与正文组成；front matter 只使用 `key: 标量`、`specialty: [kind:value, ...]` 与 `skills: [技能 id, ...]` 三种形式。枚举字段与关键词一律写英文 id，中文展示文本由文本表承载（见本节末「运行时文本来源」）。

卡牌分两类：**随从牌**（`card_type: minion`）能站场，必须有初始攻击力与生命值；**效果牌**（`card_type: effect`）不站场，不得有攻击力与生命值。

| 字段 | 类型 | 取值域 | 说明 |
| --- | --- | --- | --- |
| `id` | 字符串 | 语义 slug | **同一实体类型内唯一**：卡牌池（随从与效果共享）内查重，池之间允许同名；匹配 `^[a-z][a-z0-9-]*$`；必须等于文件名；中文名用拼音，外国人名与国际通用术语用英文；不含时代前缀，时代由 `era` 字段表达 |
| `card_type` | 枚举 | `minion` / `effect`（英雄卡另有 `hero`，见 §2.1） | 随从站场，效果不站场 |
| `name` | 字符串 | 同一类型内唯一 | 卡名；优先使用素材原名。front matter 是文本来源，运行时由文本表 `card.<id>.name` 承载 |
| `playstyle` | 枚举 | 13 个玩法 id 或 `neutral` | 必填；卡牌的玩法子叶。玩法 id 见 [分类树与玩法](taxonomy.md) §2；效果牌为 `neutral`（可用 `specialty` 关联 1 个玩法，见 §1.1），学者固定 `neutral`，非学者随从为 `neutral` 时必须是造物六类工具卡 |
| `taxon` | 字符串 | 分类树叶子 id | 必填；卡牌唯一的科学分类子叶。效果牌按题材取科学、人文、社会或造物下的学科/技术分类叶子；造物卡采用机械玩法时必须落在 `automation`；其余取值见 [分类树与玩法](taxonomy.md) §1 |
| `specialty` | 列表 | `play:<玩法 id>` / `prey:<分类节点 id>` / `host:<分类节点 id>` | 可省略；玩法关联、捕食分类与寄生分类。`play:` 只允许学者卡、中立非学者卡与效果牌（效果牌至多 1 条）；`prey:` / `host:` 只允许生物卡 |
| `subtype` | 字符串 | 小写英文 slug，匹配 `^[a-z][a-z0-9-]*$` | **仅随从**；学科或类别，不参与玩法与分类判定（如 `economics`、`animal`）；展示名由文本表 `enum.subtype.<subtype>` 提供 |
| `level` | 整数 | 1–7 | 星级，不是时代；7 星的数值区间与份数见[数值与经济](../systems/economy-and-numbers.md) |
| `era` | 枚举 | `prehistoric` / `primitive` / `classical` / `feudal` / `industrial` / `modern` / `future` | **随从与效果牌都必填**；题材归属 |
| `attack` | 整数 | ≥0 | **仅随从，必填**；学者必须为 0 |
| `health` | 整数 | ≥1 | **仅随从，必填**；学者取同星级区间上浮 30% |
| `skills` | 列表 | 技能 id 列表 | **随从可省略**，省略等于不带技能（全池只允许 1 张中立工具卡无技能）；**效果牌必填且非空**；顺序即结算顺序；随从的技能数量上限：1–2 星 1 个、3–4 星 2 个、5–7 星 3 个且其中登记关键词不超过 2 个；技能本体见[技能规范与数据](skill-system.md) |
| `is_scholar` | 布尔 | `true` / `false` | **仅随从**；是否为学者。学者必须 `playstyle: neutral`、`attack: 0` |
| `cost` | 整数 | 0–4 | **仅效果，必填**；购买费用，独立于星级 |
| `match_text` | 字符串 | 自由 | **仅效果，必填**；确定性替换文本，随机效果在固定种子对局中的替换版本（v0.1 不消费），与原效果相同写「同左」；运行时由文本表 `card.<id>.match_text` 承载 |

**运行时文本来源**：front matter 的 `name` 与 `match_text` 是文本的编辑来源，构建期由 `scripts/gen_text.py` 汇总到 `client/text/zh_CN.csv`（卡名 key 为 `card.<id>.name`，替换文本 key 为 `card.<id>.match_text`）。客户端通过 Godot 翻译接口按 id 取文本，服务端生成数据不含展示文本；新增语言需要扩展文本生成工具并补充各语言文本、注册对应翻译，业务代码与实体文档结构不改动。技能文本与效果文本同样由文本表承载，见[技能规范与数据](skill-system.md) §2。

**正文约定**：一级标题为卡名；`## 属性` 用表格复述 front matter 的字段，供直接阅读，并新增「技能」行列出所引用的技能 id；随从属性表另含「玩法」（玩法子叶展示名，如「哺乳纲」「中立」）、「科学分类」（完整路径，如「动物界 › 脊索动物门 › 哺乳纲 › 灵长目 › 人科」）、「关联分类」（如「擅长：哺乳纲」「关联：机械」「捕食：偶蹄目」「寄生：细菌域」，多项用「、」分隔）与「子类」行；效果牌属性表含「玩法」（恒为「中立」）与「科学分类」（完整路径，如「科学 › 生物学」「社会 › 军事学」）。随从与效果牌的属性表不再含「英雄资格」行，英雄卡见 §2.1。`## 效果` 由所引用技能按 `skills` 顺序渲染（技能文案取自实例模板渲染结果或其 `text` 覆盖），无技能写「无」；卡牌在 `## 效果` 之后写 `## 设计说明` 与 `## 出处`。属性表与 front matter 必须一致，由 §5 的校验脚本交叉核对。

**出处约定**：每张卡牌正文在「## 效果」之后必须写一段「## 出处」，用一句可查证的话说明卡名或效果对应的史实、科学发现、文化概念或文学来源，不附链接，不得杜撰。出处不进入属性表。该要求由 §5 校验脚本覆盖。

**编码约定**：front matter 一行一个字段，列表元素用英文逗号分隔；正文只使用中文标点（，、；：）。

### 1.1 玩法、科学分类与关联分类的约束

1. **玩法子叶**：每张卡恰好一个，取 13 个玩法之一或 `neutral`。学者固定 `neutral`；非学者卡为 `neutral` 时只能落在造物六类工具分类（动力与能源、交通与运载、武器与攻城、生产与建筑、信息与计算、生活与医疗）；效果牌固定 `neutral`。
2. **科学分类子叶**：每张卡恰好一个，取分类树叶子。生物按真实物种建到科；造物采用机械玩法时 `taxon` 必须落在 `automation`；效果牌按题材归入科学、人文、社会下的学科叶子或造物技术分类。
3. **玩法与科学分类相互独立**：一张卡可以是「人科」的科学分类、而玩法为「机械」或「植物界」；人类卡不单独成为玩法或筛选维度。
4. **关联分类**：`play:` 只允许学者卡（擅长玩法）、中立非学者卡（关联玩法）与效果牌（定向玩法），取值必须是 13 个玩法之一，不含 `neutral`；效果牌至多 1 条 `play:`，且只在对应玩法启用的对局中进入商店；`prey:` / `host:` 只允许生物卡，取分类树的任一节点，按祖先关系匹配，写上级节点即覆盖其下级；效果牌不得有 `prey:` / `host:`。

## 2. 数值与关键词约束

以下约束中，攻击力、生命值与关键词相关部分作用于随从牌；效果牌校验星级、费用、技能与时代，时代与随从牌同口径（必填且属于七个时代之一）。

1. 攻击力与生命值必须落在 [数值与经济](../systems/economy-and-numbers.md)的星级区间内；
2. 学者的 `attack` 必须为 0，生命值取区间上浮 30%；
3. 关键词由所引用技能的 `keyword` 字段派生，只能来自[关键词与机制](../rules/keywords-and-mechanics.md) §1 的判定表（技能 `keyword` 写英文 id，如 `battlecry`、`breed 1`，转写规则见同节）；其中**成长只出现在效果文本、不作为技能 `keyword` 登记**，技能 `keyword` 实际可登记 16 个常驻词；**通用 12 词**（繁衍、战吼、亡语、复生、嘲讽、护盾、连击、传染、无视嘲讽、剧毒、减伤、潜行）必须符合 [关键词与机制](../rules/keywords-and-mechanics.md) §7 的时代解锁关系（史前只有繁衍/战吼/亡语，原始才有成长/嘲讽，古典才出现连击/无视嘲讽/传染，封建才有复生，工业才有护盾，现代与未来不再新增），其中剧毒/减伤/潜行不按时代解锁，最小星级按卡池实际（剧毒 3、减伤 2、潜行 3），玩法归属为剧毒爬行纲/头足纲/水螅纲、减伤爬行纲/细菌域/水螅纲、潜行仅头足纲；**专属 4 词不参与时代解锁**；`光环` 不是关键词，持续效果写在正文 `## 效果` 中；
   - 专属词必须与玩法或分类一致：`分解` 只能在真菌界或细菌域玩法的卡、`装配` 只能在机械玩法或带 `play:machine` 的中立工具卡、`播种` 只能在植物界玩法、`进化` 只能在非学者生物卡；
4. 关键词折算后，`攻击力 + 生命值 + 折算` 不得超过同星级白板总和 + 4；
5. 同名卡只允许出现一次（三连靠份数，不靠重名）；该唯一性约束**按卡牌类型分别作用于随从池、效果牌池与英雄池**：随从池与效果牌池各自唯一，英雄池内 id 与名称唯一；英雄卡与同名随从卡分属两个池，允许 id 与名称相同；
6. 涉及敌方目标的文本必须显式写出选择器：随机、最左侧、最左侧及相邻、攻击力最高、全体；战吼中的敌方效果延迟到战斗开始时结算，见 [核心规则](../rules/core-rules.md) §4.4。

### 2.1 英雄卡

英雄是独立卡牌实体，位于 `content/heroes/`，`card_type: hero`，只用于开局选英雄；**不进商店、不进牌池、不参与三连与发现，不可购买**。英雄卡只保留身份与技能字段（`id`、`name`、`card_type`、`playstyle`、`specialty`、`skills`），不含星级、攻击、生命、时代、科学分类与费用。每张英雄卡都与 `content/cards/` 中一张随从卡**同 id、同名**，两卡分属英雄池与随从池；引擎按用途查对应池，英雄查询只走英雄池。

英雄候选池按本局启用的 5 个玩法过滤：英雄的 `playstyle` 在本局玩法内时入选；中立英雄至少有一个 `play:` 关联玩法命中才入选，纯通用中立英雄始终入选；未启用玩法的英雄不出现在任何玩家的候选中。开局时，服务端为每位玩家分配 4 张候选英雄卡，玩家从自己的候选中选 1 张作为英雄；候选在同一房间内优先互不重复，候选池不足时允许跨玩家重复并按池大小缩减每人候选数，候选池为空时回退到全部英雄卡抽取。候选在开局确定，重进房间（含断线重连）不重新分配，本局玩法与候选都不重新抽取。

- 选择英雄不消耗牌池份数、不进入手牌或战场；同名随从卡仍作为普通随从留在卡池中，可被任何玩家购买，数值与技能不变。
- 英雄身份授予英雄卡的全部 `skills`；买到的同名随从卡按普通随从结算，同样获得该随从卡的全部 `skills`。两张卡的玩法与关联保持一致，`skills` 各自维护、不要求相同，但分别从各自的池读取。
- 英雄技能只能为主动或被动技能：英雄不进入战场，技能不得登记战吼、护盾、亡语等随从战场关键词。一个英雄可以有多个主动技能，按英雄卡 `skills` 顺序展示与结算。
- 主动技能由玩家支付技能实体的 `cost` 后使用，每回合至多 `uses_per_turn` 次；被动技能按技能对象文本的触发前缀自动结算，宿主为玩家本人。
- 多人局允许重复选择同一张英雄卡；英雄身份互不影响。
- 英雄池恰好 32 张；随从池与效果牌不得再有 `is_hero` 字段，英雄卡不得出现「英雄资格」属性行或旧版英雄技能字段与 `## 英雄技能` 小节。

**统计口径**：成长按全部卡牌（随从与效果牌）的效果文本统计（当前 113 张），不作为技能 `keyword` 登记；其余常驻词按所引用技能的 `keyword` 统计。

**分布约束**：专属词必须各有足够密度，否则玩家在同一局里抽不到自己的机制。下限为装配 ≥8、播种 ≥5、进化 ≥6；当前实际为 19 / 16 / 6。2026-11-19 修正表外第二技能时进化曾降到 3 张，随后按「补回进化密度」把复活猛犸、合成细胞、基因改造人的「复生」换回「进化」，恢复为 6 张；复生随之由 7 张降到 4 张。分解已随真菌界与细菌域卡牌落地（当前 9 张），密度下限按同口径 ≥5 设置。

**为什么"新增"占多数**（本段为 v0.1 初版卡池的历史取舍，数字不随玩法扩充更新）：素材共 140+ 条，但可用于随从的名字在时代上极不均衡——现代之后极其密集（科学家、发明、病毒），史前/原始几乎没有人物名，未来社会完全空缺。为保证每个时代、每个星级都有足够卡量，史前 14 张、原始 19 张、未来 18 张，共 **51 张必须新增**；封建与现代则尽量沿用素材。在此之上，植物、病毒与人类在 4 星以后存在密度断层，又新增 16 张原创卡（植物 6、病毒 6、人类 4），合计 **67 张新增**。七时代扩展再补 **40 张新增**（古典 14、工业 14、7 星 12），最终为 **123 张新增**；另有 8 张英雄卡新增；英雄候选改版再补 19 张英雄卡，合计 **150 张新增**（53 张保留 + 150 张新增 = 203 张随从）。这是**有意的取舍**，不是遗漏。

## 5. 校验规则与命令

每次修改卡牌文档后必须运行：

```bash
python3 scripts/validate_docs.py
```

校验覆盖：

- **文档与字段**：文档数量、`card_type` 合法、文件名与 `id` 一致、`id` 在卡牌池内唯一、`id` 格式、枚举字段合法、随从必有 `attack`/`health` 且效果牌不得有、`is_scholar` 与学者攻击力约束、学者生命值偏离「同星级生命上限 ×1.3」不超过 1 点；旧分类字段残留视为错误。
- **科学分类树**：节点 `id` 唯一、父节点存在、无环、层级合法；生物叶子为「科」、造物叶子为「技术分类」、科学/人文/社会叶子为「学科」；每张卡的 `taxon` 必须是叶子，`prey:` / `host:` 指向的节点必须存在。
- **玩法与关联分类**：`playstyle` 取 13 个玩法或 `neutral`；学者固定 `neutral`；非学者为 `neutral` 时仅限造物六类工具卡；造物卡采用机械玩法时 `taxon` 必须为 `automation`；效果牌必须 `neutral` 且 `taxon` 为分类树叶子，`specialty` 至多 1 条 `play:`；`play:` 只允许学者、中立非学者与效果牌，`prey:` / `host:` 只允许生物卡。
- **技能数量**：1–2 星随从最多 1 个技能，3–4 星最多 2 个，5–7 星最多 3 个且登记关键词不超过 2 个；无技能随从全池恰好 1 张，且必须是中立非学者工具卡。
- **关键词**：16 个常驻词的白名单；`分解` 仅真菌界/细菌域玩法；`装配` 仅机械玩法或带 `play:machine` 的中立工具卡；`播种` 仅植物界玩法；`进化` 仅非学者生物卡；`剧毒` 仅爬行纲/头足纲/水螅纲、`减伤` 仅爬行纲/细菌域/水螅纲、`潜行` 仅头足纲；通用词的最小星级必须与时代解锁表一致（剧毒/减伤/潜行按卡池实际最小星级）；光环分句句式合法。
- **DSL**：筛选键为 `taxon` / `playstyle` / `play` / `prey` / `host` / `subtype` / `id` / `type` / `scholar` / `keyword` / `other`；`timesIf` 使用「键:值:次数」格式；`Decompose` 的 `basis` 与 `duration` 必填且取值合法；`OnKill` / `OnAllyKill` 在触发白名单内；「分解：」前缀只允许三种击杀/死亡触发。
- **其余**：卡牌时代分布、随从星级分布、星级数值区间与超模上限（战吼/亡语的召唤、复制类按 4 点折算，其余按 2 点）、效果牌星级、费用与时代、单体敌方目标是否写明选择器、英雄卡恰好 32 张、随从与效果牌不得再有 `is_hero`、无已废弃的英雄技能字段或小节残留、**技能引用完整性与渲染一致性**、**每份文档的属性表与其 front matter 一致**（含「玩法」「科学分类」「关联分类」行）、**每张卡牌必须有非空「## 出处」**。

期望：输出包含 `随从 309 张、效果牌 100 张、技能 254 个、英雄卡 32 张，校验通过`，其前打印时代、玩法、星级、关键词与技能引用统计，其后打印 `分类树节点 338 个、玩法 13 个，校验通过` 与 `v0.2 成就 6 个，校验通过`；退出码 0。否则逐条打印违规并以退出码 1 结束。
