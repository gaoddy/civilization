# 对局结束即销毁房间（产品）

> 状态：已确认（2026-11-19）
> 适用版本：v0.1
> 依据：[房间与邀请](../../product/systems/rooms-and-invites.md)

## 1. 定位与用户

一局结束后不再保留房间。结算页只负责展示本局结果，玩家看完点「确定」回大厅；原房间与房间码在对局结束时失效。要再玩需要重新创建房间或加入别人的房间。

## 2. 功能规则

1. 对局结束（服务端下发 `GameOver`）时立即销毁房间：所有成员同时离座，房间与房间码失效，不保留等待区，也不重置给下一局使用。
2. 结算页继续展示本局名次、本人统计与阵容；数据来自本局下发内容，不依赖房间继续存在。
3. 点「确定」只做客户端导航：清空本地对局与房间状态并回到大厅，不再向服务端发送离开房间请求。
4. 房间销毁后，原房间码不可再加入；要再玩需创建新房间、凭新房间码加入或接受邀请。
5. 玩家在结算页断线后重连：直接回大厅，不补发上一局结果，也不恢复房间。
6. 房间内的准备、开局、房主移除成员、解散、对局中退出等规则不变；这些只发生在对局结束之前。

## 3. 页面与交互

- 结算页结构与按钮不变：只保留「确定」。
- 点「确定」后立即导航大厅，无二次确认。
- 房间在结算期间不会再有状态变化（已销毁），结算页不显示房间相关提示。

## 4. 状态与边界

| 状态 | 表现 |
| --- | --- |
| 对局结束 | 房间立即销毁，旧房间码失效；所有成员进入各自结算页 |
| 结算页停留 | 结果保持不变，不自动跳转 |
| 点「确定」 | 回大厅；本地房间状态清空 |
| 结算页断线重连 | 回大厅，不补发结果 |
| 房间在结算前被解散 | 按现有解散规则处理，不进入对局 |

## 5. 明确不做

- 不再保留房间等待区，也不再支持「赛后回房再开一局」。
- 不做房间复用、空房间池、创建房间时分配旧房间。
- 不做结算页自动返回大厅。
- 不改动对局内的退出与弃权规则。

## 6. 验收标准

1. 对局结束收到 `GameOver` 后，该房间从服务端消失，原房间码加入返回房间不存在/不在房间。
2. 所有座位在结算页展示期间都已不属于原房间；结算页不依赖服务端再次查询。
3. 点「确定」回到大厅，客户端不再发送离开房间请求，也不出现错误提示。
4. 结算页断线重连后到达大厅，看不到上一局结果。
5. 对局开始前的房主移除、解散与房主转移行为与现在一致。
