# 战斗行动轮次循环 · 技术方案

> 状态：方案未实施
> 产品规则：[product.md](product.md)

## 1. 改动边界

| 端 | 范围 |
| --- | --- |
| 规则引擎 | `SideBoard` 指针改为环形轮次；连击在同一拍连续结算；复生不再重置行动次数；学者连击生效 |
| 测试 | 调整连击、学者连击与行动上限用例；新增轮次循环、人数不等、召唤/复生位置用例 |
| 协议 | 不变：`CombatAction` 的 `attack` / `death` / `reborn` / `summon` 结构不变 |
| 房间服务 | 不变：按 `actions` 下发与播放 |
| 客户端 | 不变：按动作序列逐条播放，连击只是两条 `attack` 动作 |

不涉及：目标选择（嘲讽、最优攻击、随机）、伤害与护盾结算、传染、召唤/复生触发条件、行动上限数值、战报结构。

## 2. 规则引擎实现

### 2.1 每侧状态与轮次

`SideBoard` 的 `pointer` 从「单向走完即结束」改为「环形轮次」：

- `attacks_left` 表示**本轮剩余行动次数**：普通 1、连击 2、不能攻击 0。
- `find_attacker` 每次调用时先检查边界：`pointer >= minions.len()` 时执行 `reset_round()`：
  - `pointer = 0`；
  - 对所有存活随从执行 `attacks_left = starting_tokens[i]`。
- 然后从 `pointer` 向右扫描，返回第一个 `alive && health.current > 0 && attacks_left > 0` 的下标；跳过的随从随指针前进。
- 扫描到末尾返回 `None`；该侧下一次轮到时才再次重置并扫描，从而满足「最后一个出手后，该侧下一拍从最左开始」。
- 一侧全部随从都不能攻击时，每拍重置后仍返回 `None`，主循环切换到另一侧；不会死循环。

### 2.2 连击

- `resolve_attack` 保持「一次攻击」的职责，行动次数递减仍在其末尾完成。
- 主循环取到攻击者后记录 `attacker_id`，按本拍开始时的 `attacks_left` 连续调用 `resolve_attack`：
  - 每次调用前检查攻击者仍存活、双方仍有存活随从；攻击者阵亡或战斗结束则停止；
  - 攻击者被复生复活后视为存活，继续执行剩余次数；
  - 每次调用 `action_count += 1`，仍受 `MAX_ACTIONS = 200` 限制。
- 两次攻击之间不插入对方出手，目标由 `pick_target` 各自独立选择。
- `starting_tokens` 去掉学者特判：不能攻击返回 0；连击返回 2；其余返回 1。学者攻击力仍由 `effective_attack_with` 强制为 0，两次攻击都造成 0 伤害。

### 2.3 指针推进

- 攻击者行动完毕（含连击全部次数）后不手动移动 `pointer`；下一次该侧 `find_attacker` 从当前 `pointer` 扫描，`attacks_left == 0` 的攻击者被跳过，指针自然右移。
- `insert_at` 中 `position <= pointer` 时 `pointer += 1` 的逻辑保留：插入到本轮已行动区域的随从不会在本轮被轮到。
- `append` 不调整 `pointer`：追加到末尾的随从位于指针当前位置或前方，本轮会轮到。
- 轮次重置只重置该侧，不影响另一侧；两侧轮次各自独立。

### 2.4 复生

- `resolve_deaths` 的复生分支移除 `attacks_left = starting_tokens` 的重置，保留死亡时的值：
  - 本轮未行动的随从复生后保留 `attacks_left > 0`，位置在指针前方时本轮会轮到；
  - 本轮已行动的随从复生后保留 `attacks_left == 0`，本轮不再行动，避免同一随从一轮内二次行动。
- 该侧进入下一轮时，`reset_round` 统一恢复所有存活随从的行动次数。

### 2.5 召唤

- `append` / `insert_at` 继续用 `starting_tokens` 初始化新随从的 `attacks_left`，新随从视为本轮未行动。
- 本轮是否轮到由插入位置与 `pointer` 的关系自然决定，不需要额外标记。

### 2.6 不变量

- `attacks_left` 仍是战斗局部字段；`write_back_persistent` 只回写传染与成长，持久棋盘与 `state_hash` 的既有语义不受影响。
- 连击的两次攻击各计 1 次行动，`MAX_ACTIONS = 200` 与胜负判据不变。
- `MAX_TRIGGERS`、召唤上限与随机流 `Stream::Combat` 的消费顺序保持现状；连击两次攻击会按现有顺序各消耗一次目标随机。

## 3. 测试

调整：

- `windfury_attacks_twice`：断言连击随从连续两次出手后该侧才轮到下一个随从，并覆盖该侧第二轮回到最左。
- `scholar_granted_windfury_still_attacks_once`：改为学者带连击时攻击 2 次。
- 行动上限用例（`combat.rs` 的 100 个连击随从、`settle.rs` 的 200 令牌场景）：按新轮次重新校准预期，确认 200 次行动上限仍触发、判据不变。

新增：

- 双方等量低攻高血：断言出手序列为先 1 → 后 1 → 先 2 → 后 2 → 先 1 → 后 1 …。
- 人数不等（先手 1 个、后手 3 个）：断言先手随从每拍出场，后手按 1 → 2 → 3 → 1 循环，两侧轮次不同步。
- 连击第一次击杀目标：断言第二次重新选目标并记录第二条攻击动作。
- 连击攻击者第一次后被反击致死且无复生：断言不记录第二次攻击。
- 战斗中召唤插入已行动区域 / 待行动区域：断言本轮是否行动。
- 复生随从本轮已行动 / 未行动：断言本轮是否再次行动。
- 一侧全部不能攻击：断言该侧跳过、另一方连续出手，且行动上限仍生效。

## 5. 已知限制

- 战斗阶段的服务端兜底截止仍是下一回合招募截止（75–120 秒）。新规则下战斗可跑满 200 次行动，低攻高血且每拍都有反击的极端战斗约 400–1000 条动作，客户端演示（动作数 × 320ms + 2s）可能超过兜底而被提前结算截断。是否按动作数延长阶段截止待定，已记录在 [v0.1 待确认事项](../../open-questions.md)。
