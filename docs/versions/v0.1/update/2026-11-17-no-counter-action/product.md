# 战斗演示不播放反击

> 状态：已确认
> 相对版本基线的增量：战斗演示只为主动攻击产生动作，反击不再单独播放，也不单独占用演示节拍。

## 1. 范围

- 包含：战斗中一次攻防交换在客户端演示里的动作数、反击伤害的呈现方式、反击致死的呈现方式。
- 不包含：反击的结算规则（何时反击、伤害量、护盾与 `OnDealDamage` 的触发顺序）、主动攻击的演示表现、横幅与结算流程。

## 2. 规则

- 一次攻击交换只产生一条演示动作，即主动攻击。
- 反击照常结算：伤害、护盾消耗、`OnDealDamage` 触发与死亡判定都不变；反击造成的攻击方掉血写进同一条主动攻击动作的状态快照。
- 客户端不为反击播放飞卡、命中闪光或伤害飘字，反击也不额外占用一个动作节拍。
- 攻击方因反击掉血或阵亡时，血量在同一条主动攻击动作应用时静默更新；阵亡仍由随后的阵亡动作淡出。
- 演示总时长按实际下发的动作数计算，动作数减少后总时长相应缩短。

## 3. 界面与状态

| 状态 | 表现 |
| --- | --- |
| 攻击交换未致死 | 攻方卡飞向目标，目标闪光并飘出主伤害数字；攻方被反击扣掉的血量静默更新，没有飘字 |
| 反击击杀攻击方 | 同一次攻方飞行结束后，攻方卡片按阵亡动作淡出 |
| 目标被主伤害击杀 | 目标不再反击，只有主动攻击一条动作 |
| 护盾挡下反击 | 攻击方血量不变，也没有额外演出 |

## 4. 影响

- 战斗演示比旧版本短：反击不再各占一拍，动作数与演示时长都会减少。
- 历史战斗的动作数与当前代码不再逐条一致；需要对比时以重新生成的产物为准。
- 战斗结算结果不变，双方最终血量与胜负判定与旧版本一致。
