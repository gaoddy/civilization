# 战斗棋盘容量与阵亡展示

> 状态：已确认
> 相对版本基线的增量：明确战斗期的棋盘容量与阵亡展示；补充「先死亡、再召唤、后复生」的进场顺序。

## 1. 范围

- 包含：战斗期棋盘容量的计数口径、阵亡随从在战斗行中的展示、召唤/播种/复制/复生在满场时的处理、召唤位置的下标口径。
- 不包含：招募阶段的棋盘规则（见[核心规则](../../product/rules/core-rules.md) §4.2）、战斗结算算法本身（见 §5）、出牌落点与战报展示的缺陷修正（不改变规则，随本任务一并修复）。

## 2. 规则

- 战场的 7 个随从位在**战斗期同样生效**，按**存活随从数**计数。
- 阵亡随从**立即离开战斗展示行**，不再以变暗卡片保留。
- 战斗中任何把随从放进棋盘的行为（召唤、播种、复制到棋盘、复生）都要求进场前存活随从数小于 7；已满时本次进场作废。
- 同一次死亡结算内的顺序固定为：**死亡 → 召唤 → 复生**。死亡先空出位置，召唤占用剩余位置，复生最后进行；复生时若已无空位，该随从保持阵亡。
- 召唤的插入位置以**存活随从序列的下标**表示（0–6，不考虑已阵亡的随从）；复生后的随从回到它阵亡前的相对位置。
- 战斗行只显示存活随从；攻击、受击、传染与召唤的攻防都显示服务端下发的值。

## 3. 界面与状态

| 状态 | 表现 |
| --- | --- |
| 随从阵亡 | 该卡片从战斗行消失，不保留变暗占位 |
| 随从复生 | 卡片在原相对位置重新出现，攻防为复生后的下发值 |
| 召唤 | 新卡片按服务端给出的存活序列下标插入 |
| 存活已满时召唤/复生 | 不出现新卡片，也不改变现有阵容 |

## 4. 影响

- 满场时亡语召唤、播种与复生可能落空，战斗结果与旧版本可能不同。
- 历史战斗回放的数值不再与当前代码逐位可比；需要对比时以重新生成的产物为准。
