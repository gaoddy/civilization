# 冻结跨回合保留，解冻只在当回合（产品）

> 状态：已确认（2026-11-20）
> 适用版本：v0.1
> 相对版本基线的增量：冻结的卡牌不解冻就一直保留；「解冻」只在冻结的当回合可用，进入下一回合按钮回到「冻结」；手动刷新换上新卡牌后不再带冻结状态。

## 1. 定位与用户

面向对局招募阶段的全部玩家。当前冻结标记会一直保留，按钮却按「商店里还有没有冻结槽位」显示「解冻」，于是新回合一开始按钮就是「解冻」：玩家以为要再按一次冻结，实际按下去把跨回合保留的商店解了冻，下一回合整店重抽，看起来像「冻结的牌下回合丢了」。

本次明确两件事：

1. 冻结状态跨回合保留，只由解冻或刷新清除；
2. 解冻只是冻结当回合的撤销操作，不跨回合继承。

## 2. 范围

### 包含

- 冻结的卡牌与实例编号在后续每回合招募开始时原位保留，被买空的槽位补新牌。
- 冻结标记随卡牌保留：新回合商店卡照常显示冻结蒙层与「冻」字。
- 解冻按钮态按「本回合是否冻结过且仍有冻结槽位」判定：冻结当回合显示「解冻」，新回合重新显示「冻结」。
- 新回合直接提交解冻视为非法操作。
- 新回合重新按「冻结」后，本回合内重新取得解冻权；解冻为幂等操作，空槽跳过。
- 手动刷新、升时代重抽产生的新卡牌不带冻结状态。

### 不包含

- 不改变冻结、解冻的意图种类与字段。
- 不改变手动刷新、升时代清除冻结的既有规则。
- 不新增「保留自冻结」标记、提示或新的视觉样式。

## 3. 功能规则

1. 招募阶段按冻结按钮冻结全部非空槽位；按钮高亮，tooltip 为「解冻」。
2. 冻结的当回合内，再按一次解冻全部已冻结槽位；未冻结槽位不变，不重抽、不消耗金币。
3. 进入下一回合招募阶段：上一回合冻结的非空槽位沿用原实例与卡牌原位保留，冻结蒙层与「冻」字保留；被买空的槽位补新牌。
4. 新回合冻结按钮回到「冻结」，按钮不高亮：解冻权不跨回合。此时直接解冻会被服务端拒绝。
5. 新回合再次按「冻结」后，本回合内重新取得解冻权；再次按下即解冻全部已冻结槽位。
6. 手动刷新或升时代都换成一整组新卡牌，新卡牌没有冻结状态；被买空而未冻结的槽位同样不保留。
7. 已结束招募、非招募阶段、断线与目标待选等阻塞状态下，冻结与解冻按钮保持禁用且不发送意图。

## 4. 页面与交互

- 冻结按钮（雪花图标）的位置、尺寸与可用性门控不变。
- 冻结蒙层、冰晶与「冻」字的视觉不变，跨回合保留的卡牌继续显示。
- 冻结按钮的激活态与 tooltip 跟随本回合的解冻权，而不是商店里是否存在冻结卡；新回合按钮不高亮、tooltip 为「冻结」。
- 冻结与解冻都只对非空槽位生效；空槽位跳过。

## 5. 状态与边界

| 状态 | 表现 |
| --- | --- |
| 上回合冻结、本回合开始 | 冻结牌原位保留并继续显示冻结蒙层；空槽补新牌；按钮为「冻结」 |
| 冻结当回合 | 按钮高亮为「解冻」，按一次解冻全部已冻结槽位 |
| 新回合未重新冻结 | 冻结规则继续生效；直接解冻被拒绝 |
| 新回合重新冻结后 | 本回合内可解冻，规则同冻结当回合 |
| 解冻后 | 卡牌保留到本回合结束，之后按正常规则随商店重抽 |
| 手动刷新 / 升时代 | 换新卡牌，冻结与解冻权同时清除 |
| 已结束招募 / 非招募阶段 / 断线 / 目标待选 | 冻结与解冻按钮禁用且不发送意图 |

## 6. 明确不做

- 不新增「保留自冻结」标记或提示。
- 不改变冻结与解冻的可用性门控。
- 不做滑动、长按或二次确认来单独解冻某个槽位。

## 7. 验收标准

1. 冻结后进入下一回合：冻结牌原位保留、实例编号不变，蒙层与「冻」字仍在，被买空的槽位补新牌。
2. 新回合按钮为「冻结」且不高亮；直接解冻返回错误，冻结状态不变。
3. 新回合按「冻结」后按钮变为「解冻」，本回合内解冻成功，卡牌保留到本回合结束、再下一回合重抽。
4. 不解冻连续过两个回合：冻结牌仍在原位；手动刷新后换新卡且无冻结状态。
5. 已结束招募、战斗阶段、断线和目标待选期间按钮禁用且不发送冻结或解冻意图。
