# 移除学者机制与确定性替换文本产品增量

> 状态：已确认
> 需求归属：v0.1
> 类型：数据模型与规则精简（改变部分卡牌的成长行为，取消 v0.2 比赛模式）

## 1. 移除 `is_scholar`

- 卡牌不再有「学者」身份：front matter 删除 `is_scholar` 字段，卡牌属性表删除「学者」行。
- 攻击力为 0 只是普通卡面数值，不再触发任何特殊战斗规则：
  - 攻击力按卡面与加成正常计算，不再恒为 0；
  - 成长、繁衍、装配等属性成长对攻击力为 0 的随从按普通随从结算，攻击力与生命值各 +1；
  - 攻击力为 0 的随从可以正常获得攻击力加成并造成伤害。
- 现有 49 张原学者卡保留 `attack: 0` 与现有生命值，卡面数值不变；生命值校验改为按「攻击力为 0 的随从取同星级生命上限 ×1.3」执行，不引入新字段。
- 「进化」关键词的承载范围由「非学者生物卡」改为「生物卡」；原学者卡现在可以携带进化。
- 无技能随从仍恰好 1 张，且必须是造物工具卡。
- 技能 DSL 删除 `scholar` 筛选键与 `timesIf=scholar:<次数>` 语法。
- 删除 4 个学者定向技能与 3 个学者定向模板，相关卡牌改配通用技能：
  - 孔子：`aura-other-plus-0-plus-2`，你的其他随从获得 +0/+2；
  - 卡尔·萨根：`aura-other-plus-0-plus-3`，你的其他随从获得 +0/+3；
  - 高斯（随从卡与英雄卡）：`activate-friendly-growth-twice`，使一个友方随从获得两次成长，1 费、每回合 1 次；
  - 炼金术士：`battlecry-friendly-growth-once`，战吼：使一个友方随从获得一次成长。
- 新增的 3 个通用技能不改变卡牌星级、身材与费用。

## 2. 移除 `match_text`

- 卡牌与技能 front matter 删除 `match_text` 字段；卡牌与技能属性表删除「确定性替换」行。
- 文本表删除 `card.<id>.match_text` 与 `skill.<id>.match_text`；生成、校验与渲染链路同步删除。
- 不再要求效果牌、被效果牌引用的技能、主动技能填写确定性替换文本。
- 随机效果在 v0.1 继续由规则引擎的固定随机流处理，不提供替换文案。

## 3. 取消 v0.2 比赛模式

- 删除 v0.2 比赛模式整节及其产品规则、验收标准与索引条目。
- v0.2 其他内容（移动端适配、成就、自动匹配与天梯等）保留；涉及比赛模式的引用一并删除。
- v0.1 卡牌与英雄设计说明中「比赛模式下改为……」的口径删除，不再承诺替换行为。
- 路线图中不再保留比赛模式这一版本目标。

## 4. 不变

- 卡牌总数、时代/星级/玩法分布、效果牌费用、技能与卡牌的其余数值不变。
- 协议 schema、数据库、room-service 接口与对局流程不变。
- 英雄卡数量仍为 32；英雄结构与技能规则除本需求列出的技能改配外不变。
- 随机效果仍走确定性随机流；固定种子重放能力不变。

## 5. 验收

1. `make data-check` 通过，输出不含学者统计，且没有 `match_text` / 「确定性替换」残留。
2. `make test` 与 `make lint` 通过；与原学者相关的断言改为「攻击力按普通随从结算」。
3. 原 49 张攻击力 0 的随从可以正常获得攻击力，成长同时增加攻击力与生命值。
4. 4 个学者定向技能、3 个学者定向模板及其文本 key 不再存在；相关卡牌引用新通用技能并通过校验。
5. `docs/versions/v0.2/product/systems/competitive-mode.md` 删除，仓库内没有指向它的链接或「比赛模式」计划条目。
6. 固定种子模拟基线按仓库流程重定，并在测试注释记录原因。
