# 技能实体化

## 1. 问题

现行基线只在英雄上建模「技能」：英雄用 `skill_name / skill_cost / skill_type / skill_uses_per_turn / skill_trigger / skill_text / match_text` 七个字段描述一个技能；卡牌的效果只是 `## 效果` 里的一段文本，没有身份。

由此产生三个问题：

1. 相同效果在多张卡上重复写文本。168 张卡共 190 段效果文本，去重后只有 104 段；「播种：死亡时召唤一个 1/1 的幼苗」被 14 张卡共用，改一处要改 14 份。
2. 卡牌效果与英雄技能是两套写法，同一种效果无法互相引用。
3. `keywords` 字段事实上是「第一代共享机制」，但它只能表达 12 个常驻关键词，无法表达战吼、亡语、光环与条件触发。

## 2. 定义

- **技能**：一段可独立结算的效果。技能有独立 `id` 与规范文本，可被任意卡牌或英雄引用，也可被多张同时引用。
- **效果牌**：本质上是一张一定带有技能的卡牌，必须携带至少 1 个技能；技能数量不设上限。
- **随从牌**：可携带 0–N 个技能，也可以不携带。
- **英雄**：恰好携带 1 个技能。
- **关键词**：不再是卡牌字段，而是技能上的属性；卡牌的关键词由所引用技能派生。

## 3. 技能实体

技能是独立实体，一份文档一个技能，位于 `docs/versions/v0.1/product/content/skills/<id>.md`，文件名等于 `id`。技能 `id` 与卡牌 `id`、英雄 `id` 分属三个命名空间，允许同名，各自查重。

| 字段 | 必填 | 取值域 | 说明 |
| --- | --- | --- | --- |
| `id` | 是 | `^[a-z][a-z0-9-]*$` | 技能命名空间内唯一；必须等于文件名 |
| `name` | 条件必填 | 自由 | 显示名；被英雄引用的技能必填，卡牌技能可省略 |
| `keyword` | 否 | 12 个常驻关键词的取值（含 `繁衍 N`、`装配 N`） | 该技能使携带者登记的关键词；赋予他人关键词的效果不填 |
| `text` | 是 | 自由 | 技能的规范效果文本，也是卡面显示的唯一真值 |
| `match_text` | 条件必填 | 自由 | 比赛模式下的确定性替换；被效果牌或英雄引用的技能必填，无随机写「同左」 |

**`text` 的形态**：沿用卡面现有写法。战吼、亡语、繁衍、装配、播种、进化、传染等带触发关键词的效果保留前缀（如「战吼：使一个友方随从获得一次成长」）；英雄主动技能不带前缀，触发方式由英雄字段表达。

**技能边界**：一段技能是一个可独立结算的效果单元，不等于按「；」机械切分。「若其为<流派>，改为<效果>」是前一段效果的条件变体，必须与前一段留在同一个技能内（如炼金术士、巫医），因此技能 `text` 内部可以出现「；」。其余并列效果各成一个技能。

**`keyword` 的口径**：只登记「携带者自身拥有的常驻关键词」。例如白蚁的「繁衍 1」登记在技能 `keyword` 上，再由白蚁这张卡派生；而效果牌「光合作用」的文本是「使一个友方植物随从获得繁衍 2」，关键词是赋予目标的，技能的 `keyword` 留空，卡牌也不因此获得关键词。每段技能最多登记 1 个关键词；一张卡有多个关键词时，拆成多个技能。

**以现有字段为准**：本次迁移的 `keyword` 赋值必须让卡牌派生出的关键词与迁移前的 `keywords` 字段完全一致，不修正既有数据。已知三处卡面文本与字段不一致，保持原样：毒蛇、猛犸象的效果文本是「亡语：…」但 `keywords` 为空；无线电报的第二段是「战吼：…」但 `keywords` 只有 `装配 2`。修正另立需求，不在本次范围。

**不做的参数化**：`繁衍 1`、`繁衍 2`、`繁衍 3` 是三个技能，不合并为带参数的模板。参数化留待后续版本。

## 4. 引用规则

### 4.1 卡牌

| 变化 | 内容 |
| --- | --- |
| 新增 | `skills: [<技能 id>, ...]`，有序列表，顺序即结算顺序，等价于原「卡面文本从上到下」 |
| 删除 | `keywords` 字段 |
| 必填 | 效果牌 `skills` 必填且非空；随从牌可省略，省略等于不带技能 |

卡牌的 `## 效果` 段落由引用技能渲染：按 `skills` 顺序取技能 `text`，用「；」连接；不带技能时写「无」。属性表新增「技能」行，列技能 id。

卡牌的「关键词」行保留，值改为从所引用技能的 `keyword` 派生，顺序与 `skills` 一致；没有关键词写「无」。与迁移前的 `keywords` 字段比对时按多重集合比较，不要求顺序一致——红树林、水生蕨的旧字段是 `[繁衍 N, 播种]`，效果文本顺序是「播种；繁衍 N」，两者只能保渲染顺序。数值折算使用派生后的关键词。

### 4.2 英雄

| 变化 | 内容 |
| --- | --- |
| 新增 | `skill: <技能 id>`，单个引用 |
| 删除 | `skill_name`、`skill_text`、`match_text` |
| 保留 | `skill_cost`、`skill_type`、`skill_uses_per_turn`、`skill_trigger` |

英雄的触发时机与费用、次数属于英雄自身，不进入技能实体：同一个技能可以被一个战吼随从和一个战斗开始时结算的英雄共用，触发方式由宿主决定。

### 4.3 共享规则

- 只有 `text` 完全相同、且 `keyword` 上下文一致（同一段落在各卡上登记的关键词相同）时才共享同一个技能；否则各自建立独立技能。措辞不同但语义相近的保持独立，不修改既有卡面文本。唯一需要拆分的是「战吼：使你的所有机械随从获得一次成长」：克劳德·香农把它登记为 `战吼`，无线电报的 `keywords` 只有 `装配 2`，两者不能共用同一个 `keyword` 值。
- 同一技能被多张卡引用时，各自结算，互不影响。
- 技能文本变化时，所有引用它的卡牌与英雄同步变化；这是共享引用的预期行为。

## 5. 迁移口径

| 对象 | 数量 |
| --- | --- |
| 卡牌去重后的效果段 | 104 个技能文本，因关键词上下文冲突拆 1 个，共 105 个技能 |
| 英雄技能 | 13 个技能 |
| 技能总数 | 118 个 |
| 引用技能的效果牌 | 32 张，每张 1 个技能 |
| 引用技能的随从牌 | 129 张 |
| 不带技能的随从牌 | 7 张 |
| 技能引用总数 | 188 段卡牌效果单元（原始 190 段子句，2 处条件变体合并）+ 13 个英雄技能 |

卡牌与英雄的实际效果、数值、流派、星级一律不变；本次只改变数据的组织方式。唯一例外是鲁迅的技能文本：删除末尾重复的次数说明「；每回合可用 2 次」，次数继续由 `skill_uses_per_turn: 2` 表达。

## 7. 验收标准

1. `python3 scripts/validate_docs.py` 退出码 0，末行输出包含 `技能 118 个`。
2. 每张效果牌至少引用 1 个技能；7 张无效果随从的 `skills` 为空且 `## 效果` 为「无」。
3. 每份技能文档的 `id` 等于文件名，技能 id 全局唯一。
4. 卡牌 `## 效果` 与所引用技能 `text` 按顺序拼接的结果一致。
5. 卡牌属性表的「技能」「关键词」行与 front matter、技能 `keyword` 一致。
6. 英雄文档的 `skill` 指向存在的技能，且被英雄引用的技能都有 `name` 与 `match_text`。
7. 181 份卡牌与英雄文档的效果文本与迁移前逐字一致（鲁迅技能文本按 §5 删除次数说明除外），仅引用方式改变。
8. 所有相对链接可解析。

## 8. 非目标

- 不新增、删除或重做任何卡牌、英雄、成就；
- 不修改任何效果的数值、触发时机与比赛模式替换结果；
- 不合并措辞相近但不完全相同的技能；
- 不做技能参数化与技能模板；
- 不改变关键词的词表、时代解锁与折算规则。

## 9. 已知取舍

- **名称不是每份技能必填**：104 个卡牌技能中大多数没有自然语言名称，强行命名会制造大量低价值内容。只有被英雄引用的技能需要显示名。
- **`match_text` 只在效果牌与英雄上强制**：随从技能中的随机效果在比赛模式下的替换不在本次范围，维持现状。
- **技能索引会展示引用数**：索引用于发现重复与共享情况，引用数由脚本统计，不写入实体文档。
