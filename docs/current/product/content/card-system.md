# 卡牌规范与数据

> 依赖：[关键词与机制](../rules/keywords-and-mechanics.md)、[时代与场景](../rules/eras-and-scenarios.md)、[数值与经济](../systems/economy-and-numbers.md)
> 状态：已实现
> 数据：`docs/current/product/content/cards/`（432 份，文件名 = id）

本文描述卡牌字段规范、数值与关键词约束、数据总览与校验方式；不描述具体实现与后续版本卡池。归属已实现产品状态的内容。

## 1. 字段规范

每张卡一个文档：`docs/current/product/content/cards/<id>.md`，文件名等于 `id`。文档由 YAML front matter 与正文组成；front matter 只使用 `key: 标量`、`categories: [kind:value, ...]` 与 `skills: [技能 id, ...]` 三种形式。枚举字段与关键词一律写英文 id，中文展示文本由文本表承载（见本节末「运行时文本来源」）。

卡牌分两类：**随从牌**（`card_type: minion`）能站场，必须有初始攻击力与生命值；**效果牌**（`card_type: effect`）不站场，不得有攻击力与生命值。

| 字段 | 类型 | 取值域 | 说明 |
| --- | --- | --- | --- |
| `id` | 字符串 | 语义 slug | **卡牌内唯一**（含进池卡与非池卡）；匹配 `^[a-z][a-z0-9-]*$`；必须等于文件名；中文名用拼音，外国人名与国际通用术语用英文；不含时代前缀，时代由 `era` 字段表达；非池卡沿用既有 `-token` 后缀或语义 id |
| `card_type` | 枚举 | `minion` / `effect` | 随从站场，效果不站场；仅用于卡牌池，英雄卡不带该字段；非池卡同样区分两类 |
| `name` | 字符串 | 进池卡内唯一 | 卡名；优先使用素材原名。仅 `in_shop_pool: true` 的卡要求名称唯一，非池卡允许与池内卡重名（如多份「变形虫幼体」）。front matter 是文本来源，运行时由文本表 `card.<id>.name` 承载 |
| `in_shop_pool` | 布尔 | `true` / `false` | 缺省 `true`；只有 `true` 的卡进入商店卡池、共享牌池、三连与发现；`false` 为衍生物或生成卡（三连奖励），不可购买、不扣池，由技能召唤或规则发放 |
| `taxon` | 字符串 | 分类树叶子 id | 必填；卡牌唯一的科学分类子叶。效果牌按题材取科学、人文、社会或造物下的学科/技术分类叶子；取值见 [分类树与玩法](taxonomy.md) §1 |
| `categories` | 列表 | `play:<玩法 id>` / `prey:<分类节点 id>` / `host:<分类节点 id>` | `in_shop_pool: true` 的卡必填且至少 1 条 `play:`，可多条，每条独立参与图鉴、卡池与对局筛选；非池卡允许没有 `play:`；`prey:` / `host:` 可 0 条，只允许生物卡。条目不重复，按玩法顺序、分类树顺序排列，见 §1.1 |
| `subtype` | 字符串 | 小写英文 slug，匹配 `^[a-z][a-z0-9-]*$` | **仅随从**；学科或类别，不参与玩法与分类判定（如 `economics`、`animal`）；展示名由文本表 `enum.subtype.<subtype>` 提供 |
| `level` | 整数 | 1–7 | 星级，不是时代；7 星的数值区间与份数见[数值与经济](../systems/economy-and-numbers.md) |
| `era` | 枚举 | `prehistoric` / `primitive` / `classical` / `feudal` / `industrial` / `modern` / `future` | **随从与效果牌都必填**；题材归属 |
| `attack` | 整数 | ≥0 | **仅随从，必填**；攻击力为 0 的随从按普通随从结算 |
| `health` | 整数 | ≥1 | **仅随从，必填**；攻击力为 0 的随从取同星级生命上限 ×1.3 |
| `skills` | 列表 | 技能 id 列表 | **随从可省略**，省略等于不带技能（进池随从只允许 1 张造物工具卡无技能，非池卡一般无技能）；**进池效果牌必填且非空**；顺序即结算顺序；随从的技能数量上限：1–2 星 1 个、3–4 星 2 个、5–7 星 3 个且其中登记关键词不超过 2 个；技能本体见[技能规范与数据](skill-system.md) |
| `cost` | 整数 | 0–4 | **仅效果，必填**；购买费用，独立于星级 |

**运行时文本来源**：front matter 的 `name` 与英雄卡的 `introduction` 是文本的编辑来源，构建期由 `scripts/gen_text.py` 汇总到 `client/text/zh_CN.csv`（卡名 key 为 `card.<id>.name`，英雄介绍 key 为 `card.<id>.introduction`）。客户端通过 Godot 翻译接口按 id 取文本，服务端生成数据不含展示文本；新增语言需要扩展文本生成工具并补充各语言文本、注册对应翻译，业务代码与实体文档结构不改动。技能文本与效果文本同样由文本表承载，见[技能规范与数据](skill-system.md) §2。

**正文约定**：一级标题为卡名；`## 属性` 用表格复述 front matter 的字段，供直接阅读，并新增「技能」行列出所引用的技能 id；随从与效果牌的属性表均含「玩法」（全部 `play:` 的展示名，按玩法顺序用「、」分隔，如「哺乳纲、机械」「哺乳纲、植物界」）、「科学分类」（完整路径，如「动物界 › 脊索动物门 › 哺乳纲 › 灵长目 › 人科」「科学 › 生物学」）与「关联分类」（只显示 `prey:` / `host:`，如「捕食：偶蹄目；寄生：细菌域」，没有时省略该行）；随从另含「子类」行。随从与效果牌的属性表不再含「英雄资格」行，英雄卡见 §2.1。`## 效果` 由所引用技能按 `skills` 顺序渲染（技能文案取自实例模板渲染结果或其 `text` 覆盖），无技能写「无」；卡牌在 `## 效果` 之后写 `## 设计说明` 与 `## 出处`。属性表与 front matter 必须一致，由 §5 的校验脚本交叉核对。

**出处约定**：每张卡牌正文在「## 效果」之后必须写一段「## 出处」，用一句可查证的话说明卡名或效果对应的史实、科学发现、文化概念或文学来源，不附链接，不得杜撰。出处不进入属性表。该要求由 §5 校验脚本覆盖。

**编码约定**：front matter 一行一个字段，列表元素用英文逗号分隔；正文只使用中文标点（，、；：）。

### 1.1 玩法、科学分类与关联分类的约束

1. **玩法归属**：每张进池卡至少 1 条 `play:`，取值只能是[分类树与玩法](taxonomy.md) §2 的 13 个玩法之一，不含 `neutral`；非池卡允许没有 `play:`。一张卡可以有多条 `play:`，同时属于多个玩法；每条归属独立参与图鉴分类、卡池过滤、英雄候选与对局内玩法筛选，卡牌任一条命中即视为该玩法卡牌。图鉴与数据总览的玩法统计按归属重复计入，卡牌总数按唯一 id 计。
2. **科学分类子叶**：每张卡恰好一个 `taxon`，取分类树叶子。生物按真实物种建到科；效果牌按题材归入科学、人文、社会下的学科叶子或造物技术分类。科学分类与玩法无绑定关系，机械玩法不要求 `taxon` 落在 `automation`。
3. **玩法与科学分类相互独立**：一张卡可以是「人科」的科学分类、而玩法为「机械」或「植物界」；人类卡不单独成为玩法或筛选维度。
4. **关联分类列表**：每条写作 `kind:value`，同类不重复，顺序固定为先 `play:`（按 [分类树与玩法](taxonomy.md) §2 的玩法顺序）、再 `prey:`、最后 `host:`（同类按分类树声明顺序）。`prey:` / `host:` 只允许生物卡，取分类树的任一节点，按祖先关系匹配，写上级节点即覆盖其下级；效果牌不得有 `prey:` / `host:`。造物工具卡与效果牌使用同一份列表承载玩法归属，不再区分「擅长玩法」「关联玩法」「定向玩法」。

## 2. 数值与关键词约束

以下约束中，攻击力、生命值与关键词相关部分作用于随从牌；效果牌校验星级、费用、技能与时代，时代与随从牌同口径（必填且属于七个时代之一）。

1. 攻击力与生命值必须落在 [数值与经济](../systems/economy-and-numbers.md)的星级区间内；攻击力为 0 的随从改为校验生命值不超过同星级生命上限 ×1.3；
2. **卡池分布约束**（作用于进池随从；多归属卡在每条 `play:` 下分别计数）：
   - 攻击力 > 0 的随从：同一「玩法 + 星级 + 攻击力 + 生命值」组合最多 2 张；
   - 同一「玩法 + 星级 + 效果技能集」最多 1 张。效果技能集指技能列表中剔除 `keyword-` 前缀的关键词技能后剩下的部分；效果技能集按**有序元组**比较，技能顺序是 `skills` 顺序（也是结算顺序），顺序不同即视为不同集合，只有顺序与内容都相同才算重复；关键词技能允许跨卡复用；
   - 效果技能集为空（只带关键词技能）的随从：同一「玩法 + 星级 + 身材 + 完整技能列表」最多 1 张；
   - 攻击力为 0 的随从：豁免身材约束，同一「玩法 + 星级 + 完整技能列表」最多 1 张，生命值在可选档位内分摊。

   校验脚本按上述四条分别统计，打印 `分布 {'身材组': 0, '身材卡': 0, '效果技能组': 0, '效果技能卡': 0, '只带关键词组': 0, '只带关键词卡': 0, '攻 0组': 0, '攻 0卡': 0}`；任一组非 0 即退出码 1。
3. 关键词由所引用技能的 `keyword` 字段派生，只能来自[关键词与机制](../rules/keywords-and-mechanics.md) §1 的判定表（技能 `keyword` 写英文 id，如 `battlecry`、`breed 1`，转写规则见同节）；其中**成长只出现在效果文本、不作为技能 `keyword` 登记**，技能 `keyword` 实际可登记 16 个常驻词；**通用 12 词**（繁衍、战吼、亡语、复生、嘲讽、护盾、连击、传染、无视嘲讽、剧毒、减伤、潜行）必须符合 [关键词与机制](../rules/keywords-and-mechanics.md) §7 的时代解锁关系（史前只有繁衍/战吼/亡语，原始才有成长/嘲讽，古典才出现连击/无视嘲讽/传染，封建才有复生，工业才有护盾，现代与未来不再新增），其中剧毒/减伤/潜行不按时代解锁，最小星级按卡池实际（剧毒 3、减伤 2、潜行 3），玩法归属为剧毒爬行纲/头足纲/水螅纲、减伤爬行纲/细菌域/水螅纲、潜行仅头足纲；**专属 4 词不参与时代解锁**；`光环` 不是关键词，持续效果写在正文 `## 效果` 中；
   - 专属词必须与玩法或分类一致：`分解` 只能在真菌界或细菌域玩法的卡、`装配` 只能在 play 命中机械的卡（含造物六类工具卡）、`播种` 只能在植物界玩法、`进化` 只能在生物卡；
4. 关键词折算后，`攻击力 + 生命值 + 折算` 不得超过同星级白板总和 + 4；
5. 进池卡同名只允许出现一次（三连靠份数，不靠重名）；非池卡允许重名。该唯一性约束**按卡牌类型分别作用于进池随从、进池效果牌与英雄池**：随从池与效果牌池各自唯一，英雄池内 id 与名称唯一；英雄卡与同名随从卡分属两个池，允许 id 与名称相同；
6. 涉及敌方目标的文本必须显式写出选择器：随机、最左侧、最左侧及相邻、攻击力最高、全体；战吼中的敌方效果延迟到战斗开始时结算，见 [核心规则](../rules/core-rules.md) §4.4。

### 2.1 英雄卡

英雄是独立卡牌实体，位于 `content/heroes/`，只用于开局选英雄；**不进商店、不进牌池、不参与三连与发现，不可购买**。英雄卡只保留身份、介绍与技能字段（`id`、`name`、`categories`、`introduction`、`skills`），不含 `card_type`、星级、攻击、生命、时代、科学分类与费用。`introduction` 为 40–80 字的英雄介绍，正文 `## 简介` 与之一致；只用于展示，不参与对局结算。每张英雄卡都与 `content/cards/` 中一张随从卡**同 id、同名**，两卡分属英雄池与随从池；引擎按用途查对应池，英雄查询只走英雄池。

英雄候选池按本局启用的 5 个玩法过滤：英雄任一条 `play:` 命中本局玩法即入选，不再区分中立英雄与纯通用英雄；未启用玩法的英雄不出现在任何玩家的候选中。开局时，服务端为每位玩家分配 4 张候选英雄卡，玩家从自己的候选中选 1 张作为英雄；候选在同一房间内优先互不重复，候选池不足时允许跨玩家重复并按池大小缩减每人候选数，候选池为空时回退到全部英雄卡抽取。候选在开局确定，重进房间（含断线重连）不重新分配，本局玩法与候选都不重新抽取。

- 选择英雄不消耗牌池份数、不进入手牌或战场；同名随从卡仍作为普通随从留在卡池中，可被任何玩家购买，数值与技能不变。
- 英雄身份授予英雄卡的全部 `skills`；买到的同名随从卡按普通随从结算，同样获得该随从卡的全部 `skills`。两张卡的 `categories` 完全一致，`skills` 各自维护、不要求相同，但分别从各自的池读取。
- 英雄技能只能为主动或被动技能：英雄不进入战场，技能不得登记战吼、护盾、亡语等随从战场关键词。一个英雄可以有多个主动技能，按英雄卡 `skills` 顺序展示与结算。
- 主动技能由玩家支付技能实体的 `cost` 后使用，每回合至多 `uses_per_turn` 次；被动技能按技能对象文本的触发前缀自动结算，宿主为玩家本人。
- 多人局允许重复选择同一张英雄卡；英雄身份互不影响。
- 英雄池恰好 32 张；随从池与效果牌不得再有 `is_hero` 字段，英雄卡不得出现「英雄资格」属性行或旧版英雄技能字段与 `## 英雄技能` 小节。

### 2.2 棋盘随从的主动技能展示

- 随从卡可携带 0–N 个主动技能；进入本人棋盘后，每张卡按 `skills` 顺序在卡面右上角显示技能角标，文本为 `◆<费用>×<剩余次数>`（`◆` 为费用字形），剩余次数为 `uses_per_turn` 减本回合已用次数（缺省 1）。
- 角标只在本人棋盘显示，对手棋盘不下发该字段；服务端判定不可用（阶段、次数、金币或目标候选）时角标置灰，可用性以 `abilities[].canUse` 与 `disabledReason` 为准。
- 当前 41 张非英雄随从卡共引用 18 个主动技能，均可通过随从入口发动（清单以生成数据与 `python3 scripts/validate_docs.py` 为准）。

## 5. 校验规则与命令

每次修改卡牌文档后必须运行：

```bash
python3 scripts/validate_docs.py
```

校验覆盖：

- **文档与字段**：文档数量、`card_type` 合法（仅卡牌池，英雄卡不带该字段）、文件名与 `id` 一致、`id` 在卡牌池内唯一、`id` 格式、枚举字段合法、随从必有 `attack`/`health` 且效果牌不得有、攻击力为 0 的随从生命值偏离「同星级生命上限 ×1.3」不超过 1 点、英雄卡 `introduction` 为 40–80 字且与 `## 简介` 一致；旧分类字段残留视为错误。
- **科学分类树**：节点 `id` 唯一、父节点存在、无环、层级合法；生物叶子为「科」、造物叶子为「技术分类」、科学/人文/社会叶子为「学科」；每张卡的 `taxon` 必须是叶子，`prey:` / `host:` 指向的节点必须存在。
- **玩法与关联分类**：每张进池卡至少 1 条 `play:`，取值必须是 13 个玩法之一且不含 `neutral`；非池卡允许没有 `play:`；`play:` 可多条；`prey:` / `host:` 只允许生物卡，节点必须在分类树中；同一张卡内条目不重复，顺序为先 `play:`（按玩法顺序）、再 `prey:`、最后 `host:`；英雄卡与同 id 随从卡的 `categories` 完全一致，`skills` 各自维护、不要求相同。造物工具卡与效果牌不再有额外的玩法限制。
- **技能数量**：1–2 星随从最多 1 个技能，3–4 星最多 2 个，5–7 星最多 3 个且登记关键词不超过 2 个；进池随从中无技能者恰好 1 张，且必须是造物六类工具卡；非池卡不受技能数量约束。
- **关键词**：16 个常驻词的白名单；`分解` 仅 play 命中真菌界或细菌域；`装配` 仅 play 命中机械（含造物六类工具卡）；`播种` 仅 play 命中植物界；`进化` 仅生物卡；`剧毒` 仅 play 命中爬行纲/头足纲/水螅纲、`减伤` 仅 play 命中爬行纲/细菌域/水螅纲、`潜行` 仅 play 命中头足纲；通用词的最小星级必须与时代解锁表一致（剧毒/减伤/潜行按卡池实际最小星级）；光环分句句式合法。
- **DSL**：筛选键为 `taxon` / `playstyle` / `play` / `prey` / `host` / `subtype` / `id` / `type` / `keyword` / `other`；`timesIf` 使用「键:值:次数」格式；`Decompose` 的 `basis` 与 `duration` 必填且取值合法；`OnKill` / `OnAllyKill` 在触发白名单内；「分解：」前缀只允许三种击杀/死亡触发。
- **卡池分布**：§2 第 2 条的四条约束——同玩法同星级同身材（攻 > 0）≤ 2 张、同玩法同星级效果技能集 ≤ 1 张、只带关键词卡按「身材 + 完整技能集」≤ 1 张、攻 0 卡按完整技能集 ≤ 1 张；脚本打印 `分布` 统计，各组的「组」「卡」计数必须全部为 0。
- **其余**：卡牌时代分布、随从星级分布、星级数值区间与超模上限（战吼/亡语的召唤、复制类按 4 点折算，其余按 2 点）、效果牌星级、费用与时代、单体敌方目标是否写明选择器、英雄卡恰好 32 张、随从与效果牌不得再有 `is_hero`、无已废弃的英雄技能字段或小节残留、**技能引用完整性与渲染一致性**、**每份文档的属性表与其 front matter 一致**（含「玩法」「科学分类」「关联分类」行）、**每张卡牌必须有非空「## 出处」**。

期望：输出包含 `分布 {'身材组': 0, '身材卡': 0, '效果技能组': 0, '效果技能卡': 0, '只带关键词组': 0, '只带关键词卡': 0, '攻 0组': 0, '攻 0卡': 0}`，以及 `随从 332 张、效果牌 100 张、技能 262 个、英雄卡 32 张，校验通过`；其前打印时代、玩法、星级、关键词与技能引用统计，其后打印 `分类树节点 338 个、玩法 13 个，校验通过` 与 `v0.2 成就 6 个，校验通过`；退出码 0。否则逐条打印违规并以退出码 1 结束。
