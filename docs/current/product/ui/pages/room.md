# 选英雄页（房间）

> 状态：已实现
> 场景：`client/scenes/room.tscn`
> 脚本：`client/scenes/room.gd`；候选卡 `client/scenes/room_hero_card.gd`（`RoomHeroCard`），悬停详情层 `client/scenes/room_hero_detail_layer.gd`（`RoomHeroDetailLayer`）
> 验证：`make client-smoke`

## 1. 目的、入口与返回

- 目的：开局前从服务端分配给本人的一组候选英雄里选一张并确认。确认同时等于「准备」，服务端在 8 个座位全部确认后自动开局。房主在等待区还可以移除其他成员或解散房间。
- 入口：大厅创建或加入房间成功后收到 `RoomUpdate` 进入；重连回到 `Lobby` 阶段时同样进入本页。对局结束即销毁房间，不会再回到本页。
- 返回：收到 `GameStarted` 或阶段离开 `Lobby` 且已有视图时进入对局页；`NOT_IN_ROOM` / `ROOM_NOT_FOUND` 回大厅；被房主移出或房间解散时按 `RoomClosed.reason` 提示原因后回大厅；认证类错误回登录。本页没有主动离开房间入口。

## 2. 结构层级

```text
背景（全屏）
DraftPanel：卡片面板（surface，铺满整屏，忽略鼠标）
└─ ContentCenter：居中容器（忽略鼠标）
   └─ 纵向容器（间距 8，忽略鼠标）
      ├─ OtherPlayers：其他玩家的「名字 · 已确认/未确认」胶囊行（水平居中）
      │  └─ 房主且阶段为等待区时，每行追加移除按钮 `Kick_<playerId>`
      ├─ 小标题「请选择英雄」（居中）
      ├─ HeroCandidates：本人候选英雄卡（`RoomHeroCard`，HBoxContainer，水平居中）
      ├─ InviteRow：「邀请好友」标签 + 在线好友按钮行（水平居中）
      ├─ ConfirmButton：确认（主按钮，高 36，按自身宽度居中）
      ├─ DissolveButton：解散房间（仅房主可见，按自身宽度居中）
      └─ StatusLabel：状态行（居中）
HeroDetailLayer：悬停详情层（全屏，默认隐藏，忽略鼠标）
└─ RoomHeroDetail：详情卡（名字 + 介绍 + 技能，贴在悬停卡外侧，不显示图片）
```

- 面板铺满视口，尺寸只由视口决定，不随候选行或状态文字变化；内容块在面板内水平与垂直居中。
- 面板顶部只显示其他玩家的名字与确认状态，从不显示任何人选了哪张英雄——候选只发给本人，页面也没有别的数据来源。
- 面板内只渲染服务端下发的本人候选；候选未到时显示「正在分配英雄…」，内容块随内容变矮但仍保持居中。
- 本页不显示房间码，也不提供主动离开房间入口；邀请好友只在本页提供（邀请要求邀请者已在大厅阶段的房间内），分享入口留给后续版本。
- 房主操作只在本人是房主且 `GameStore.phase == Lobby` 时出现：其他成员行显示「移除」，底部显示「解散房间」。非房主看不到任何管理控件；对局开始后管理控件不再渲染。
- 对局结束时服务端即销毁房间，本页随对局页一起退出；结算页只展示本局结果，不回到本页等待区。
- 邀请行只列好友：`status == "online"` 的按钮可点，`inGame` 与 `offline` 置灰；没有好友时显示「暂无好友可邀请」。点击后状态行显示「已邀请 X」，邀请结果由服务端 `FriendInviteResult` 回写为「好友已接受邀请」或「好友没有接受邀请」。

## 3. 状态清单

| 状态 | 触发 | 表现 | 出口 |
| --- | --- | --- | --- |
| 加载中 | 本人候选为空且未确认 | 候选区「正在分配英雄…」，确认禁用 | 收到带 `heroCandidates` 的 `RoomUpdate` |
| 未连接 | `Net` 未连接 | 状态行「未连接服务器」，确认禁用 | 自动重连后恢复 |
| 悬停预览 | 鼠标移入候选卡（触控端长按 450ms） | 悬停卡左侧或右侧外侧显示详情卡；移出（或抬手）立即关闭 | 移到另一张卡或移出候选行 |
| 已选未确认 | 点中一张候选卡 | 该卡出现外扩金色选中框，确认可用；再次点击同一张保持选中 | 点确认或改选另一张 |
| 已确认 | 本人座位 `ready` 为真 | 选中框保留，确认按钮显示「已确认」并禁用，全部候选卡锁定不可改选；悬停仍可看详情 | 等待其他玩家或开局 |
| 房主等待区 | 本人 `isHost` 为真且阶段为 `Lobby` | 其他成员行出现「移除」，底部出现「解散房间」 | 移除后成员列表刷新；解散后全房回大厅 |
| 非房主等待区 | 本人不是房主 | 不渲染移除与解散控件 | 等待房主操作或开局 |
| 被移出 | 收到 `RoomClosed{reason:"kicked"}` | 状态行写入「你已被房主移出房间」，随后回大厅 | 大厅 |
| 房间解散 | 收到 `RoomClosed{reason:"dissolved"}` | 状态行写入「房间已解散」，随后回大厅 | 大厅 |
| 对局结束 | 收到 `GameOver` | 房间已销毁，本页不再可用 | 进入结算页 |
| 错误 | `Error` 消息 | 状态行中文文案，tooltip 为协议原文 | 按错误码留页、回大厅或回登录 |

- 同一时刻只有一张卡处于选中态：点已选中的卡保持选中，点另一张才切换；点空白不取消选中。
- 确认后不可改选：页面锁定全部候选卡，服务端也会拒绝候选外的卡与已确认后的改选。

## 4. 候选卡

- 卡面 `160×209`：有卡面美术时叠 `card_face`（按 112:146 比例，向内收 3px，四角落在卡片圆角内），否则铺玩法色（`UITheme.playstyle_cover`）并居中显示大号首字水印（`color-text` 16% 透明度）；名字在底部居中，叠在卡面上时带半透明底色。
- 数据只取 `CardDB`：玩法决定封面色，名字来自卡表；不显示数值，避免与对局内的当前值混淆。
- 悬停态把卡片描边切换为 `color-border-strong`；触控端不显示悬停描边。
- 选中态由卡片外扩的 `SelectedFrame` 表达：透明底、2px `color-accent` 描边、`radius-lg` 圆角，向卡片外扩 `space-2xs`；不使用额外徽标或文字。
- 已确认时全部候选卡锁定：卡面内容降透明度，选中框保持全亮，卡片不再响应选择；悬停仍可看详情。
- 有 `card_face` 美术的候选显示卡面图并隐藏首字水印；无美术或加载失败时回退玩法色与水印。

## 5. 悬停详情

- 触发：桌面鼠标移入候选卡，或触控端长按候选卡 450ms（位移超过 8 画布单位取消）。
- 关闭：桌面移出候选卡；触控端抬手。点击只切换选中，不打开或关闭详情。
- 位置：详情卡贴着悬停的那张候选卡：悬停卡中心在详情层中心左侧时挂在卡片左侧外侧，否则挂右侧外侧；与卡片间隙 `space-sm`，竖直方向与卡片居中对齐。面板四周夹紧在详情层安全区内，夹紧后若压住悬停卡则换到另一侧；贴卡定位允许覆盖其他候选卡。
- 内容：英雄名 + 英雄介绍（`CardDB.hero_introduction`，非空时显示，弱化色） + 技能列表；不显示卡面或立绘图片。技能列表与图鉴英雄详情共用 `UI.skill_list`，按英雄 `skills` 顺序逐条展示：技能名（没有名称时省略）、触发类型标签、完整技能文本；主动技能追加「费用 N · 每回合 N 次」。无技能时显示「暂无技能」。
- 样式：`UITheme.panel_style("raised")` 面板；文本按详情宽度换行，英雄技能最多 2 条，不需要滚动。详情层与其子节点全部忽略鼠标输入，不拦截对候选卡、确认按钮或空白处的点击。
- 候选刷新时若候选 id 未变，只更新选中/锁定状态，不重建卡片，避免悬停详情被意外关闭；必须重建时，若指针仍停在原英雄卡上则恢复详情。

## 6. 数据来源

| 数据 | 来源 |
| --- | --- |
| 其他玩家的名字与确认状态 | `room_players[].displayName`、`room_players[].ready` |
| 本人候选 | `room_players[]` 中本人那一项的 `heroCandidates`（服务端只对本人填充） |
| 本人已选英雄 | `room_players[]` 中本人那一项的 `heroCardId` |
| 本人确认状态 | `room_players[]` 中本人那一项的 `ready` |
| 本人是否房主 | `room_players[]` 中本人那一项的 `isHost`（协议同时下发 `hostId`） |
| 卡面与技能列表 | `CardDB.card` / `CardDB.hero` / `CardDB.display_name` / `CardDB.skill_info`；技能列表由 `UI.skill_list` 读取英雄卡的 `skills` |

- 页面不做分配逻辑：候选完全由服务端下发，客户端不洗牌、不补齐、不去重。
- 其他玩家的 `heroCandidates` 恒为 `null`，页面也不读取这一字段用于他人展示。

## 7. 事件

| 操作 | 请求 |
| --- | --- |
| 点确认 | 先 `SelectHeroCard{cardId}`，再 `Ready{ready:true}`，一次完成选英雄与准备 |
| 点候选卡 | 纯本地状态，不发请求 |
| 点移除 | `KickMember{targetPlayerId}`；仅房主且等待区可用 |
| 点解散 | `DissolveRoom{}`；仅房主且等待区可用 |

- 确认按钮在未选中、已确认或未连接时禁用；禁用状态不发送任何请求。
- 选英雄与准备分两条消息发送：服务端仍然要求「先选英雄再准备」，两条消息顺序发送即可满足。

## 8. 适配

- 页面内容固定 16:9 居中，桌面与 iPad 以 1280×720、iPhone 以 960×540 为设计基准，窗口比例变化只在内容框外露出背景；候选固定 4 张（服务端 `CANDIDATE_COUNT = 4`），用 `HBoxContainer` 单行展示并水平居中。
- 面板铺满内容框且尺寸只由内容框决定；确认键、候选行与状态行在内容块内同轴居中。
- 桌面与手机都按悬停卡贴边定位：详情宽桌面 280、手机 200，与卡片间隙 `space-sm`，允许覆盖相邻候选卡；手机长按浮层同样不拦截输入。
- 详情只跟随指针：桌面指针移出候选卡即关闭，空白处按下/松开（无移动）同样关闭；触控抬手即关闭。
- 候选卡只加载英雄卡面位图；详情不加载任何图片，字体与配色由设计令牌统一决定。
