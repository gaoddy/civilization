# 选英雄页（房间）

> 状态：已实现
> 场景：`client/scenes/room.tscn`
> 脚本：`client/scenes/room.gd`
> 验证：`make client-smoke`

## 1. 目的、入口与返回

- 目的：开局前只做一件事——从服务端分配给本人的一组候选英雄里选一张并确认。确认同时等于「准备」，服务端在 8 个座位全部确认后自动开局。
- 入口：大厅创建或加入房间成功后收到 `RoomUpdate` 进入；重连回到 `Lobby` 阶段时同样进入本页。
- 返回：收到 `GameStarted` 或阶段离开 `Lobby` 且已有视图时进入对局页；`NOT_IN_ROOM` / `ROOM_NOT_FOUND` 回大厅；认证类错误回登录。本页没有离开房间入口。

## 2. 结构层级

```text
背景（全屏）
SkillDismissLayer（全屏，位于内容之下，默认隐藏）
DraftPanel：卡片面板（surface，铺满整屏，忽略鼠标）
└─ ContentCenter：居中容器（忽略鼠标）
   └─ 纵向容器（间距 8，忽略鼠标）
      ├─ OtherPlayers：其他玩家的「名字 · 已确认/未确认」胶囊行（水平居中）
      ├─ 小标题「请选择英雄」（居中）
      ├─ HeroCandidates：本人候选英雄卡（HBoxContainer，水平居中）
      ├─ ConfirmButton：确认（主按钮，高 36，按自身宽度居中）
      └─ StatusLabel：状态行（居中）
技能层（全屏，默认隐藏，忽略鼠标输入）：技能浮层
```

- 面板铺满 1280×720，尺寸不随候选行或状态文字变化；内容块在面板内水平与垂直居中。
- 面板顶部只显示其他玩家的名字与确认状态，从不显示任何人选了哪张英雄——候选只发给本人，页面也没有别的数据来源。
- 面板内只渲染服务端下发的本人候选；候选未到时显示「正在分配英雄…」，内容块随内容变矮但仍保持居中。
- 本页不显示房间码，也不提供离开房间入口；邀请与分享入口留给后续版本。

## 3. 状态清单

| 状态 | 触发 | 表现 | 出口 |
| --- | --- | --- | --- |
| 加载中 | 本人候选为空且未确认 | 候选区「正在分配英雄…」，确认禁用 | 收到带 `heroCandidates` 的 `RoomUpdate` |
| 未连接 | `Net` 未连接 | 状态行「未连接服务器」，确认禁用 | 自动重连后恢复 |
| 已选未确认 | 点中一张候选卡 | 该卡描边高亮，弹出技能浮层，确认可用 | 点确认或改选另一张 |
| 已确认 | 本人座位 `ready` 为真 | 选中卡保持高亮，确认按钮显示「已确认」并禁用，全部候选卡不再响应点击 | 等待其他玩家或开局 |
| 错误 | `Error` 消息 | 状态行中文文案，tooltip 为协议原文 | 按错误码留页、回大厅或回登录 |

- 同一时刻只有一张卡处于选中态：再点同一张取消选中并关闭浮层，点另一张切换选中并刷新浮层。
- 确认后不可改选：页面禁用一切改选入口，服务端也会拒绝候选外的卡与已确认后的改选。

## 4. 候选卡

- 卡面 `160×200`：部落色封面铺满（`UITheme.tribe_cover`），居中为大号首字水印（`color-text` 16% 透明度），名字在底部居中。
- 数据只取 `CardDB`：部落决定封面色，名字来自卡表；不显示数值，避免与对局内的当前值混淆。
- 选中态由 2px `color-accent` 描边表达，不使用额外徽标。
- 已确认时全部候选卡整体降透明度并解除点击绑定。
- 没有图片资源，封面为色块与水印；后续有封面图时按 `cardId` 替换。

## 5. 技能浮层

- 触发：选中一张候选卡时显示。
- 关闭：再点同一张卡、点另一张，或点浮层以外的空白（`SkillDismissLayer` 铺满全屏、位于内容之下）。
- 内容：英雄名 + `CardDB.display_text(hero_id)` 的技能文本。
- 样式：`UITheme.panel_style("raised")` 面板，居中显示。浮层本身与其子节点全部忽略鼠标输入，不拦截对候选卡、确认按钮或空白层的点击。

## 6. 数据来源

| 数据 | 来源 |
| --- | --- |
| 其他玩家的名字与确认状态 | `room_players[].displayName`、`room_players[].ready` |
| 本人候选 | `room_players[]` 中本人那一项的 `heroCandidates`（服务端只对本人填充） |
| 本人已选英雄 | `room_players[]` 中本人那一项的 `heroCardId` |
| 本人确认状态 | `room_players[]` 中本人那一项的 `ready` |
| 卡面与技能文本 | `CardDB.card` / `CardDB.display_name` / `CardDB.display_text` |

- 页面不做分配逻辑：候选完全由服务端下发，客户端不洗牌、不补齐、不去重。
- 其他玩家的 `heroCandidates` 恒为 `null`，页面也不读取这一字段用于他人展示。

## 7. 事件

| 操作 | 请求 |
| --- | --- |
| 点确认 | 先 `SelectHeroCard{cardId}`，再 `Ready{ready:true}`，一次完成选英雄与准备 |
| 点候选卡 | 纯本地状态，不发请求 |

- 确认按钮在未选中、已确认或未连接时禁用；禁用状态不发送任何请求。
- 选英雄与准备分两条消息发送：服务端仍然要求「先选英雄再准备」，两条消息顺序发送即可满足。

## 8. 适配

- 逻辑尺寸固定 1280×720，窗口按 `canvas_items` 缩放；候选固定 4 张（服务端 `CANDIDATE_COUNT = 4`），用 `HBoxContainer` 单行展示并水平居中。
- 面板铺满屏幕且尺寸固定；确认键、候选行与状态行在内容块内同轴居中。
- 不加载图片与字体资源，深浅色由设计令牌统一决定。
