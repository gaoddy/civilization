# 对局页

> 状态：已实现
> 场景：`client/scenes/game.tscn`
> 脚本：`client/scenes/game.gd`
> 验证：`make client-smoke`

## 1. 目的、入口与返回

- 目的：在酒馆战棋式的三栏布局中呈现服务端 `PlayerView` 与 `CombatResult`，并把玩家操作转成协议意图。
- 入口：房间页在 `RoomUpdate` 阶段离开 `Lobby` 或收到 `GameStarted` 后导航进入；重连后收到视图也会进入。
- 返回：对局结束收到 `GameOver` 后进入结算页；认证类错误回登录；`NOT_IN_ROOM` / `ROOM_NOT_FOUND` 回大厅。

## 2. 结构层级

```text
背景
└─ 外边距
   └─ 纵向根容器
      ├─ 主体（横向）
      │  ├─ 左栏 座位列（88）
      │  │  └─ 8 行座位：头像 + 名次角标 + 血量条；点击展开战报
      │  ├─ 中区（自适应）
      │  │  ├─ 招募视图
      │  │  │  ├─ 商店（6 槽）
      │  │  │  └─ 我方棋盘（按容量的随从卡或空位）
      │  │  ├─ 战斗视图
      │  │  │  ├─ 对手随从行
      │  │  │  ├─ 结果横幅
      │  │  │  └─ 我方随从行
      │  │  └─ 手牌行（横向滚动，招募与战斗常驻）
      │  └─ 右栏（272）
      │     ├─ 身份块：售货员大图（名字贴底）与下方商店操作横排 / 对手英雄（幽灵战或已淘汰观战）
      │     ├─ 状态块：回合数与剩余时间同一行，位于右栏垂直中心
      │     └─ 英雄块：我方英雄大图在上，英雄技能在下，生命/时代/金币三格贴底
      └─ 状态行
选择浮层（全屏，默认隐藏）：待选/目标弹层
详情层（全屏，忽略鼠标输入）：卡牌与座位详情面板（默认隐藏）
```

- 页面没有顶栏；生命、时代与金币只在右栏 `SideHero` 的自己英雄介绍里各出现一次。
- 左栏 `PlayersRail` 每行只有 44px 头像、左上角名次角标与 6px 血量条，不显示名字、时代、随从数与血量数字。
- 左栏固定宽 88，只够放下头像；点击展开的战报浮层覆盖在中区与右栏之上，不挤压三栏宽度。
- 名次角标在 `rank` 为 `null` 时不显示；已淘汰行仍显示名次并整体压暗，仍可点击。
- 点击座位行在行右侧展开这名玩家的战报浮层，浮层覆盖中区与右栏但不改变三栏宽度；同一时刻只有一行展开，展开状态按 `playerId` 在视图刷新重建后保持。
- 右栏分三段：`SideIdentity`（身份）、`SideStatus`（回合数与剩余时间同一行）、`SideHero`（自己英雄介绍在上、英雄技能在下、生命/时代/金币三格贴底）；身份块与英雄块等高，状态块因此落在右栏垂直中心。
- 招募阶段的售货员用 200×150 大卡，我方英雄用 200×150 大图，名字都在底部居中；刷新、升时代与冻结三个商店操作按钮横排在售货员正下方，身份块内居中；售货员的「商店营业中」与我方英雄的部落/时代/技能说明只在鼠标悬停时通过详情浮层显示。
- 中区商店与棋盘面板不显示标题；棋盘不再显示「随从 x/x」，容量只体现在槽位数量上。
- 自己英雄的生命、时代与金币拆成三块等宽数据格，每格用「小标题 + 高对比大数值」单独呈现。
- 招募阶段悬停中部倒计时会翻成「结束招募」，移出恢复剩余时间；点击发出 `EndRecruit`。战斗阶段倒计时只显示「战斗中」，不翻转。
- 战斗视图只有「对手随从 / 结果横幅 / 我方随从」三段；不再有双方英雄条。
- 详情层位于内容与战报之上、选择浮层之下，只在悬停或触摸座位行、招募棋盘与战斗随从、商店卡时显示；选择浮层打开时自动隐藏，战报浮层打开时也不抢占画面。
- 招募视图与战斗视图互斥显示：战斗与结算阶段隐藏招募视图、商店操作按钮、英雄技能与结束招募，节点保留以便状态恢复。
- 手牌行不在招募视图内，而是中区里位于战斗视图之下的常驻行：演示期间手牌照常显示当前内容但只读。
- 招募视图自上而下固定为商店、我方棋盘；棋盘面板按内容高度收缩并贴到招募视图底部，下方留白全部落在商店与棋盘之间，使棋盘直接位于手牌上边。
- 左栏、右栏与状态行在两个阶段都常驻。

## 3. 状态清单

| 状态 | 触发 | 表现 | 出口 |
| --- | --- | --- | --- |
| 加载中 | `GameStore.view` 为空 | 状态行「等待对局状态…」 | 收到视图后自动恢复 |
| 空棋盘 | `self.board` 为空 | 棋盘显示按容量的「空位」槽 | 从手牌打出随从 |
| 空商店槽 | 槽位 `cardId` 为 `null` | 槽位显示「空槽」且不响应点击 | 刷新商店 |
| 空手牌 | `self.hand` 为空 | 手牌区「手牌为空」 | 购买或发现获得 |
| 目标待选 | `self.pendingChoices` 头部 `kind` 为 `target` | 浮层只列我方棋盘随从并高亮触发者，没有取消与跳过；购买/刷新/升时代/冻结/结束招募/英雄技能/出售/换位/拖拽全部禁用 | 选中一个随从后发出 `ChooseTarget` |
| 战斗动作未到 | 战斗阶段 `last_combat` 为空 | 对手行「等待战斗动作…」，横幅隐藏 | 收到 `CombatResult` 后自动恢复 |
| 战斗演示中 | 战斗阶段已有 `CombatResult` 且动作未播完 | 双方随从按动作逐步更新，横幅隐藏；攻击方卡克隆后飞向目标、命中闪光与伤害飘字、再飞回原位，阵亡卡回位后才消失；右栏状态行显示「战斗中」、不显示招募倒计时；商店、刷新、升时代、冻结、英雄技能、结束招募不可见，手牌只读 | 动作播完并经过横幅停留 |
| 演示播完 | 动作播完且超过 `TAIL_MS` | 横幅显示胜负或「平局」、伤害与双方随从数；页面发送一次 `CombatPlayed` | 全部参战座位回报后服务端推进到下一回合招募（兜底截止同样推进） |
| 幽灵战 | 战斗阶段 `mirror` 为真 | 右栏身份块显示幽灵归属者的英雄，带「幽灵」角标且无血量条；对手信息整体压暗 | 服务端推进到下一回合招募 |
| 自身已淘汰 | 战斗阶段自己不在存活座位 | 右栏身份块显示「已淘汰 · 观战中」 | 服务端推进阶段 |
| 战报为空 | 展开的座位上没有 `combatLog` 条目 | 展开块显示「无战报」 | 收到该座位参与的战报 |
| 座位已淘汰 | `alive` 为假 | 座位行整体压暗，名次角标仍显示，仍可点击展开战报 | 对局结束 |
| 错误 | `Error` 消息 | 状态行中文文案，tooltip 为协议原文 | 按错误码留页、回大厅或回登录 |
| 无权限 | 页面没有按角色区分的操作；越权请求由服务端拒绝 | 按错误状态展示，不本地隐藏操作 | 按错误码处理 |
| 离线 | `Net` 未连接 | 状态行「未连接 · 正在重连」；操作提示「未连接，操作未发出」 | 3 秒自动重连，收到 `Snapshot` 恢复 |
| 视图过期 | `view.turn` 与 `GameStore.turn` 不一致 | 全部操作禁用 | 收到新回合视图 |
| 倒计时归零 | `phaseDeadline` 已过 | 右栏倒计时显示「等待结算」，全部招募操作禁用 | 服务端推进阶段 |
| 已结束招募 | `self.recruited` 为真 | 只读；倒计时悬停显示「已结束招募」，冻结禁用 | 服务端推进阶段 |
| 达到上限 | 商店 6 槽、棋盘按 `boardSlots` 计 | 槽位固定，空位以「空位」占位 | 服务端判定手牌与棋盘上限，拒绝原因进 tooltip |

- 同一时刻只呈现一种主状态；错误文本不覆盖正在显示的待选弹层，弹层由独立的视图门槛控制。
- 右栏身份判定以阶段优先：招募阶段一律显示售货员「商店营业中」，即使自己已淘汰；战斗阶段才按「自身已淘汰 → 幽灵战 → 对手 → 等待配对」的顺序显示。幽灵战除 `mirror` 为真外，还要求当前回合战报有效（`combat_is_current()`）且 `opponentPlayerId` 非空。
- 幽灵战的结果横幅在「胜利/失败/平局」后追加「（幽灵）」。

## 4. 数据来源

| 数据 | 来源 |
| --- | --- |
| 回合、阶段、阶段截止时间 | `view.turn`、`view.phase`、`view.phaseDeadline`；`GameStore.phase`、`GameStore.deadline` 作为空视图或旧视图时的兜底 |
| 生命、生命上限、时代、金币、英雄、技能次数 | `view.self` 与 `view.hpCap` |
| 商店、手牌、棋盘、可用性 | `view.self.shop/hand/board/affordances`，按钮可用性只取 `buyable`、`playable`、`sellable`、`can*` |
| 座位行与对手信息 | `view.players`（座位号、名字、生命、时代、存活、随从数、英雄、准备、名次 `rank`、托管） |
| 座位血量条 | `players[].hp` 与 `view.hpCap` 的比例；`hpCap` 缺失按 40 |
| 座位战报 | `view.combatLog`：按 `participantIds` 过滤出该玩家参与的全部条目 |
| 战斗双方与结果 | `CombatResult`：`ownBoard`、`opponentBoard`、`actions`、`damage`、`winnerId`、`mirror`；当前对手为 `view.opponentPlayerId` |
| 战斗动作 | `CombatResult.actions` 的 `kind`（`attack`/`death`/`reborn`/`contagion`/`summon`）、`sourceMinionId`/`targetMinionId`、动作后的 `source`/`target` 随从状态（`minionId`/`attack`/`health`/`alive`）与 `summon`（`side`/`position`/`minion`） |
| 手牌是否需要目标 | `self.hand[].requiresTarget`；队首待选类型取 `self.pendingChoices[].kind` |
| 随从详情构成 | 棋盘随从的 `stats`（`attack` / `health` 各含 `initial`、`permanent`、`turn`、`aura`、`damage`、`current`）；缺失时退化为顶层 `attack` / `health` |
| 卡面与商店详情 | `CardDB` 卡表：`card_type`、`tribe`、`attack`、`health`、`era`、`display_cost`、`skills` |

- 页面不做本地规则推导：不计算伤害、不推断可用性、不排序名次；战斗演示按 `actions` 逐条应用服务端下发的数值，不做任何加减。
- `CombatResult` 只发给该场参战者本人：观战者（含幽灵归属者）在战斗阶段不收到它，只能从战报里看到这场对战的结果与幽灵归属者名字；阵容演示只发给参战者。
- 战斗演示期间还没有本场 `combatLog`：战报在结算时才下发，演示中展开座位只看到既往回合条目。
- 座位战报文案为「第 N 回合 · 对手名 · 胜/负/平 · 伤害 X」；平局无胜者时输出「平」；幽灵战的对手写「幽灵（名字）」，`ghostId` 为空时只写「幽灵」；`damage` 为 0 时省略伤害段；没有条目时显示「无战报」。
- 详情面板直接展示 `stats` 的分层数值，不自行重算层和与当前值。
- 商店卡的攻击力与生命值只读卡表的原始值，不参与任何判定。
- 重排（拖拽换位）与冻结没有对应 affordance，按阶段、`recruited` 与下标本地门控，与服务端拒绝条件一致。
- 时代文案由 `CardDB.era_name` 把序号 1–7 映射为「史前、原始、古典、封建、工业、现代、未来」；右栏自己英雄的属性行、右栏对手身份块的元信息与座位详情统一显示「时代 X」。

## 5. 棋盘拖拽与出售

- 棋盘随从卡不提供卡内按钮；拖拽是换位与出售的唯一入口。
- 拖拽门控：阶段为招募、视图未过期、倒计时未归零、未结束招募、`Net` 已连接、队首待选不是 `target`。任一不满足时不开始拖拽，卡片按失效态降低透明度。
- 棋盘内换位：拖起后原卡立即隐藏，原位置不留虚线占位；指针在棋盘内移动时，插入位由同尺寸透明占位承载，其余随从实时让位。松手按「移除被拖随从后剩余序列中的插入下标」发出 `RearrangeBoard{fromIndex,toIndex}`；落回原位不发意图。
- 拖到商店：可出售的随从拖入商店面板时，面板转为金色描边，标题行显示「松手出售 +N 金」（普通随从 1 金、金色随从 3 金）；松手发出 `SellMinion{minionId}`。不可出售的随从与手牌拖到商店都静默取消。
- 拖拽数据带视图版本 `epoch`；拖拽途中视图重建、换回合、开战、断线或进入目标待选时，松手不产生意图。
- 拖拽结束（含取消）恢复棋盘原顺序与原卡可见性；服务端视图到达后整块重建。

## 6. 卡面与详情

### 卡面

- 商店卡与棋盘卡共用同一卡面：部落色封面铺满卡片，底部信息区两行——名称居中；下一行攻击在左、类型在中间、生命在右。
- 商店卡在封面左上角显示购买费用 `CostBadge`，右上角显示时代 `EraBadge`；费用与时代取自 `CardDB` 的 `display_cost` 与 `era`，只用于展示。
- 商店卡显示 `CardDB` 卡表的**原始**攻击力与生命值，效果牌没有数值时显示「—」；类型显示部落，完整类型（随从/效果 + 部落）由详情面板给出。
- 棋盘卡与战斗只读卡显示服务端下发的**当前**攻击力与生命值；金色随从在封面上角显示「★」。
- 冻结的商店卡在整卡上覆盖 `FreezeOverlay`：`color-info` 蒙层透明度 0.22，叠一组间距 14、固定 45° 的冰晶细线，右下角保留「冻」字 `FreezeGlyph`；蒙层只压暗自身，不压暗冰晶与「冻」字。
- 商店卡整卡可点击购买；不可购买时整卡降透明度，原因在详情面板给出，不使用原生 tooltip。
- 没有图片资源时封面由部落色块与卡名首字水印组成；后续有图片资源时按 `cardId` 替换。

### 详情

- 触发：座位行、商店卡、招募棋盘与战斗双方的随从卡在鼠标悬停进入时显示详情；触摸操作在按下时显示、松开后按指针所在卡片矩形更新或隐藏。鼠标左键按下同样显示，松开后按指针位置更新或隐藏。
- 命中：以卡片或座位行的全局矩形判断指针是否仍在目标内，指针落在其中子控件上不会隐藏面板；移出矩形才隐藏。
- 定位：商店卡详情优先挂在卡片右侧，放不下换左侧；棋盘卡详情优先挂在下方，放不下换上方；座位详情按左栏位置挂在右侧或左侧。面板始终夹紧在视口内，且不与当前锚点矩形相交。
- 商店详情显示「名称 / 类型 / 费用 / 原始 / 时代 / 技能文本 / 不可购买原因」，技能文本按面板宽度换行。
- 座位详情显示「名字 / 英雄 / 生命（当前/上限）/ 时代 / 随从数 / 状态」；存活时追加「招募」行（已招募/未招募）。
- 随从详情显示顺序固定为「随从名称 / 初始 / 永久 / 回合 / 光环 / 受击 / 当前」，名称单独一行，其余每行同时给出攻击与生命两个数值。
- 有符号行（永久、回合、光环）正数带 `+`；初始与当前为原值。受击行展示层和与当前值的差值，按损失量显示（差值为正时显示 `-N`）。
- 受击在两个数值上都为 0 时省略该行；其余行始终显示。
- `stats` 缺失时只显示一行「当前」，取顶层 `attack` / `health`。
- 面板只读、不拦截鼠标；每次视图重建前隐藏面板，避免指向已销毁的卡片。

## 7. 适配与性能

- 逻辑尺寸固定 1280×720，窗口按 `canvas_items` 缩放；没有竖屏与超宽布局。
- 三栏中只有中区自适应，左栏与右栏固定宽；棋盘、商店、手牌使用 `HFlowContainer` 自动换行，手牌与座位列使用滚动容器。
- 战斗演示逐帧按 320ms 一步推进并重画两行；卡片按 `minionId` 原地更新，不整行重建。
- 碰撞演出在覆盖层 `CombatFxLayer` 上完成：攻方单程 130ms，命中时目标闪光 120ms 并飘出「-伤害」520ms；阵亡卡原位淡出 160ms，复生与召唤卡缩放缓入 160ms。覆盖层不参与布局、不拦截鼠标。
- 每次 `view_changed` 重建左栏与中区，节点上限为 8 个座位、按 `boardSlots` 的棋盘点位、6 个商店槽、10 张手牌；不使用图片与字体资源。
- 座位展开块按当前展开的 `playerId` 重建；同一时刻最多展开一行，战报条目随服务端最近 5 回合上限增长。
