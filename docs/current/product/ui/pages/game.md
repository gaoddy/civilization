# 对局页

> 状态：已实现
> 场景：`client/pages/game/game.tscn`
> 脚本：`client/pages/game/game.gd`
> 验证：`make client-smoke`

## 1. 目的、入口与返回

- 目的：在酒馆战棋式布局中呈现服务端 `PlayerView` 与 `CombatResult`，并把玩家操作转成协议意图。
- 入口：房间页在 `RoomUpdate` 阶段离开 `Lobby` 或收到 `GameStarted` 后导航进入；重连后收到视图也会进入。
- 返回：对局结束收到 `GameOver` 后进入结算页；顶部工具条「退出对局」发送 `LeaveRoom`，服务端在对局阶段按弃权结算，客户端清空房间并回大厅；认证类错误回登录；`NOT_IN_ROOM` / `ROOM_NOT_FOUND` 回大厅。
- 首局引导：对局页挂载非阻塞首局引导，默认隐藏；玩家点顶部工具条「提示」时打开，说明见[首局引导](../components/first-game-guide.md)。

## 2. 结构层级

```text
背景
└─ 外边距（左/右 16，上 12，下 8）
   └─ 纵向根容器（间距 8）
      ├─ TopBar（28）：状态文本（左）+ 图鉴/提示/退出对局（右）
      └─ 主体（横向，间距 12）
         ├─ PlayersRail（88）
         │  └─ 8 个方形座位可选框：头像铺满框内（名次角标收在头像内左上、圆形深底白字；血量条叠在底部内侧）；悬停描边，点击展开战报
         └─ CenterPanel（自适应，间距 8）
            ├─ RecruitPanel（招募可见，418）
            │  ├─ ShopView：操作行 64（升时代—售货员—刷新/冻结）+ 商店 6 槽 146
            │  ├─ RecruitRiver（32）：回合数居中，倒计时贴右端
            │  └─ BoardPanel（7 槽 146）
            ├─ CombatPanel（战斗可见，418）
            │  ├─ OpponentView（64）：对手圆角头像、名字、名次、HP 与血量条
            │  ├─ CombatOpponentRow（146）
            │  ├─ CombatRiver（32）：回合数与结果居中，「战斗中」贴右端
            │  └─ CombatOwnRow（146）
            ├─ HeroRow（84）：84×84 英雄卡（头像裁切铺满、右下角只显示当前生命）+ 金币与主动/被动技能列
            └─ HandStrip（146）：贴底手牌，10 张单行
瞄准层（全屏，忽略鼠标，默认隐藏）：技能与战吼的选目标弧线、候选角标与命中描边
选择浮层（全屏，默认隐藏）：发现候选卡面与进化选项块
详情层（全屏，忽略鼠标输入）：卡牌与座位详情面板（默认隐藏）
图鉴覆盖层（全屏，默认隐藏）：本局卡池的卡牌图鉴，首次点开时创建并复用
首局引导层（全屏，默认隐藏）：GuideOverlay 压暗层忽略鼠标 + 手牌上方宽度随内容自适应的 GuideBar 提示条
```

- 页面没有右栏：身份、回合、英雄与工具入口分别落在顶部工具条、河道、英雄行与商店操作行。
- 顶部工具条左侧 `StatusLabel` 承载等待、断线、未发出与错误文案，右侧三个入口只受连接状态影响。
- 左栏 `PlayersRail` 是 8 个方形座位可选框，边长取左栏内宽与「人均可用高度」的较小值，8 行按 `seat-row-gap` 排开后垂直居中，不滚动、也不拉伸行高；行就是头像的外框，2px 描边与 `radius-md` 圆角由可选框底板绘制，头像铺满框内（边长 = 行边长 − 4），悬停时描边转 `color-border-strong`。框内还叠有收在左上角的圆形名次角标与贴底的 6px 血量条，不显示名字、时代、随从数与血量数字。
- iPhone 基准下座位行使用紧凑令牌（血量条 4、行距 2），边长按可用高度等比缩小（960×540 下约 57），8 席在含底部安全区的可视高度内一屏放下；桌面与 iPad 受左栏内宽（88 减面板内边距）限制，边长固定为 64。
- 左栏固定宽 88，只够放下头像；点击展开的战报浮层覆盖在中央舞台之上，不挤压左栏与舞台宽度。
- 名次角标在 `rank` 为 `null` 时不显示；有角标时为叠在头像内左上角的圆形（深色半透明底、白色数字）；已淘汰行仍显示名次并整体压暗，仍可点击。
- 左栏按服务端下发的 `rank` 升序排列，第 1 名在最上；名次变化时整列随视图实时重排。`rank` 为 `null` 的座位排在最后，同位置按座位号。客户端只按名次排显示顺序，不自行推导名次。
- 点击座位行在行右侧展开这名玩家的战报浮层，浮层覆盖中央舞台但不改变左栏宽度；同一时刻只有一行展开，展开状态按 `playerId` 在视图刷新重建后保持。
- 招募阶段：商店操作行居中（升时代图标、64×64 圆角售货员头像、刷新与冻结图标），商店与棋盘各 6 / 7 槽居中，河道夹在两者之间；售货员只显示立绘、不显示名字条，图标 tooltip 与售货员悬停详情承担操作说明。
- 战斗阶段：顶部恢复对手身份块（圆角头像、名字、名次、HP 行与血量条），双方随从行夹住河道；幽灵战换成幽灵身份块并压暗、去掉血量条。
- 自己英雄行常驻：84×84 英雄卡是整块方形头像，有素材时按 cover 裁切铺满卡面并收进框的圆角（无头像素材时回退玩法色与名字首字），玩法色 2px 圆角描边叠在头像之上、四角不露方形头像；不显示名字与时代，只在右下角叠当前生命数字（深色半透明底、白字，不显示上限，位于描边之上不被裁切）；英雄名由 tooltip 与悬停详情承担。右侧窄列自上而下为全部被动技能标记与金币（同一行，24 高、按英雄卡 `skills` 顺序横排）、全部主动技能图标（40 高、按 `self.heroPowers` 顺序横排）。被动技能只读、不可点击、不置灰，悬停显示「被动技能：名称 + 效果」；主动技能只有不可用时置灰并给出原因。
- 战斗阶段隐藏主动技能图标，英雄卡、金币与被动技能标记保留；结算阶段尚未离开战斗视图时同样如此。
- 自己淘汰后英雄行改为「已淘汰 · 观战中」，不再显示英雄卡与技能。
- 两条河道：招募河道中央显示回合数，右端倒计时悬停翻成「结束招募」，点击发出 `EndRecruit`；战斗河道中央始终显示回合数，播完后追加胜负与伤害，右端固定「战斗中」。
- 两种组合固定占用 418 高，河道均位于组合顶部下方 234–266；组合下方间距 8 接英雄行（84），再间距 8 接手牌（146），手牌底边固定在页面底部上方 8。iPhone 基准下组合占 278、英雄行 74、手牌 92、舞台间距 4，手牌仍贴底。
- 手牌行贴底、无面板无标题：按 80 步进重叠，相邻卡交叠 32，1–10 张始终单行居中；手牌卡底边距页面底部桌面为 8、iPhone 为 4。舞台有富余高度时留白落在手牌上方，手牌不离开底部。
- 鼠标进入手牌卡时该卡置顶，以底边中点为轴放大到 1.12，整张卡完整可见；移出立即恢复。悬停期间右侧交叠带也归这张卡，不会切到下一张，从该处拖拽拾起的仍是这张卡。悬停不改变手牌顺序、下标与拖拽数据；拖拽一开始就结束悬停放大，拖拽预览保持原始尺寸。
- 不可出牌的手牌（禁用原因）与战斗阶段的手牌同样可以悬停完整查看，只是不能拖拽；原生 tooltip 保持，完整技能文本与禁用原因仍可读到。
- 手牌悬停不显示详情面板，不新增第二块浮层；放大后的卡片绘制在英雄行之上。
- 手牌拖拽取消或视图刷新后不保留悬停放大：指针不动时需要移出再移入一次才会重新放大。
- 招募视图与战斗视图互斥显示：战斗与结算阶段隐藏招募视图、商店操作、主动技能与结束招募，节点保留以便状态恢复；被动技能标记不受影响。
- 选择浮层：全屏压暗，提示下方横排候选；发现显示与手牌同尺寸的卡面（费用、时代、卡框、名称、基础身材与介绍，介绍沿用同尺寸手牌卡的压缩与省略规则），进化显示同尺寸选项块（+2/+2、护盾、复生）。点击任一卡面或选项块即发出 `ChooseDiscover { choice }`；浮层拦截点击，不穿透到棋盘、商店与手牌，打开时收起详情与图鉴。
- 详情层位于内容与战报之上、瞄准层与选择浮层之下，只在悬停或触摸座位行、棋盘与战斗随从、商店卡、售货员、双方英雄卡时显示；选目标瞄准中与选择浮层打开时自动隐藏，战报浮层打开时也不抢占画面。
- 首局引导挂在对局页最上层（`FirstGameGuide`，`layer = 100`）；四块压暗矩形与锚点容器忽略鼠标，只有手牌上方的提示条接收「下一步 / 跳过」点击，购买、拖拽、结束招募与倒计时照常工作。

## 3. 状态清单

| 状态 | 触发 | 表现 | 出口 |
| --- | --- | --- | --- |
| 加载中 | `GameStore.view` 为空 | 顶部工具条状态文本「等待对局状态…」 | 收到视图后自动恢复 |
| 空棋盘 | `self.board` 为空 | 棋盘不渲染占位槽，只留拖放空白区域 | 从手牌打出随从 |
| 空商店槽 | 槽位 `cardId` 为 `null` | 该槽位不渲染，商店只显示有卡槽位且整体居中 | 刷新商店 |
| 空手牌 | `self.hand` 为空 | 手牌区「手牌为空」 | 购买或发现获得 |
| 手牌悬停 | 指针进入手牌卡 | 该卡置顶并以底边中点为轴放大 1.12，整张卡可见；邻卡与手牌顺序不动；禁用与战斗阶段同样生效 | 指针移出或开始拖拽后复位 |
| 战吼目标待选 | `self.pendingChoices` 头部 `kind` 为 `target` | 入场随从留在棋盘，候选卡显示金色角标；不弹列表；购买/刷新/升时代/冻结/结束招募/主动技能/出售/换位/拖拽全部禁用 | 按住拖出箭头命中候选后发出 `ChooseTarget { target }`；落空或 `Esc` 发出 `AbandonTarget`，随从离场、牌回原手牌位置 |
| 技能瞄准 | 按住需要目标的英雄技能按钮且候选非空 | 弧线从技能按钮指向指针，候选显示金色角标，命中卡加呼吸描边；指针不在候选上时弧线转灰、端点画叉；不显示悬停详情 | 松手命中候选发出 `UseHeroPower { skillId, target }`；落空或 `Esc` 取消，不发意图、不扣金币与次数 |
| 发现 / 进化待选 | `self.pendingChoices` 队首为发现或进化待选 | 全屏压暗，提示下方横排候选项；发现为与手牌同尺寸的卡面，进化为同尺寸选项块；浮层拦截点击，详情与图鉴收起 | 点击任一卡面或选项块发出 `ChooseDiscover { choice }`；服务端消费待选后随视图关闭 |
| 战斗动作未到 | 战斗阶段 `last_combat` 为空 | 对手行「等待战斗动作…」，战斗河道只显示回合数 | 收到 `CombatResult` 后自动恢复 |
| 战斗开场 | 战斗阶段已有本回合 `CombatResult` 且首条动作尚未播放 | 战场压暗，中央独立底板上显示双方头像、名字、英雄名与「VS」「战斗开始」，约 1.2 秒后淡出；显示期间演示暂停，首条动作在淡出后开始 | 开场淡出后进入「战斗演示中」；重连续播已进入战斗中段时不显示 |
| 战斗演示中 | 战斗阶段已有 `CombatResult` 且动作未播完 | 双方随从按动作逐步更新，河道只显示回合数；两行与河道占位固定，一方随从全灭时该行只留空白；攻击方卡克隆后飞向目标、命中闪光与伤害飘字、再飞回原位，阵亡卡回位后才消失；河道右端显示「战斗中」、不显示招募倒计时；商店、刷新、升时代、冻结、主动技能、结束招募不可见，被动技能标记保留，手牌只读 | 动作播完并经过横幅停留 |
| 演示播完 | 动作播完且超过 `TAIL_MS` | 河道在回合数之后追加胜负或「平局」、对手名与伤害，上下两行与河道位置不变；页面发送一次 `CombatPlayed` | 全部参战座位回报后服务端推进到下一回合招募（兜底截止同样推进） |
| 幽灵战 | 战斗阶段 `mirror` 为真 | 顶部对手身份块换成幽灵身份块，带「幽灵」角标且无血量条；整块压暗；结果中的对手名追加「（幽灵）」 | 服务端推进到下一回合招募 |
| 自身已淘汰 | 战斗阶段自己不在存活座位 | 英雄行显示「已淘汰 · 观战中」，隐藏英雄卡与技能；刷新、升时代、冻结、技能与结束招募均不可用；对手展示不受影响 | 服务端推进阶段 |
| 战报为空 | 展开的座位上没有 `combatLog` 条目 | 展开块显示「无战报」 | 收到该座位参与的战报 |
| 座位已淘汰 | `alive` 为假 | 座位行整体压暗，名次角标仍显示，仍可点击展开战报 | 对局结束 |
| 错误 | `Error` 消息 | 顶部工具条状态文本为中文文案，tooltip 为协议原文；停留 4 秒后自动清空，阶段或回合变化时提前清空 | 按错误码留页、回大厅或回登录 |
| 无权限 | 页面没有按角色区分的操作；越权请求由服务端拒绝 | 按错误状态展示，不本地隐藏操作 | 按错误码处理 |
| 离线 | `Net` 未连接 | 顶部工具条状态文本「未连接 · 正在重连」；操作提示「未连接，操作未发出」 | 3 秒自动重连，收到 `Snapshot` 恢复 |
| 视图过期 | `view.turn` 与 `GameStore.turn` 不一致 | 全部操作禁用 | 收到新回合视图 |
| 倒计时归零 | `phaseDeadline` 已过 | 招募河道倒计时显示「等待结算」，全部招募操作禁用 | 服务端推进阶段 |
| 已结束招募 | `self.recruited` 为真 | 只读；招募河道倒计时悬停显示「已结束招募」，冻结禁用 | 服务端推进阶段 |
| 图鉴覆盖层打开 | 点击顶部工具条「图鉴」 | 全屏图鉴盖住页面，只显示本局卡池；对局数据照常刷新，拖拽、待选与演示状态保留 | 点「返回对局」或 `Esc` 收起；对局选择浮层可见时随刷新自动收起 |
| 首局引导 | 点击顶部工具条「提示」 | 手牌上方的提示条与目标高亮显示；不拦截输入，不改变对局状态 | 点「下一步」推进，「跳过」或「完成」收起 |
| 引导阶段切换 | 引导已打开且对局阶段变化 | 切换到当前阶段对应的步骤；终局收起 | 点「跳过」/「完成」收起 |
| 主动退出 | 点击顶部工具条「退出对局」 | 发送 `LeaveRoom`；服务端按弃权结算，退出者立即离开并停止接收该局消息 | 清空房间并回大厅 |
| 达到上限 | 商店 6 槽、棋盘按 `boardSlots` 计 | 只渲染有卡槽位，不显示空位占位；棋盘行保留整行拖放区 | 服务端判定手牌与棋盘上限，拒绝原因进 tooltip |

- 同一时刻只呈现一种主状态；错误文本不覆盖正在显示的发现/进化弹层，弹层由独立的视图门槛控制。
- 招募阶段不渲染对手身份块；战斗阶段 `OpponentView` 的判定顺序为「`opponentPlayerId` 为空 → 等待配对；`mirror` 为真且当前回合战报有效 → 幽灵；其余 → 普通对手」。本人淘汰只落在英雄行，不再拦截对手展示。
- 幽灵战除 `mirror` 为真外，还要求当前回合战报有效（`combat_is_current()`）且 `opponentPlayerId` 非空。

## 4. 数据来源

| 数据 | 来源 |
| --- | --- |
| 回合、阶段、阶段截止时间 | `view.turn`、`view.phase`、`view.phaseDeadline`；`GameStore.phase`、`GameStore.deadline` 作为空视图或旧视图时的兜底 |
| 生命、生命上限、时代、金币、英雄、技能次数 | `view.self` 与 `view.hpCap` |
| 被动技能标记 | `CardDB.hero(heroCardId).skills` 中 `CardDB.skill(id).cost` 为空的技能；主动技能只取 `view.self.heroPowers` |
| 商店、手牌、棋盘、可用性 | `view.self.shop/hand/board/affordances`，按钮可用性只取 `buyable`、`playable`、`sellable`、`can*` |
| 座位行与对手信息 | `view.players`（座位号、名字、生命、时代、存活、随从数、英雄、准备、名次 `rank`、托管） |
| 座位血量条 | `players[].hp` 与 `view.hpCap` 的比例；`hpCap` 缺失按 40 |
| 座位战报 | `view.combatLog`：按 `participantIds` 过滤出该玩家参与的全部条目 |
| 战斗双方与结果 | `CombatResult`：`ownBoard`、`opponentBoard`、`actions`、`damage`、`winnerId`、`mirror`；当前对手为 `view.opponentPlayerId` |
| 战斗动作 | `CombatResult.actions` 的 `kind`（`attack`/`death`/`reborn`/`contagion`/`summon`）、`sourceMinionId`/`targetMinionId`、动作后的 `source`/`target` 随从状态（`minionId`/`attack`/`health`/`alive`）与 `summon`（`side`/`position`/`minion`） |
| 手牌目标与候选 | `self.hand[].requiresTarget` 与 `self.hand[].targetCandidates`；队首待选类型与候选取 `self.pendingChoices[]` 的 `kind` / `candidates`；英雄技能逐个取 `self.heroPowers[].requiresTarget` / `targetCandidates` |
| 随从详情构成 | 棋盘随从的 `stats`（`attack` / `health` 各含 `initial`、`permanent`、`turn`、`aura`、`damage`、`current`）；缺失时退化为顶层 `attack` / `health` |
| 随从获得的效果 | 当前生效的 `keywords` 减去卡面 `skills` 的 `keyword` 派生值；名称取 `enum.keyword.<id>`，规则说明取 `ui.game.detail.keyword.<id>`，层数词把层数代入 `%d` |
| 卡面与商店详情 | `CardDB` 卡表：`card_type`、`categories`、`taxon`、`attack`、`health`、`era`、`display_cost`、`skills`；分类路径走 `CardDB.taxon_path`，玩法/分类名走 `CardDB.playstyle_name` / `CardDB.taxon_name` |
| 图鉴卡池 | `CardPool.card_ids(view.enabledFactions)`：与服务端 `card_in_pool` 同规则复算本局卡池，排除非池卡 |
| 首局引导 | 步骤表与当前对局阶段；不读写本地记录 |

- 页面不做本地规则推导：不计算伤害、不推断可用性、不推导名次；左栏只按服务端 `rank` 排显示顺序。战斗演示按 `actions` 逐条应用服务端下发的数值，不做任何加减。
- 图鉴覆盖层不参与对局操作：本局卡池用 `CardPool` 按 `enabledFactions` 复算，只用于列出可出现的卡牌，出牌与商店合法性仍以服务端视图为准。
- `CombatResult` 只发给该场参战者本人：观战者（含幽灵归属者）在战斗阶段不收到它，只能从战报里看到这场对战的结果与幽灵归属者名字；阵容演示只发给参战者。
- 战斗演示期间还没有本场 `combatLog`：战报在结算时才下发，演示中展开座位只看到既往回合条目。
- 座位战报文案为「第 N 回合 · 对手名 · 胜/负/平 · 伤害 X」；平局无胜者时输出「平」；幽灵战的对手写「幽灵（名字）」，`ghostId` 为空时只写「幽灵」；`damage` 为 0 时省略伤害段；没有条目时显示「无战报」。
- 详情面板直接展示 `stats` 的分层数值，不自行重算层和与当前值。
- 商店卡的攻击力与生命值只读卡表的原始值，不参与任何判定。
- 重排（拖拽换位）与冻结没有对应的槽位 affordance，按阶段、`recruited` 与下标本地门控，与服务端拒绝条件一致；冻结按钮按 `affordances.canUnfreeze` 选择冻结或解冻意图，tooltip 同步显示「冻结」或「解冻」。`canUnfreeze` 只在本回合冻结过且仍有冻结槽位时为其，跨回合保留的冻结仍显示「冻结」。冻结按钮的激活态同样取 `canUnfreeze`，商店卡本身的冻结蒙层按各槽位 `frozen` 绘制。
- 时代文案与玩法文案都由 `CardDB` 取文本表：`era_name` 把序号 1–7 映射为「史前、原始、古典、封建、工业、现代、未来」，`playstyle_name` 取 `enum.playstyle.<id>`；战斗对手身份块与座位详情统一显示时代文案，英雄卡不再显示时代。
- 房间页的候选英雄卡显示英雄卡面，选中时加金色描边；无卡面素材时回退玩法色封面、名字首字水印与贴底名字。

## 5. 拖拽操作

- 三种卡（手牌、棋盘随从、商店）的拖拽预览都保持指针按下时在卡上的位置：卡片跟着指针移动，预览不从左上角起算。
- 拖拽期间不显示任何卡的悬停详情：起手时已打开的面板立即收起，购买经过棋盘、出售经过商店卡都不弹出介绍；松手或取消后指针移入卡片才恢复。
- 商店卡拖到手牌区购买：可购买的商店卡可拖起，拖起后原卡隐藏、原位留同尺寸空白（与棋盘卡一致），松手或取消后恢复；拖入贴底手牌带时整条卡带转为金色描边，松手发出 `BuyMinion{slot}`；落在已有手牌卡上同样有效。点击商店卡不发意图，只保留详情。
- 不可购买的商店卡整卡降透明度且不能起手拖拽；拖到棋盘、手牌带以外或不可购买槽位静默取消。手牌已满时不做本地判断，由服务端拒绝并在状态栏给出原因。
- 棋盘随从卡不提供卡内按钮；拖拽是换位与出售的唯一入口。
- 手牌随从拖入棋盘：指针在棋盘内移动时，棋盘在插入下标处放同尺寸透明占位，其余随从实时让位；落在某张随从卡上即插到该卡之前。棋盘已满、指针在棋盘外或效果牌拖拽时不显示占位，落点规则不变。
- 拖拽门控：阶段为招募、视图未过期、倒计时未归零、未结束招募、`Net` 已连接、队首待选不是 `target`。任一不满足时不开始拖拽，卡片按失效态降低透明度。
- 棋盘内换位：拖起后原卡立即隐藏，原位置不留虚线占位；指针在棋盘内移动时，插入位由同尺寸透明占位承载，其余随从实时让位。松手按「移除被拖随从后剩余序列中的插入下标」发出 `RearrangeBoard{fromIndex,toIndex}`；落回原位不发意图。
- 拖到商店：可出售的随从拖入商店面板时，面板转为金色描边，右上角浮出「松手出售 +N 金」（普通随从 1 金、金色随从 3 金）；松手发出 `SellMinion{minionId}`。不可出售的随从与手牌拖到商店都静默取消。
- 需要目标的效果牌拖动时，瞄准层按棋盘、手牌与商店卡上的目标元数据画同一套弧线、候选角标与命中描边；落点仍由落点控件判定，落点提交路径不变。
- 拖拽数据带视图版本 `epoch`；拖拽途中视图重建、换回合、开战、断线或进入目标待选时，松手不产生意图。
- 拖拽结束（含取消）恢复棋盘原顺序与原卡可见性；服务端视图到达后整块重建。

## 6. 卡面与详情

### 卡面

- 商店卡、棋盘卡、手牌卡与战斗只读卡共用同一套卡面语言，按场景由独立组件实现；桌面 112×146、iPhone 70×91（保持同一卡形，只缩尺寸不改比例）：玩法色封面铺满卡片（卡面容器只留 1px 描边），底部信息区为名称居中，下一行攻击在左、玩法在中间、生命在右。
- 商店卡与棋盘卡不显示介绍，信息区固定为紧凑高度（桌面 56），悬停或长按详情面板仍给出完整技能文本；手牌卡保留介绍且不截断：信息区按文本向上扩展，字号在 11–8 之间逐档缩小、行距收紧，直到整段介绍完整放下，角标始终绘制在信息区之上（桌面信息区最高到角标下方，约 125）。iPhone 紧凑卡受 70×91 限制，只容纳 1 行 8px 介绍并省略；移动端暂不在手牌卡面展开完整文本。
- 商店卡在封面左上角显示购买费用 `CostBadge`，右上角显示时代象形 `EraGlyph`；费用与时代取自 `CardDB` 的 `display_cost` 与 `era`，只用于展示。
- 商店卡显示 `CardDB` 卡表的**原始**攻击力与生命值，效果牌没有数值时显示「—」；类型位显示全部玩法名（多项用「、」分隔），完整类型（随从/效果）、科学分类与关联分类由详情面板给出。
- 棋盘卡与战斗只读卡显示服务端下发的**当前**攻击力与生命值；金色随从在封面上角显示「★」。
- 手牌随从同样显示服务端下发的**当前**攻击力与生命值（含成长等全部加成），金色随从在封面角标显示「★」；「三连奖励」牌在角标行显示锁定的发放星级，悬停提示「获得一张 N 星随从」。
- 冻结的商店卡在整卡上覆盖 `FreezeOverlay`：`color-info` 蒙层透明度 0.22，叠一组间距 14、固定 45° 的冰晶细线，右下角保留「冻」字 `FreezeGlyph`；蒙层只压暗自身，不压暗冰晶与「冻」字；解冻后随视图重建移除蒙层与「冻」字。
- 商店卡拖到手牌带购买；不可购买时整卡降透明度且无法拖拽，原因在详情面板给出，不使用原生 tooltip。
- 没有图片资源时封面由玩法色块与卡名首字水印组成；后续有图片资源时按 `cardId` 替换。

### 详情

- 触发：座位行、商店卡、招募棋盘与战斗双方的随从卡在鼠标悬停进入时显示详情；触摸操作在按下时显示、松开后按指针所在卡片矩形更新或隐藏。鼠标左键按下同样显示，松开后按指针位置更新或隐藏。
- 拖拽期间一律不显示悬停详情：起手时已打开的面板立即收起，拖拽经过的卡片（购买经过棋盘、出售经过商店卡等）都不弹出；松手或取消后指针移入卡片才重新显示。
- 命中：以卡片或座位行的全局矩形判断指针是否仍在目标内，指针落在其中子控件上不会隐藏面板；移出矩形才隐藏。
- 定位：商店卡详情优先挂在卡片右侧，放不下换左侧；棋盘卡详情优先挂在下方，放不下换上方；座位详情按左栏位置挂在右侧或左侧。面板始终夹紧在视口内，且不与当前锚点矩形相交。
- 商店详情显示「名称 / 类型 / 科学分类 / 玩法 / 关联分类 / 费用 / 原始 / 时代 / 技能文本 / 不可购买原因」，技能文本按面板宽度换行；关联分类只显示 `prey:` / `host:`，为空时省略该行。
- 座位详情显示「名字 / 英雄 / 生命（当前/上限）/ 时代 / 随从数 / 状态」；存活时追加「招募」行（已招募/未招募）。
- 随从详情显示顺序固定为「随从名称 / 科学分类 / 玩法 / 关联分类 / 技能介绍 / 获得 / 初始 / 永久 / 回合 / 光环 / 受击 / 当前」，名称与介绍单独成行，其余数值行同时给出攻击与生命两个数值。
- 「获得」行只列对局中获得、卡面技能文本未覆盖的关键词，按固定关键词顺序用「、」连接并按层数显示（如「嘲讽、减伤 2」）；随后逐条给出「关键词：规则说明」，说明按面板宽度换行。没有获得项或卡表缺少该卡时整组省略。
- 科学分类显示为从界到科的完整路径（如「动物界 › 脊索动物门 › 哺乳纲 › 食肉目 › 猫科」），路径缺失显示「未定」；玩法缺失同样显示「未定」。
- 关联分类行把捕食与寄生分别聚合，格式为「捕食：偶蹄目；寄生：人科」，两类都为空时不显示该行。
- 英雄详情显示顺序为「英雄卡面美术 / 英雄名称 / 英雄介绍 / 玩法 / 关联分类 / 英雄技能」，卡面美术无素材时省略；英雄卡不含科学分类、时代、费用与原始数值，关联分类为空时不显示该行。对手英雄与幽灵归属者的英雄详情走同一口径，技能文本取 `CardDB.hero_text`。
- 有符号行（永久、回合、光环）正数带 `+`；初始与当前为原值。受击行展示层和与当前值的差值，按损失量显示（差值为正时显示 `-N`）。
- 受击在两个数值上都为 0 时省略该行；其余行始终显示。
- `stats` 缺失时仍显示名称与技能介绍，并追加一行「当前」，取顶层 `attack` / `health`。
- 面板只读、不拦截鼠标；每次视图重建前隐藏面板，避免指向已销毁的卡片。

## 7. 适配与性能

- 页面内容固定 16:9 居中等比缩放（contain）：桌面与 iPad 以 1280×720、iPhone 以 960×540 为设计基准，窗口比例变化只在内容框外露出背景；没有竖屏布局。
- 只有中央舞台自适应，左栏固定宽；商店、棋盘、手牌与战斗行都用居中容器承载固定宽度子行。桌面在 1148 的舞台可用宽下，棋盘 7 槽与手牌十张各需 832；iPhone 在紧凑卡宽 84 下，棋盘 7 槽需 636、手牌十张需 624。手牌与棋盘的最小宽度按整行显式给出，避免流式容器按单卡计算导致换行。
- 战斗开场在 `CombatIntro` 覆盖层上完成：总时长 1200ms，前 160ms 缩放 0.94→1 并淡入，末尾 160ms 淡出并微放大；显示期间不推进动作与碰撞演出。双方身份放在一块独立底板上，避免与河道回合数、随从卡重叠。覆盖层铺满战斗组合、不参与布局、不拦截鼠标；点击不可跳过。
- 战斗演示逐帧按 320ms 一步推进并重画两行；卡片按 `minionId` 原地更新，不整行重建。
- 碰撞演出在覆盖层 `CombatFxLayer` 上完成：攻方单程 130ms，命中时目标闪光 120ms 并飘出「-伤害」520ms；阵亡卡原位淡出 160ms，复生与召唤卡缩放缓入 160ms。覆盖层铺满战斗组合、不参与布局、不拦截鼠标。
- 每次 `view_changed` 重建左栏与中央舞台，节点上限为 8 个座位、按 `boardSlots` 的棋盘点位、6 个商店槽、10 张手牌；不使用图片与字体资源。
- 座位展开块按当前展开的 `playerId` 重建；同一时刻最多展开一行，战报条目随服务端最近 5 回合上限增长。
- 图鉴覆盖层首次打开时创建并一直复用，关闭只切可见性；网格按批加载、节点随滚动增长，不随对局视图刷新重建。
- 首局引导层只在 `_process` 中重算高亮矩形，最多 4 块压暗矩形与 1 条提示条，不参与舞台布局；提示条停靠在手牌上方。
- 瞄准层全屏但不参与布局；瞄准或拖拽需要目标期间逐帧重判指针命中并重绘弧线，关闭后停止绘制。

## 8. 音效反馈

- 音效只跟随服务端确认的状态与事件播放，不按按钮按下或视图差异提前推断；操作被拒绝时没有音效。
- 刷新：手动刷新、首次免费刷新、效果刷新与升时代重抽各播一次刷新音效。回合开始同一批事件里的自动重抽只播商店入场音效，不叠刷新音效；同一封 `StateUpdate` 只响一次。
- 商店入场：每回合开始播一次；首回合 `GameStarted` 不带事件，页面首次进入对局时补播一次。
- 冻结/解冻：以商店槽位 `frozen` 标记变化为准，冻结与解冻各一条独立音效；槽位新建、移除、重抽与进入新回合都不算冻结或解冻。
- 购入：所有卡牌买到手牌都播购入音效，随从牌与效果牌一致；被服务端拒绝的购买不响。
- 战斗：每次攻击播攻方卡牌的攻击音效，每个随从阵亡播死亡音效，双方随从都覆盖；重连续播不补播已经过去的动作。
- 战斗开始/结束：本场战斗首次装载且首条动作尚未播放时播一次开始音效，与开战画面同时出现；结果横幅首次出现时播一次结束音效，胜负与平局一致。重连续播已进入战斗中段不补播开始音效；重连时结果横幅已存在则补播一次结束音效，后续刷新不重复。
- 卡牌挂钩：卡牌音效按卡牌 id 查找逐卡资源，当前全部回落到默认公共音效；后续逐卡放入资源后，该卡自动使用自己的音效，其余卡不变。
- 资源缺失时静默，不报错、不阻塞对局；同一帧多个攻击/死亡由多路播放，不互相截断。
