# 卡牌图鉴页

> 状态：已实现
> 场景：`client/pages/gallery/gallery.tscn`
> 脚本：`client/pages/gallery/gallery.gd`；主体组件 `client/ui/card_gallery.gd`（`CardGallery`）
> 验证：`make client-smoke` 的 `gallery` 与 `layout` 场景（`client/tests/ui_smoke_gallery.tscn`、`ui_smoke_layout.tscn`）

## 1. 目的、入口与返回

- 目的：只读浏览全部卡牌（含衍生物与生成卡等非池卡）的完整信息，在随从视图按时代、玩法与类型筛选，在英雄视图按英雄玩法筛选；不读取房间、对局或手牌状态。
- 入口：
  - 大厅「卡牌图鉴」按钮，导航到 `pages/gallery/gallery.tscn`，随从视图为全部卡牌（当前 432 张，其中 24 张非池卡），英雄视图为 32 张英雄卡。
  - 对局右上角工具组里的「图鉴」按钮，以全屏覆盖层 `GalleryOverlay` 叠在对局页上，不切换场景，随从视图只含本局卡池（按 `view.enabledFactions` 复算，排除非池卡；默认夹具为 177 张），英雄视图只含本局玩法可用的英雄。
- 返回：大厅页点「返回大厅」或按 `Esc` 回大厅；对局覆盖层点「返回对局」或按 `Esc` 只收起覆盖层，对局状态与拖拽、待选、战斗演示全部保留。

## 2. 结构层级

```text
软件背景 PageBackground（bg_main，整窗 cover）
└─ 页面容器 PageBody → PageSurface（语义面板，设计画布尺寸）
   └─ 外边距（space-2xl）
      └─ 纵向根容器（间距 space-md）
         ├─ 头部（横向一行，间距 space-sm，高 32 固定）
         │  ├─ 视图分段 GalleryModeBar：ModeMinion（随从）/ ModeHero（英雄）
         │  ├─ GalleryEraSelect：时代 · <当前值> ▾
         │  ├─ GalleryPlaySelect：玩法 · <当前值> ▾
         │  ├─ GalleryKindSelect：类型 · <当前值> ▾
         │  ├─ 弹性空隙
         │  ├─ GalleryCount：<N> 张
         │  └─ 返回按钮：返回大厅 / 返回对局
         ├─ 卡面网格 GalleryGrid（列数按可用宽度计算，纵向滚动分批追加）
      ├─ 筛选面板层 GalleryFilterPanel（锚点定位，默认隐藏）
      └─ 详情浮层 GalleryDetailLayer（默认隐藏）：头部以下的遮罩 + 右侧详情抽屉
```

- 头部只占一行，不显示「卡片图鉴 / 本局卡片图鉴」标题与副标题；视图分段、筛选下拉、计数与返回同处一行。
- 筛选为三个下拉触发器，文字格式为「维度 · 当前值 ▾」，例如「时代 · 全部 ▾」；选中非「全部」的条目时文字转为金色。
- 英雄视图隐藏「时代」与「类型」下拉，只保留「玩法」；切回随从视图时恢复，并保留各自的筛选条件。
- 网格直接占满头部以下的宽度与高度，不再有左侧分类目录与常驻详情；详情只在点击卡面后以浮层抽屉打开。
- 筛选面板挂在触发按钮下沿，宽 240，覆盖网格但不压暗页面；详情抽屉打开时遮罩从头部下沿开始压暗，头部仍可操作。

## 3. 状态清单

| 状态 | 触发 | 表现 | 出口 |
| --- | --- | --- | --- |
| 初始 | 进入页面且卡池非空 | 预选筛选结果首张并保留选中描边，详情浮层保持关闭 | 点击卡面 |
| 筛选面板打开 | 点「时代」「玩法」或「类型」 | 面板贴在按钮下沿，列出条目与计数；零计数项禁用；当前项高亮 | 选条目、点面板外、再点同一按钮、`Esc` |
| 筛选生效 | 在面板中选条目 | 网格重建并回到首批、顶部；计数更新；选中卡被筛掉时改为结果首张；详情浮层关闭 | 改选其它条目 |
| 玩法联动类型 | 改「玩法」为任一值或「全部」 | 「类型」回到「全部」 | — |
| 视图切换 | 点「随从 / 英雄」分段 | 时代与类型下拉隐藏或恢复，玩法改为英雄玩法或普通玩法；网格与计数随视图更新并回到首批；详情关闭 | 再点另一分段 |
| 英雄集合为空 | 本局没有可用英雄 | 英雄分段禁用并保持随从，随从视图正常 | — |
| 点击卡面 | 点任一卡面 | 卡面显示选中描边，右侧抽屉打开并显示该卡详情；网格保持当前滚动位置与已加载批次 | 点遮罩、点关闭按钮、`Esc` |
| 空结果 | 页面卡池为空，或筛选结果为空 | 计数显示「0 张」，网格区显示「没有符合条件的卡牌」；详情浮层关闭且没有可打开的卡 | 放宽筛选或返回 |
| 零计数筛选项 | 某项在当前另外两维筛选下计数为 0 | 该项禁用（置灰、不可点），当前选中的项不禁用 | 改回其它筛选 |
| 加载更多 | 滚动接近网格底部 | 追加下一批卡面，保持当前滚动位置与选中；底部显示「已显示 N / M 张 · 继续下滑加载」 | 继续下滑 |
| 全部加载完 | 已加载张数等于结果张数 | 底部显示「已显示 M / M 张 · 已全部加载」 | — |
| 英雄玩法筛选 | 英雄视图打开「玩法」面板并选择 | 网格只列该玩法的英雄；没有英雄的玩法显示但禁用 | 改选其它玩法 |
| 详情有卡图 / 无卡图 | 选中卡有 / 无对应美术（所有卡取 `card_face`） | 显示美术大图 / 玩法色底 + 首字占位 | 选中其它卡 |
| 大厅模式 | 大厅入口 | 返回「返回大厅」、随从视图 432 张、英雄视图 32 张 | 返回大厅 |
| 对局覆盖层 | 对局右上角工具组「图鉴」 | 返回「返回对局」、随从视图仅本局卡池、英雄视图仅本局可用英雄 | 返回对局或 `Esc` |
| 加载中 | 不需要：`CardDB` 在启动时已加载 | — | — |

- 随从视图三个维度的计数都按另外两维换算，任一筛选下的计数都等于点下去实际能看到的张数；英雄视图的玩法计数按本局英雄池换算。
- 切换视图保留各视图的筛选条件；每次切换都回到首批并滚到顶部。
- `Esc` 逐层关闭：先收筛选面板，再收详情浮层，最后才发出 `closed`（返回大厅或收起覆盖层）。
- 对局覆盖层打开期间，对局视图照常刷新但不重建图鉴；对局的选择浮层可见时，图鉴随下一次刷新自动收起，避免两层叠加。

## 4. 数据来源

| 数据 | 来源 |
| --- | --- |
| 卡牌展示表 | `CardDB.cards`（`generated/cards.json`，含非池卡与 `in_shop_pool`） |
| 英雄展示表 | `CardDB.heroes`（`generated/heroes.json`），与 `cards` 分开，只含身份与技能 |
| 卡名 | `CardDB.display_name`：`card.<id>.name` |
| 类型 | `card_type` 经 `UIWording.enum_text("card_type")`；英雄视图固定显示「英雄」 |
| 科学分类 | `CardDB.taxon_path(taxon)` 的完整路径，以「 · 」连接；缺失显示「未定」 |
| 玩法 | `CardDB.playstyles` 的 13 个玩法按固定顺序展示，不含「中立」；效果牌与英雄不作为顶层玩法 |
| 英雄玩法 | `CardDB.playstyles` 的 13 个玩法按同一顺序展示；英雄按全部 `play:` 归属归入对应玩法，带多条归属的英雄在多个玩法中同时出现，不按单一玩法去重 |
| 玩法分类归属 | 随从视图的卡牌按全部 `play:` 归属归入对应玩法；带多条归属的卡在多个玩法中同时出现；「全部」按唯一卡牌 id 去重计数 |
| 类型筛选 | 「效果」取 `card_type = effect`，「随从」取其余条目；非池卡同样按自身 `card_type` 归类 |
| 玩法与关联分类 | 玩法取 `CardText.playstyle_text`，拼接全部 `play:` 的展示名；关联分类取 `CardText.association_text`，只聚合 `prey:` / `host:` |
| 时代 | `era` 经 `UIWording.enum_text("era")`；未识别的时代排在最后，且不算入任何时代 |
| 费用与原始数值 | `display_cost`、`attack`、`health`；数值缺失显示「—」 |
| 技能 | `skills[]` 经 `CardDB.skill_name` 取 `skill.<id>.name`，缺键返回空串并跳过（不显示内部 id） |
| 效果文本 | `CardDB.display_text`：`skills[]` 的 `skill.<id>.text` 按顺序换行拼接，缺键跳过 |
| 本局卡池 | `CardPool.card_ids(view.enabledFactions)`：与服务端 `card_in_pool` 同规则，`in_shop_pool: true` 且任一条 `play:` 命中启用玩法即入池；非池卡不入池 |
| 本局英雄池 | `CardPool.hero_ids(view.enabledFactions)`：与服务端 `hero_in_pool` 同规则，英雄任一条 `play:` 命中启用玩法即入选；过滤后为空时回退到全部英雄 |

- 图鉴只做展示，不参与规则判定；费用、攻防均取卡表原始值，不代表对局中的当前数值。
- 排序：普通卡先按时代序号（1–7，未知排最后），再按本地化名称升序；英雄视图按本地化名称升序；同一筛选下顺序稳定。

## 5. 详情

- 详情浮层由遮罩与右侧抽屉组成：抽屉宽桌面与 iPad 440、手机 400，顶部从头部下沿开始、底部贴到页面底边，右边缘桌面留 24、手机留 16，圆角 `radius-lg`；桌面与手机同为贴右整高抽屉。遮罩从头部下沿开始，底色 `color-bg`、透明度 `scrim-alpha-gallery`（0.62）。
- 抽屉打开时 0.12 秒淡入；不提供右上角关闭按钮，点遮罩或按 `Esc` 关闭；抽屉内点击不关闭。关闭后网格保留选中描边与滚动位置。
- 详情内容可纵向滚动，内边距桌面 `space-xl`（16）、手机 `space-md`（8）。
- 普通卡首行是左侧封面 + 右侧信息列：封面 160×209（手机 112×146，按卡面 112:146 等比，无图时玩法色 + 首字占位）；右列自上而下为名称、元信息一行、玩法、关联分类（有才显示）、科学分类。
- 元信息一行用「·」串联「类型 · 时代 · 费用 · 攻 x / 血 y」；时代为空、攻防为空时省略对应项，四项全部写成文字，不用图标或角标。
- 卡片下方是分隔线 +「效果」标题，每个效果单独一行；没有效果文本时整块省略。
- 英雄首行同为封面 + 右侧名称、介绍（有才显示）、玩法、关联分类；下方为分隔线与技能列表，技能块自带名称与触发标签，不再另加标题。不显示类型「英雄」、科学分类、时代、费用与攻防，也不再单独显示「技能」名称行。
- 预览区只显示美术大图（160×209，手机 112×146，按卡面 112:146 等比）：普通卡与英雄都取 `card_face`；封面复用公共卡框 `CardFrame`（普通卡按卡表 `level` 画星级，英雄不计星级），不再拼装卡面组件与角标。
- 玩法行展示全部 `play:` 归属，按固定玩法顺序用「、」连接；关联分类只聚合 `prey:` / `host:`，格式为「捕食：…；寄生：…」，两类都为空时省略该行。
- 英雄技能列表按 `skills` 顺序逐条展示：技能名（没有名称时省略）、触发类型标签、完整技能文本；主动技能追加「费用 N · 每回合 N 次」。无技能时显示空态。该列表与对局页选英雄覆盖层的悬停详情共用 `SkillList.build`。
- 费用显示为「N 金」；攻防显示为「攻 x / 血 y」，效果牌没有数值时省略攻防项。
- 详情内容超出抽屉高度时纵向滚动，不做水平滚动。

## 6. 适配与性能

- 页面内容固定 16:9 居中，桌面与 iPad 以 1280×720、iPhone 以 960×540 为设计基准，窗口比例变化只在内容框外露出软件背景；页面容器背景随内容框缩放。图鉴没有竖屏布局。
- 网格列数按可用宽度计算：桌面与 iPad 基准 9 列、手机基准 7 列，列距桌面 `space-lg`（12）、手机 `space-md`（8）；卡宽按列数平分整行宽度并等比放大，卡高保持 112:146，右侧不留空。
- 网格按批加载：桌面每批 27 张，手机每批 12 张；首批不足一屏时自动继续加载。滚动到底部附近追加下一批，只保留已加载批次，不重建已可见卡面。
- 头部一行容纳视图分段、三个下拉、计数与返回；控件宽度由文字决定，手机基准下整体不越界。
- 筛选面板宽 240，挂在下拉按钮下沿，超出页面时由外壳夹紧；面板只接收自身点击，点外部关闭。
- 桌面与 iPad 的详情抽屉宽 440、手机 400，顶部对齐头部下沿、底部贴到页面底边，纵向占满头部以下区域；遮罩始终从头部下沿开始，打开详情后头部仍可切换视图、改筛选或返回。
- 对局覆盖层首次打开时创建，之后只切可见性并复用节点；每次打开都会重置视图、筛选与选中。
