# 卡牌图鉴页

> 状态：已实现
> 场景：`client/scenes/gallery.tscn`
> 脚本：`client/scenes/gallery.gd`；主体组件 `client/scenes/card_gallery.gd`（`CardGallery`）
> 验证：`make client-smoke`（`client/tests/ui_smoke_gallery.tscn`）

## 1. 目的、入口与返回

- 目的：只读浏览全部卡牌（含衍生物与生成卡等非池卡）的完整信息，在随从视图按时代与玩法筛选，在英雄视图按英雄玩法筛选；不读取房间、对局或手牌状态。
- 入口：
  - 大厅「卡牌图鉴」按钮，导航到 `scenes/gallery.tscn`，随从视图为全部卡牌（当前 432 张，其中 24 张非池卡），英雄视图为 32 张英雄卡。
  - 对局顶部工具条右侧的「图鉴」按钮，以全屏覆盖层 `GalleryOverlay` 叠在对局页上，不切换场景，随从视图只含本局卡池（按 `view.enabledFactions` 复算，排除非池卡；默认夹具为 177 张），英雄视图只含本局玩法可用的英雄。
- 返回：大厅页点「返回大厅」或按 `Esc` 回大厅；对局覆盖层点「返回对局」或按 `Esc` 只收起覆盖层，对局状态与拖拽、待选、战斗演示全部保留。

## 2. 结构层级

```text
背景（color-bg，铺满）
└─ 外边距（space-2xl）
   └─ 纵向根容器
      ├─ 头部（横向，一行）
      │  ├─ 标题（font-display）：卡牌图鉴 / 本局卡牌图鉴
      │  ├─ 视图切换（标题右侧，单按钮显示当前视图，点击切换）
      │  ├─ 顶部筛选栏（HFlowContainer，居中）
      │  │  ├─ 随从视图：时代章节「全部」+ 7 个时代
      │  │  └─ 英雄视图：英雄分类「全部」+ 13 个玩法
      │  └─ 返回按钮：返回大厅 / 返回对局
      └─ 主体（横向，space-lg）
         ├─ 分类目录（仅随从视图，140）：「全部」+ 13 个玩法，单选，无标题；
         │  选中项下方展开「全部 / 随从 / 效果」二级单选
         ├─ 卡面网格（自适应）
         │  ├─ 网格：6 列，每页 18 张（6×3），无滚动条
         │  ├─ 空态：「没有符合条件的卡牌」
         │  └─ 分页条：上一页 / 第 N/M 页 / 下一页
         └─ 常驻详情（280）：选中卡的大卡面与属性行
```

- 头部只占一行：标题、视图切换、当前视图的顶部筛选栏与返回按钮；筛选栏在剩余宽度内居中，名称在上、计数在下；不显示副标题与总计数。
- 视图切换位于标题右侧，同一时刻只显示当前视图的一个按钮，按钮文字为「随从」或「英雄」；默认随从视图，英雄集合为空时按钮禁用。
- 随从视图保留左侧分类目录；英雄视图隐藏左侧目录，主体只保留网格与常驻详情。
- 详情常驻，不弹层、不翻页：选中卡变化时只重建右栏内容，网格保持当前页。
- 网格只构建当前页的卡面节点，翻页与筛选都会回到第 1 页；每页张数按可见行数确定，不出现滚动。
- 卡面由 `GalleryCardFace.build` 构建（112×146），封面、费用与时代角标的取数与对局一致；英雄视图改由 `GalleryCardFace.build_hero` 构建「英雄」角标与玩法，不含费用、时代与攻击/生命。

## 3. 状态清单

| 状态 | 触发 | 表现 | 出口 |
| --- | --- | --- | --- |
| 初始选中 | 进入页面且目录非空 | 选中筛选后的第一张卡，详情立即有内容 | 点击其它卡 |
| 视图切换 | 点击标题右侧的当前视图按钮 | 按钮文字切换为另一视图，顶部筛选栏、左侧目录与网格随视图切换；回到第 1 页并选中结果首张 | 再次点击切换 |
| 英雄集合为空 | 本局没有可用英雄 | 切换按钮禁用并保持「随从」，随从视图正常 | — |
| 已选卡被筛掉 | 改时代、分类或英雄分类后当前选中卡不在结果里 | 自动改为结果中的第一张 | — |
| 空目录 | 页面传入的卡牌集合为空，或筛选结果为空 | 网格区显示「没有符合条件的卡牌」，详情显示「选择一张卡牌查看详情」，分页条隐藏 | 放宽筛选或返回 |
| 零计数筛选项 | 某项在当前另一维筛选下计数为 0 | 该项禁用（置灰、不可点），当前选中的项不禁用 | 改回其它筛选 |
| 分页首页 / 末页 | 第 1 页 / 最后一页 | 上一页或下一页按钮禁用 | 翻页 |
| 顶层分类 | 随从视图点击「全部」或任一分类 | 目录该项下展开「全部 / 随从 / 效果」二级项；切换顶层分类时二级回到「全部」 | 改选二级项 |
| 英雄分类 | 英雄视图点击「全部」或任一玩法 | 网格只列该玩法的英雄；没有英雄的分类显示但禁用 | 改选其它分类 |
| 二级筛选 | 随从视图点击随从或效果 | 与时代、顶层分类叠加筛选，计数按另外两维换算 | 改回「全部」 |
| 详情有卡图 / 无卡图 | 选中卡有 / 无 `card_face` 美术 | 显示卡面美术大图 / 玩法色底 + 首字占位 | 选中其它卡 |
| 大厅模式 | 大厅入口 | 标题「卡牌图鉴」、返回「返回大厅」、随从视图 432 项、英雄视图 32 张 | 返回大厅 |
| 对局覆盖层 | 对局顶部工具条「图鉴」 | 标题「本局卡牌图鉴」、返回「返回对局」、随从视图仅本局卡池、英雄视图仅本局可用英雄 | 返回对局或 `Esc` |
| 加载中 | 不需要：`CardDB` 在启动时已加载 | — | — |

- 随从视图的时代章节计数按当前分类筛选换算，目录计数按当前时代筛选换算；英雄分类计数按当前英雄池换算。任一筛选下的计数都等于点下去实际能看到的张数。
- 切换视图保留各视图的筛选条件；从英雄视图切回随从视图时，时代、分类与二级筛选回到切换前的选择。
- 对局覆盖层打开期间，对局视图照常刷新但不重建图鉴；对局的选择浮层可见时，图鉴随下一次刷新自动收起，避免两层叠加。

## 4. 数据来源

| 数据 | 来源 |
| --- | --- |
| 卡牌展示表 | `CardDB.cards`（`generated/cards.json`，含非池卡与 `in_shop_pool`） |
| 英雄展示表 | `CardDB.heroes`（`generated/heroes.json`），与 `cards` 分开，只含身份与技能 |
| 卡名 | `CardDB.display_name`：`card.<id>.name` |
| 类型 | `card_type` 经 `UI.enum_text("card_type")`；英雄视图固定显示「英雄」 |
| 科学分类 | `CardDB.taxon_path(taxon)` 的完整路径，以「 · 」连接；缺失显示「未定」 |
| 分类目录 | `CardDB.playstyles` 的 13 个玩法按固定顺序展示，不含「中立」；效果牌与英雄不作为顶层分类 |
| 英雄分类 | `CardDB.playstyles` 的 13 个玩法按同一顺序展示；英雄按全部 `play:` 归属归入对应玩法，带多条归属的英雄在多个分类中同时出现，不按单一玩法去重 |
| 玩法分类归属 | 随从视图的卡牌按全部 `play:` 归属归入对应玩法；带多条归属的卡在多个分类中同时出现；「全部」按唯一卡牌 id 去重计数 |
| 随从 / 效果二级筛选 | 「效果」取 `card_type = effect`，「随从」取其余条目；非池卡同样按自身 `card_type` 归类 |
| 玩法与关联分类 | 玩法取 `CardText.playstyle_text`，拼接全部 `play:` 的展示名；关联分类取 `CardText.association_text`，只聚合 `prey:` / `host:` |
| 时代 | `era` 经 `UI.enum_text("era")`；未识别的时代排在最后，且不算入任何时代章节 |
| 费用与原始数值 | `display_cost`、`attack`、`health`；数值缺失显示「—」 |
| 技能 | `skills[]` 经 `CardDB.skill_name` 取 `skill.<id>.name`，缺键返回空串并跳过（不显示内部 id） |
| 效果文本 | `CardDB.display_text`：`skills[]` 的 `skill.<id>.text` 按顺序换行拼接，缺键跳过 |
| 本局卡池 | `CardPool.card_ids(view.enabledFactions)`：与服务端 `card_in_pool` 同规则，`in_shop_pool: true` 且任一条 `play:` 命中启用玩法即入池；非池卡不入池 |
| 本局英雄池 | `CardPool.hero_ids(view.enabledFactions)`：与服务端 `hero_in_pool` 同规则，英雄任一条 `play:` 命中启用玩法即入选；过滤后为空时回退到全部英雄 |

- 图鉴只做展示，不参与规则判定；费用、攻防均取卡表原始值，不代表对局中的当前数值。
- 排序：普通卡先按时代序号（1–7，未知排最后），再按本地化名称升序；英雄视图按本地化名称升序；同一筛选下顺序稳定。

## 5. 详情

- 普通卡顺序固定：卡面美术图（无图时玩法色 + 首字占位）→ 名称 → 类型 → 科学分类 → 玩法 → 关联分类（有才显示）→ 时代（有才显示）→ 费用 → 原始（攻击 / 生命，任一非空才显示）→ 技能（有可读技能名才显示）→ 效果（有文本才显示）。
- 英雄顺序固定：卡面美术图 → 名称 → 类型「英雄」→ 玩法 → 关联分类（有才显示）→ 技能列表；不显示科学分类、时代、费用与原始数值，也不再单独显示「技能」名称行。
- 预览区只显示 `card_face` 美术大图（200×260，手机 160×208），不再拼装卡面组件与角标。
- 玩法行展示全部 `play:` 归属，按固定玩法顺序用「、」连接；关联分类只聚合 `prey:` / `host:`，格式为「捕食：…；寄生：…」，两类都为空时省略该行。
- 英雄技能列表按 `skills` 顺序逐条展示：技能名（没有名称时省略）、触发类型标签、完整技能文本；主动技能追加「费用 N · 每回合 N 次」。无技能时显示空态。该列表与选英雄页的技能浮层共用 `UI.skill_list`。
- 费用显示为「N 金」；原始数值显示为「攻击 / 生命」，效果牌没有数值时显示「— / —」。
- 详情区可纵向滚动；内容超出 280 宽时由文本换行，不做水平滚动。

## 6. 适配与性能

- 逻辑尺寸固定 1280×720，窗口按 `canvas_items` 缩放；图鉴没有竖屏与超宽布局。
- 随从视图目录固定 140、详情固定 280；英雄视图隐藏目录，网格只让出详情宽度。桌面网格 6 列，每页 18 张（6×3）；手机 4 列，每页 8 张（4×2）。翻页时整页重建，最多同时存在 18 个卡面节点。
- 头部筛选栏使用 `HFlowContainer` 与 `ButtonGroup`；英雄分类含「全部」与 13 个玩法，窄屏时整栏换行，零计数项禁用而非隐藏。
- 对局覆盖层首次打开时创建，之后只切可见性并复用节点；每次打开都会重置视图、筛选与选中。
